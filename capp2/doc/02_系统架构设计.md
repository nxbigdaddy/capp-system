## 1. 设计原则

### 1.1 高内聚低耦合

- **模块化设计**：每个功能模块职责单一，模块内部高内聚，模块之间低耦合
- **分层架构**：Controller层负责请求路由和参数校验，Service层负责业务逻辑，Model层负责数据访问，各层职责清晰
- **依赖注入**：Service通过构造函数注入依赖，避免硬编码依赖关系，便于单元测试和模块替换
- **事件驱动**：模块间通过事件机制通信（如工艺变更事件触发BOM更新、消息通知），降低直接依赖

### 1.2 可扩展性

- **水平扩展**：PHP应用无状态设计，支持多实例水平扩展，通过Nginx负载均衡分发请求
- **缓存策略**：热点数据通过Redis缓存，减轻数据库压力，缓存失效策略可配置
- **消息队列**：异步任务（消息推送、数据同步、文件处理等）通过RabbitMQ解耦，消费者可独立扩展
- **插件化集成**：外部系统集成采用适配器模式，新增系统对接只需新增适配器，不影响核心业务
- **AI服务独立部署**：AI服务作为独立微服务部署，可独立扩缩容和升级

### 1.3 安全性

- **最小权限原则**：每个用户角色仅授予完成其工作所需的最小权限
- **纵深防御**：从网络层、应用层、数据层多维度实施安全防护
- **安全编码**：参数化查询防SQL注入，输入过滤防XSS，Token验证防CSRF
- **审计追溯**：关键操作全量记录日志，支持安全审计
- **数据加密**：敏感数据加密存储，传输层全站HTTPS

### 1.4 易维护性

- **统一编码规范**：遵循PSR-12 PHP编码规范，代码风格统一
- **完善注释**：类、方法、关键逻辑添加注释，复杂业务逻辑附加说明文档
- **自动化测试**：核心业务逻辑编写单元测试，关键流程编写集成测试
- **日志规范**：统一日志格式和日志级别，支持日志检索和分析
- **配置外部化**：数据库连接、缓存配置、第三方API密钥等配置信息与代码分离

## 4. 应用架构分层

### 4.1 表现层（前端Vue应用）

表现层采用Vue.js 3.x + Element Plus构建的单页应用（SPA），部署为纯静态资源，由Nginx直接托管。

**核心职责**：

- 用户界面渲染和交互
- 前端路由管理（基于Vue Router）
- 前端状态管理（基于Pinia）
- API请求封装和统一错误处理
- 权限控制（前端路由守卫、按钮级权限指令）
- 数据校验（表单校验、业务规则校验）

### 4.2 接入层（Nginx反向代理）

接入层使用Nginx作为反向代理服务器，负责请求分发、负载均衡、静态资源服务和SSL终端。

**Nginx核心配置职责**：

| 功能 | 说明 |
|------|------|
| 反向代理 | 将API请求转发至PHP-FPM |
| 静态资源托管 | 直接托管前端Vue应用的构建产物 |
| 负载均衡 | 多PHP-FPM实例的负载均衡（round-robin/ip-hash） |
| SSL终端 | HTTPS证书管理，SSL卸载 |
| Gzip压缩 | 响应内容压缩，减少传输量 |
| 访问控制 | IP白名单、请求频率限制 |
| 缓存 | 静态资源缓存、API响应缓存 |

**Nginx配置示例**：

```nginx
server {
    listen 443 ssl;
    server_name capp.company.com;

    ssl_certificate     /etc/nginx/ssl/capp.crt;
    ssl_certificate_key /etc/nginx/ssl/capp.key;

    # 前端静态资源
    location / {
        root /var/www/capp/frontend/dist;
        try_files $uri $uri/ /index.html;
        expires 7d;
        add_header Cache-Control "public, immutable";
    }

    # API反向代理
    location /api/ {
        proxy_pass http://php_fpm_backend;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # 文件上传下载
    location /files/ {
        proxy_pass http://php_fpm_backend;
        client_max_body_size 100M;
    }

    # WebSocket
    location /ws/ {
        proxy_pass http://php_fpm_backend;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }
}

upstream php_fpm_backend {
    server 127.0.0.1:9000;
    # 支持多实例扩展
    # server 127.0.0.1:9001;
}
```

#### 4.3.3 控制器基类（app/controllers/BaseController.php）

```php
<?php
namespace App\Controllers;

use Core\Request;
use Core\Response;

abstract class BaseController
{
    protected Request $request;
    protected Response $response;

    public function __construct(Request $request, Response $response)
    {
        $this->request = $request;
        $this->response = $response;
    }

    // JSON成功响应
    protected function success($data = null, string $message = 'success', int $code = 200)
    {
        return $this->response->json([
            'code' => $code,
            'message' => $message,
            'data' => $data
        ]);
    }

    // JSON错误响应
    protected function error(string $message, int $code = 400, $data = null)
    {
        return $this->response->json([
            'code' => $code,
            'message' => $message,
            'data' => $data
        ], $code);
    }

    // 分页响应
    protected function paginate(array $items, int $total, int $page, int $pageSize)
    {
        return $this->success([
            'list' => $items,
            'pagination' => [
                'total' => $total,
                'page' => $page,
                'page_size' => $pageSize,
                'total_pages' => ceil($total / $pageSize)
            ]
        ]);
    }

    // 获取当前登录用户
    protected function getCurrentUser(): array
    {
        return $this->request->getAttribute('user');
    }
}
```

```php
{
    protected Database $db;
    protected string $table = '';
    protected string $primaryKey = 'id';

    public function __construct()
    {
        $this->db = Database::getInstance();
    }

    // 根据ID查询
    public function findById(int $id): ?array
    {
        $sql = "SELECT * FROM {$this->table} WHERE {$this->primaryKey} = :id AND is_deleted = 0";
        $stmt = $this->db->prepare($sql);
        $stmt->execute(['id' => $id]);
        return $stmt->fetch(PDO::FETCH_ASSOC) ?: null;
    }

    // 条件查询
    public function findBy(array $conditions, array $orderBy = [], int $limit = 0, int $offset = 0): array
    {
        $sql = "SELECT * FROM {$this->table} WHERE is_deleted = 0";
        $params = [];
        foreach ($conditions as $field => $value) {
            $sql .= " AND {$field} = :{$field}";
            $params[$field] = $value;
        }
        if (!empty($orderBy)) {
            $sql .= " ORDER BY " . implode(', ', $orderBy);
        }
        if ($limit > 0) {
            $sql .= " LIMIT {$limit}";
            if ($offset > 0) {
                $sql .= " OFFSET {$offset}";
            }
        }
        $stmt = $this->db->prepare($sql);
        $stmt->execute($params);
        return $stmt->fetchAll(PDO::FETCH_ASSOC);
    }

    // 新增
    public function insert(array $data): int
    {
        $data['created_at'] = date('Y-m-d H:i:s');
        $data['updated_at'] = date('Y-m-d H:i:s');
        $data['is_deleted'] = 0;
        $fields = implode(', ', array_keys($data));
        $placeholders = implode(', ', array_map(fn($f) => ":{$f}", array_keys($data)));
        $sql = "INSERT INTO {$this->table} ({$fields}) VALUES ({$placeholders})";
        $this->db->prepare($sql)->execute($data);
        return (int) $this->db->lastInsertId();
    }

    // 更新
    public function update(int $id, array $data): bool
    {
        $data['updated_at'] = date('Y-m-d H:i:s');
        unset($data[$this->primaryKey]);
        $sets = implode(', ', array_map(fn($f) => "{$f} = :{$f}", array_keys($data)));
        $sql = "UPDATE {$this->table} SET {$sets} WHERE {$this->primaryKey} = :id";
        $data['id'] = $id;
        return $this->db->prepare($sql)->execute($data) > 0;
    }

    // 软删除
    public function softDelete(int $id): bool
    {
        $sql = "UPDATE {$this->table} SET is_deleted = 1, deleted_at = NOW() WHERE {$this->primaryKey} = :id";
        return $this->db->prepare($sql)->execute(['id' => $id]) > 0;
    }

    // 开启事务
    public function beginTransaction(): void
    {
        $this->db->beginTransaction();
    }

    // 提交事务
    public function commit(): void
    {
        $this->db->commit();
    }

    // 回滚事务
    public function rollback(): void
    {
        $this->db->rollback();
    }
}
```

### 4.5 数据层（MySQL、Redis、ES、MinIO）

#### 4.5.1 MySQL数据库

MySQL作为主数据存储，承载所有业务数据。

**数据库设计要点**：

- 所有表使用InnoDB引擎，支持事务
- 统一使用UTF8MB4字符集
- 所有表包含`id`（主键）、`created_at`、`updated_at`、`is_deleted`（软删除）字段
- 关键表使用合理的索引策略
- BOM等树形数据使用`parent_id` + `path`（物化路径）双重模式
- 工艺参数等半结构化数据使用JSON字段存储

**核心数据表规划**（详见数据库设计文档）：

| 表分类 | 核心表 | 说明 |

```php
<?php
// routes/api.php - API路由定义

use App\Middleware\AuthMiddleware;
use App\Middleware\PermissionMiddleware;
use App\Middleware\LogMiddleware;
use App\Middleware\RateLimitMiddleware;

// 路由分组 - 所有API接口统一前缀
$router->group(['prefix' => '/api/v1'], function ($group) {

    // ==================== 认证相关 ====================

    // ==================== 工艺路线管理 ====================

        $g->get('/process-routes/{id}', 'ProcessRouteController@show');       // 工艺路线详情
        $g->put('/process-routes/{id}', 'ProcessRouteController@update');     // 更新工艺路线

    });

    // ==================== 工艺卡片管理 ====================

        $g->get('/bom/compare', 'BOMController@compare');              // BOM对比
    });

    // ==================== 资源管理 ====================
    // ==================== 质量管理 ====================
    // ==================== 审批流程 ====================
    // ==================== 变更管理 ====================
    // ==================== 文档管理 ====================
    // ==================== 标准工艺库 ====================
```

## 6. 模块划分

### 6.1 工艺管理模块

**模块职责**：工艺路线和工艺卡片的全生命周期管理。

**核心类**：

| 类名 | 类型 | 职责 |
|------|------|------|
| `ProcessRouteController` | Controller | 处理工艺路线相关的HTTP请求 |
| `ProcessRouteService` | Service | 工艺路线业务逻辑（创建、编排、版本管理、复制、审批提交等） |
| `ProcessRouteModel` | Model | 工艺路线数据访问 |
| `ProcessOperationModel` | Model | 工序数据访问 |
| `ProcessStepModel` | Model | 工步数据访问 |
| `ProcessCardService` | Service | 工艺卡片业务逻辑（生成、预览、导出PDF等） |
| `ProcessCardModel` | Model | 工艺卡片数据访问 |

**关键业务流程**：

```
创建工艺路线 → 编排工序 → 定义工序属性 → 关联质量控制点 →
关联工装夹具 → 编制工艺卡片 → 提交审批 → 审批通过 → 发布
```

### 6.2 BOM管理模块

**模块职责**：EBOM接收、PBOM编辑、MBOM创建和发布。

**核心类**：

| 类名 | 类型 | 职责 |
|------|------|------|
| `BOMController` | Controller | 处理BOM相关的HTTP请求 |
| `BOMService` | Service | BOM业务逻辑（EBOM/PBOM/MBOM转换、BOM对比、版本管理等） |
| `BOMModel` | Model | BOM主表数据访问 |
| `BOMNodeModel` | Model | BOM节点数据访问（树形结构） |

**关键业务流程**：

```
PLM同步EBOM → 查看EBOM结构 → 创建PBOM（调整结构） →
创建MBOM（按工序分配物料） → MBOM审批 → 发布 → 同步至U8/MES
```

### 6.3 资源管理模块

**模块职责**：设备、工装夹具、工作中心、材料定额、工时定额的管理。

**核心类**：

| 类名 | 类型 | 职责 |
|------|------|------|
| `ResourceController` | Controller | 资源管理HTTP请求处理 |
| `ResourceService` | Service | 设备、工装、工作中心业务逻辑 |
| `MaterialQuotaService` | Service | 材料定额编制和汇总 |
| `ManhourQuotaService` | Service | 工时定额编制和汇总 |

### 6.4 质量管理模块

**模块职责**：质量控制点定义、质量数据管理、质量追溯。

**核心类**：

| 类名 | 类型 | 职责 |
|------|------|------|
| `QualityController` | Controller | 质量管理HTTP请求处理 |
| `QualityService` | Service | 质量控制点定义、质量数据分析、追溯逻辑 |
| `QualityControlPointModel` | Model | 质量控制点数据访问 |
| `InspectionDataModel` | Model | 检测数据数据访问 |

### 6.5 审批流程模块

**模块职责**：审批流程定义、审批实例管理、审批任务处理。

**核心类**：

| 类名 | 类型 | 职责 |
|------|------|------|
| `ApprovalController` | Controller | 审批相关HTTP请求处理 |
| `ApprovalService` | Service | 审批流程引擎（流程定义解析、实例创建、任务流转、消息通知） |
| `ApprovalDefinitionModel` | Model | 流程定义数据访问 |
| `ApprovalInstanceModel` | Model | 流程实例数据访问 |
| `ApprovalTaskModel` | Model | 审批任务数据访问 |

**审批流程引擎设计**：

```
流程定义（JSON配置）
├── 节点类型
│   ├── start_node      # 开始节点
│   ├── approval_node   # 审批节点（单人/会签/或签）
│   ├── condition_node  # 条件分支节点
│   ├── notify_node    # 通知节点
│   └── end_node       # 结束节点
├── 连线规则
│   ├── 默认连线
│   └── 条件连线（表达式判断）
└── 操作类型
    ├── agree           # 同意
    ├── reject          # 驳回（退回上一步/退回发起人）
    ├── transfer        # 转审
    └── add_sign        # 加签（前加签/后加签）
```

### 6.6 企业微信模块

**模块职责**：企业微信扫码登录、用户同步、消息推送。

**核心类**：

| 类名 | 类型 | 职责 |
|------|------|------|
| `WeChatController` | Controller | 企业微信相关HTTP请求处理 |
| `WeChatService` | Service | OAuth2.0认证流程、通讯录同步、消息推送封装 |
| `WeChatAdapter` | Integration | 企业微信API调用封装 |

**扫码登录流程**：

```
前端生成二维码 → 用户企业微信扫码 → 企业微信回调code →
后端用code换取用户信息 → 创建/更新本地用户 → 生成JWT Token →
返回前端 → 前端存储Token → 后续请求携带Token
```

### 6.7 AI模块

**模块职责**：AI服务客户端封装，为前端提供统一的AI能力接口。

**核心类**：

| 类名 | 类型 | 职责 |
|------|------|------|
| `AIController` | Controller | AI相关HTTP请求处理 |
| `AIServiceClient` | Service | AI微服务HTTP客户端，封装参数推荐、方案优选、智能问答等接口调用 |
| `SearchService` | Service | Elasticsearch搜索服务封装 |

**AI服务调用流程**：

```
前端请求 → AIController → AIServiceClient → HTTP请求 → AI微服务(Flask) →
模型推理 → 返回结果 → AIServiceClient → AIController → 前端展示
```

### 6.8 集成对接模块

**模块职责**：统一管理所有外部系统的数据集成。

**核心类**：

| 类名 | 类型 | 职责 |
|------|------|------|
| `IntegrationController` | Controller | 集成管理HTTP请求处理 |
| `IntegrationManager` | Service | 集成管理器，协调各适配器 |
| `PLMAdapter` | Integration | CAXA PLM API调用封装 |
| `U8Adapter` | Integration | 用友U8 API调用封装 |
| `MESAdapter` | Integration | MES API调用封装 |
| `SyncLogModel` | Model | 同步日志数据访问 |

**数据同步策略**：

| 同步类型 | 触发方式 | 处理方式 | 失败处理 |
|---------|---------|---------|---------|
| 实时推送 | 业务事件触发（如MBOM发布） | 同步调用 + MQ异步确认 | 失败重试3次，记录日志，告警通知 |
| 定时拉取 | Cron定时任务 | MQ异步处理 | 失败重试，记录日志 |
| Webhook回调 | 外部系统事件通知 | MQ异步处理 | 失败重试，记录日志 |
| 手动触发 | 管理员操作 | MQ异步处理 | 失败重试，记录日志 |

|------|------|------|
| 数据库 | `capp_{业务域}` | `capp_process`, `capp_system` |
| 表名 | 小写下划线，名词 | `process_route`, `bom_node` |
| 字段名 | 小写下划线 | `route_name`, `created_at` |
| 主键 | `id`（自增整数） | `id BIGINT UNSIGNED AUTO_INCREMENT` |
| 外键 | `{关联表单数}_id` | `route_id`, `material_id` |
| 索引 | `idx_{表名}_{字段名}` | `idx_process_route_product_id` |
| 唯一索引 | `uk_{表名}_{字段名}` | `uk_bom_node_code` |

### 9.2 通用字段

所有业务表必须包含以下通用字段：

```sql
`id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键ID',
`created_by` VARCHAR(64) DEFAULT NULL COMMENT '创建人',
`created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
`updated_by` VARCHAR(64) DEFAULT NULL COMMENT '最后修改人',
`updated_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '修改时间',
`is_deleted` TINYINT(1) NOT NULL DEFAULT 0 COMMENT '是否删除 0-否 1-是',
`deleted_at` DATETIME DEFAULT NULL COMMENT '删除时间',
`remark` VARCHAR(500) DEFAULT NULL COMMENT '备注',
PRIMARY KEY (`id`)
```

### 9.3 数据类型规范

| 数据类型 | 使用场景 | 说明 |
|---------|---------|------|
| `BIGINT UNSIGNED` | 主键、外键 | 自增主键 |
| `VARCHAR(n)` | 短文本 | 编号、名称等，n根据实际长度设定 |
| `TEXT` | 长文本 | 描述、备注等 |
| `JSON` | 半结构化数据 | 工艺参数、扩展属性等 |
| `DECIMAL(10,2)` | 金额、定额 | 精确数值 |
| `DECIMAL(18,6)` | 尺寸、精度 | 高精度数值 |
| `TINYINT` | 状态、标志 | 0/1状态值 |
| `SMALLINT` | 枚举类型 | 状态码、类型码 |
| `DATETIME` | 时间 | 创建时间、修改时间 |
| `DATE` | 日期 | 计划日期、生效日期 |

### 10.1 RESTful API规范

| 方法 | 路径 | 说明 |
|------|------|------|
| `GET` | `/api/v1/resources` | 获取资源列表 |

| `GET` | `/api/v1/resources/{id}` | 获取资源详情 |
| `PUT` | `/api/v1/resources/{id}` | 更新资源（全量） |
| `PATCH` | `/api/v1/resources/{id}` | 更新资源（部分） |
| `DELETE` | `/api/v1/resources/{id}` | 删除资源（软删除） |

### 10.2 统一响应格式

**成功响应**：

```json
{
    "code": 200,
    "message": "success",
    "data": {
        // 业务数据
    },
    "timestamp": 1717737600
}
```

**分页响应**：

```json
{
    "code": 200,
    "message": "success",
    "data": {
        "list": [],
        "pagination": {
            "total": 100,
            "page": 1,
            "page_size": 20,
            "total_pages": 5
        }
    },
    "timestamp": 1717737600
}
```

**错误响应**：

```json
{
    "code": 400,
    "message": "参数验证失败",
    "errors": [
        {
            "field": "route_name",
            "message": "工艺路线名称不能为空"
        }
    ],
    "timestamp": 1717737600
}
```

### 10.3 接口认证

所有业务接口（除登录接口外）需在请求头中携带JWT Token：

```
Authorization: Bearer {token}
```

Token有效期：8小时，支持刷新Token机制。

### 11.2 关键安全措施

| 安全领域 | 措施 | 实施方式 |
|---------|------|---------|
| 身份认证 | JWT Token + 企业微信OAuth2.0 | 登录成功签发JWT，Token存储于Redis |
| 密码安全 | bcrypt哈希 + 盐值 | 密码存储使用password_hash() |
| SQL注入防护 | PDO预处理语句 | 所有SQL使用参数绑定 |
| XSS防护 | 输入过滤 + 输出转义 | htmlspecialchars + CSP头 |
| CSRF防护 | Token验证 | 每次表单提交验证CSRF Token |
| 文件上传安全 | 类型白名单 + 大小限制 + 病毒扫描 | 后端校验文件MIME和扩展名 |
| 接口限流 | Redis滑动窗口 | 单IP单接口60次/分钟 |
| 敏感数据保护 | 字段加密存储 | AES-256加密身份证号、密码等 |
| 会话安全 | Token过期 + 单点登录 | Redis管理Token生命周期 |
| 日志脱敏 | 敏感信息过滤 | 日志中隐藏密码、Token等 |
