## 1. 接口设计规范

### 1.1 RESTful API设计原则

本系统遵循RESTful架构风格设计API接口，核心原则如下：

| 原则 | 说明 |
|------|------|
| 资源导向 | URL表示资源，使用名词而非动词 |
| HTTP方法语义化 | GET（查询）、POST（创建）、PUT（更新）、DELETE（删除） |
| 无状态通信 | 每个请求独立，服务端不保存客户端状态 |
| 统一接口 | 统一的请求/响应格式和错误处理方式 |
| 可缓存性 | 适当使用HTTP缓存机制 |

### 1.2 请求/响应格式

所有接口统一使用JSON格式进行数据交换，请求和响应的Content-Type均为`application/json`。

**请求头规范：**

```
Content-Type: application/json
Authorization: Bearer {jwt_token}
X-Request-Id: {uuid}           // 请求唯一标识，用于链路追踪
X-Client-Version: 1.0.0        // 客户端版本
```

### 1.3 统一响应结构

```json
{
  "code": 200,
  "message": "success",
  "data": {},
  "request_id": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
  "timestamp": 1717737600
}
```

**字段说明：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| code | int | 是 | 业务状态码，200表示成功 |
| message | string | 是 | 状态描述信息 |
| data | any | 否 | 响应数据，失败时可能为null |
| request_id | string | 是 | 请求唯一标识 |
| timestamp | int | 是 | 响应时间戳（Unix时间戳） |

**成功响应示例：**

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "id": 1001,
    "name": "工业压缩机缸体加工工艺路线",
    "code": "PR-2026-001"
  },
  "request_id": "req-20240607-001",
  "timestamp": 1717737600
}
```

**失败响应示例：**

```json
{
  "code": 4001,
  "message": "工艺路线编码已存在",
  "data": null,
  "request_id": "req-20240607-002",
  "timestamp": 1717737600
}
```

### 1.4 认证方式（Token-based JWT）

系统采用JWT（JSON Web Token）进行身份认证。

**Token结构：**

```
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
```

**JWT Payload定义：**

```json
{
  "iss": "capp-system",           // 签发者
  "sub": "1001",                  // 用户ID
  "name": "张三",
  "dept_id": 10,
  "roles": ["工艺工程师", "审批人"],
  "iat": 1717737600,              // 签发时间
  "exp": 1717824000,              // 过期时间（默认8小时）
  "jti": "token-uuid"             // Token唯一标识
}
```

**Token管理策略：**

| 策略 | 说明 |
|------|------|
| Access Token有效期 | 8小时 |
| Refresh Token有效期 | 7天 |
| Token刷新机制 | 过期前30分钟可刷新 |
| Token黑名单 | 退出登录时加入Redis黑名单 |
| 并发登录控制 | 同一账号最多3个同时在线 |

### 1.5 接口版本管理

API版本通过URL路径标识：

```
/api/v1/...          // 第一版API
/api/v2/...          // 第二版API（未来扩展）
```

版本升级原则：
- 向后兼容的变更：保持当前版本
- 破坏性变更：发布新版本，旧版本保留至少6个月

### 1.6 分页规范

列表查询接口统一支持分页，请求和响应格式如下：

**请求参数：**

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| page | int | 否 | 1 | 当前页码 |
| page_size | int | 否 | 20 | 每页条数，最大100 |
| sort_field | string | 否 | id | 排序字段 |
| sort_order | string | 否 | desc | 排序方向：asc/desc |

**响应结构：**

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "list": [...],
    "pagination": {
      "page": 1,
      "page_size": 20,
      "total": 156,
      "total_pages": 8,
      "has_next": true,
      "has_prev": false
    }
  }
}
```

### 1.7 错误码定义

**HTTP状态码与业务码映射：**

| HTTP状态码 | 业务码范围 | 含义 |
|-----------|-----------|------|
| 200 | 200 | 请求成功 |
| 400 | 4000-4999 | 客户端错误（参数错误、业务规则校验失败） |
| 401 | 4010-4019 | 未认证或认证失效 |
| 403 | 4030-4039 | 无权限访问 |
| 404 | 4040-4049 | 资源不存在 |
| 409 | 4090-4099 | 资源冲突 |
| 422 | 4220-4229 | 请求实体无法处理 |
| 429 | 4290-4299 | 请求过于频繁 |
| 500 | 5000-5999 | 服务端内部错误 |

**详细错误码列表：**

| 错误码 | 错误信息 | 说明 |
|--------|---------|------|
| 200 | success | 成功 |
| 4000 | 请求参数错误 | 通用参数校验失败 |
| 4001 | 字段校验失败 | 具体字段错误在data中返回 |
| 4002 | 数据已存在 | 唯一性约束冲突 |
| 4003 | 数据不存在 | 引用的关联数据不存在 |
| 4004 | 状态不允许操作 | 当前状态下无法执行该操作 |
| 4010 | Token缺失 | 请求头中未包含Authorization |
| 4011 | Token无效 | Token格式错误或已篡改 |
| 4012 | Token已过期 | 需要重新登录或刷新Token |
| 4013 | Token已注销 | 用户已退出登录 |
| 4030 | 无权限访问 | 当前用户无此操作权限 |
| 4031 | 数据权限不足 | 无权访问该数据 |
| 4040 | 资源不存在 | 请求的资源ID不存在 |
| 4041 | 接口不存在 | 请求的URL不存在 |
| 4090 | 数据冲突 | 并发修改导致的数据冲突 |
| 4220 | 请求体格式错误 | JSON解析失败 |
| 4290 | 请求过于频繁 | 触发限流策略 |
| 5000 | 服务器内部错误 | 通用服务端错误 |
| 5001 | 数据库操作失败 | SQL执行异常 |
| 5002 | 外部服务调用失败 | 第三方服务异常 |
| 5003 | 文件操作失败 | 上传/下载/读写异常 |

## 2. 认证与用户接口

### 2.1 账号密码登录

**接口信息：**

| 项目 | 内容 |
|------|------|
| 请求方法 | POST |
| URL | /api/v1/auth/login |
| 认证要求 | 否 |

**请求参数：**

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| username | string | 是 | 用户名/工号 |
| password | string | 是 | 密码（前端RSA加密传输） |
| captcha_id | string | 是 | 验证码ID |
| captcha_code | string | 是 | 验证码内容 |
| remember | bool | 否 | 是否记住登录（7天） |

**请求示例：**

```json
{
  "username": "zhangsan",
  "password": "encrypted_password_string",
  "captcha_id": "cap-20240607-001",
  "captcha_code": "a3f7",
  "remember": true
}
```

**响应示例（成功）：**

```json
{
  "code": 200,
  "message": "登录成功",
  "data": {
    "access_token": "eyJhbGciOiJIUzI1NiIs...",
    "refresh_token": "eyJhbGciOiJIUzI1NiIs...",
    "token_type": "Bearer",
    "expires_in": 28800,
    "user": {
      "id": 1001,
      "username": "zhangsan",
      "real_name": "张三",
      "avatar": "https://...",
      "department": "工艺技术部",
      "roles": ["工艺工程师"]
    }
  },
  "request_id": "req-001",
  "timestamp": 1717737600
}
```

**响应示例（失败）：**

```json
{
  "code": 4012,
  "message": "用户名或密码错误",
  "data": {
    "remaining_attempts": 3,
    "lock_until": null
  },
  "request_id": "req-002",
  "timestamp": 1717737600
}
```
