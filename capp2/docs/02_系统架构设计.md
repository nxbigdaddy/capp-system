## 1. 设计原则

### 1.1 高内聚低耦合

- **模块内聚**：每个业务模块内部功能高度相关，单一模块负责完整的业务领域（如工艺管理模块独立完成工艺路线、工艺卡片的CRUD及审批流程）
- **模块间解耦**：模块间通过标准接口通信，避免直接依赖对方内部实现。采用事件驱动机制处理跨模块业务（如工艺变更通过消息队列通知相关模块）
- **数据库隔离**：核心业务表按模块划分，公共数据通过统一的数据服务访问，避免跨模块直接操作数据表

### 1.2 可扩展性

- **水平扩展**：应用层采用无状态设计，支持通过增加服务器节点实现水平扩展
- **插件化架构**：核心业务功能采用插件机制，新功能可通过插件方式动态加载，无需修改核心代码
- **接口适配层**：与外部系统（PLM/ERP/MES/MaxKB）的对接通过适配层隔离，外部系统变更时仅需修改适配层实现
- **多租户预留**：数据模型预留租户字段，为未来多租户扩展提供基础

### 1.3 安全性

- **纵深防御**：从网络层、应用层、数据层多维度实施安全策略
- **最小权限**：基于RBAC模型实现细粒度权限控制，用户仅拥有完成工作所需的最小权限
- **数据安全**：敏感数据加密存储，传输过程全链路加密，操作全程留痕审计
- **接口安全**：外部API采用签名验证+Token双认证机制，防止未授权访问

### 1.4 易维护性

- **标准化编码**：遵循PSR编码规范，统一代码风格，提高代码可读性
- **文档驱动**：核心接口、复杂业务逻辑必须配套文档，文档与代码同步更新
- **监控告警**：全链路监控，关键指标实时告警，故障快速定位
- **自动化测试**：核心业务逻辑配套单元测试，关键流程配套集成测试

## 2. 技术架构

### 2.1 技术栈选型

| 层级 | 技术选型 | 版本 | 选型理由 |
|------|----------|------|----------|
| 前端框架 | Vue.js | 3.x | 渐进式框架，组件化开发，生态成熟，适合企业级应用 |
| UI组件库 | Element Plus | 2.x | 基于Vue 3的组件库，企业级UI设计，组件丰富 |
| 前端构建 | Vite | 5.x | 极速冷启动，模块热更新，现代化构建工具 |
| 后端语言 | PHP | 8.2+ | 企业现有技术栈，性能优异，原生开发灵活可控 |
| 数据库 | MySQL | 8.0 | 成熟稳定，支持JSON类型、窗口函数，满足复杂查询需求 |
| 缓存 | Redis | 7.x | 高性能缓存，支持多种数据结构，会话管理、分布式锁 |
| 消息队列 | RabbitMQ | 3.12+ | 可靠消息投递，支持事务消息、延迟消息，适合企业集成场景 |
| 文件存储 | MinIO | 最新稳定版 | 兼容S3协议，分布式对象存储，适合工艺文档/图纸存储 |
| 搜索引擎 | Elasticsearch | 8.x | 全文检索、聚合分析，支持工艺文档/知识库的高效检索 |
| AI服务 | Python + Flask | Python 3.11+ | 独立微服务，与PHP主应用解耦，便于AI模型迭代 |
| 知识库系统 | MaxKB专业版 | 最新版 | 企业知识库系统，支持文档管理、智能问答、智能体 |
| 反向代理 | Nginx | 1.24+ | 高性能反向代理，负载均衡，静态资源服务 |
| 容器化 | Docker + Docker Compose | 最新版 | 环境一致性，快速部署，便于扩展 |

## 4. 应用架构分层

### 4.1 六层架构模型

```
┌─────────────────────────────────────────────────────────────────────┐
│                           表现层 (Presentation Layer)                │
│  Vue.js 3 SPA + Element Plus + ECharts（数据可视化）               │
│  功能：用户界面渲染、交互响应、表单验证、数据展示                     │
├─────────────────────────────────────────────────────────────────────┤
│                           接入层 (Access Layer)                      │
│  Nginx反向代理 + 负载均衡 + SSL终止 + 静态资源服务                   │
│  功能：请求路由、负载分发、安全认证、限流熔断                         │
├─────────────────────────────────────────────────────────────────────┤
│                           应用层 (Application Layer)                 │
│  PHP Controller + 中间件（认证/权限/日志/异常处理）                  │
│  功能：请求接收、参数校验、调用业务层、响应封装                       │
├─────────────────────────────────────────────────────────────────────┤
│                           服务层 (Service Layer)                     │
│  PHP Service + 领域模型 + 业务规则引擎                              │
│  功能：业务逻辑编排、事务管理、跨模块协调、数据转换                   │
├─────────────────────────────────────────────────────────────────────┤
│                           数据层 (Data Layer)                        │
│  MySQL + Redis + Elasticsearch + MinIO                             │
│  功能：数据持久化、缓存加速、全文检索、文件存储                       │
├─────────────────────────────────────────────────────────────────────┤
│                           集成层 (Integration Layer)                 │
│  CAXA PLM / U8 ERP / MES / 企业微信 / MaxKB / AI服务               │
│  功能：外部系统对接、数据交换、消息推送、智能服务                     │
└─────────────────────────────────────────────────────────────────────┘
```

### 4.2 各层职责说明

#### 4.2.1 表现层

| 职责 | 说明 |
|------|------|
| 页面渲染 | 基于Vue组件化开发，实现工艺管理各功能页面 |
| 状态管理 | 使用Pinia管理全局状态（用户信息、权限、工艺数据缓存） |
| 路由管理 | Vue Router实现前端路由，配合权限守卫控制页面访问 |
| UI组件 | Element Plus提供表格、表单、对话框、树形控件等基础组件 |
| 数据可视化 | ECharts实现工艺数据统计图表（工时分析、材料消耗等） |
| 智能体嵌入 | 集成MaxKB智能体对话组件，实现页面内智能问答 |

#### 4.2.2 接入层

| 职责 | 说明 |
|------|------|
| 反向代理 | Nginx将前端请求转发至PHP应用，静态资源直接由Nginx提供 |
| 负载均衡 | 多PHP应用节点时，Nginx进行请求分发（轮询/权重/IP哈希） |
| SSL终止 | HTTPS请求在Nginx层解密，后端使用HTTP通信 |
| 限流熔断 | 基于Nginx限流模块或Lua脚本实现API限流保护 |
| 跨域处理 | 统一配置CORS策略，处理前端跨域请求 |

#### 4.2.3 应用层

| 职责 | 说明 |
|------|------|
| 请求路由 | 统一入口index.php，根据URL路由至对应Controller |
| 参数校验 | 校验请求参数合法性，过滤非法输入 |
| 认证鉴权 | JWT Token校验，RBAC权限验证 |
| 日志记录 | 记录请求日志（请求参数、响应结果、执行时间、操作用户） |
| 异常处理 | 统一异常捕获，返回标准化错误响应 |
| 响应封装 | 统一响应格式（code/message/data结构） |

#### 4.2.4 服务层

| 职责 | 说明 |
|------|------|
| 业务逻辑 | 实现核心业务规则（工艺路线编排、BOM转换、变更影响分析） |
| 事务管理 | 跨表操作时保证数据一致性 |
| 数据转换 | DTO与Entity之间的转换，外部数据格式适配 |
| 缓存策略 | 决定何时使用缓存，缓存失效策略 |
| 事件发布 | 业务事件发布至消息队列，驱动异步处理 |
| 外部调用 | 调用外部系统接口（PLM/ERP/MES/MaxKB/AI服务） |

#### 4.2.5 数据层

| 组件 | 用途 | 数据类型 |
|------|------|----------|
| MySQL | 业务数据持久化 | 工艺路线、工艺卡片、BOM、用户、权限、审批流程 |
| Redis | 缓存与会话 | 用户会话、热点数据缓存、分布式锁、消息队列缓冲 |
| Elasticsearch | 全文检索 | 工艺文档全文索引、知识库文档索引、历史记录检索 |
| MinIO | 文件存储 | 工艺图纸、工艺文档附件、检验报告、焊接工艺评定文件 |

#### 4.2.6 集成层

| 外部系统 | 集成方式 | 数据交换 |
|----------|----------|----------|
| CAXA PLM | REST API + 数据库直连（只读） | EBOM、图纸信息、设计变更 |
| U8 ERP | REST API / WebService | 物料主数据、库存、MBOM、成本 |
| MES系统 | REST API + RabbitMQ消息 | 工单下发、报工数据、质量数据 |
| 企业微信 | 企业微信API | 扫码登录、用户同步、消息推送、移动审批 |
| MaxKB专业版 | REST API | 文档同步、知识检索、智能体对话 |
| AI服务 | REST API | 工艺参数推荐、方案优选、问答服务 |
