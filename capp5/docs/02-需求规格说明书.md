# CAPP系统 - 需求规格说明书

> 版本：V1.0 | 日期：2026-06-07 | 状态：初稿

---

## 一、总体描述

### 1.1 产品视角

本CAPP系统是面向工业压缩机和压力容器制造企业的计算机辅助工艺设计平台，基于PHP+MySQL技术栈自主开发（不使用框架），通过Web B/S架构部署，支持PC浏览器和移动端（企业微信内嵌）访问。

系统以工艺数据为核心，覆盖工艺路线设计、工艺规程编制、工时/材料定额、审批流程、变更管理和文件输出等全流程，同时深度集成企业微信、CAXA PLM、用友U8、MES和MaxKB知识库等上下游系统。

### 1.2 用户特征

| 用户类型 | 典型角色 | 计算机水平 | 使用频率 |
|---------|---------|-----------|---------|
| 工艺工程师 | 工艺编制主力 | 中等，熟悉CAD/CAPP | 每日高频 |
| 工艺审核员 | 审核把关 | 中等 | 每日中频 |
| 工艺总师 | 标准制定与管理 | 中等 | 每周 |
| 生产调度 | 查看工艺、排产 | 较低 | 每日中频 |
| 车间操作工 | 查看作业指导书 | 较低 | 每日高频 |
| 质量工程师 | 查看检验卡片 | 中等 | 每日中频 |
| 系统管理员 | 系统配置维护 | 高 | 按需 |

### 1.3 设计约束

- 技术栈：PHP 7.4+ + MySQL 5.7+/8.0，不使用任何PHP框架
- 前端：HTML5 + CSS3 + JavaScript（原生或轻量库），不使用React/Vue等框架
- 部署环境：Windows Server / Linux，Apache/Nginx + PHP-FPM
- 浏览器兼容：Chrome、Edge最新版本，企业微信内置浏览器
- 接口风格：RESTful API，数据格式 JSON

## 二、功能性需求

### 2.1 基础数据管理

#### 2.1.1 物料管理
- 物料编码、名称、规格、材质、图号、计量单位、物料类型（自制件/外购件/标准件）
- 物料分类树（按产品类型、按物料类型多维度分类）
- 物料属性的自定义扩展
- 物料导入/导出（Excel）
- 物料与PLM中EBOM数据的同步

#### 2.1.2 工作中心管理
- 工作中心编码、名称、类型（加工/装配/焊接/热处理/检测）
- 所属车间/产线、额定产能、费率
- 关联设备列表

#### 2.1.3 工序管理
- 标准工序库：工序编码、名称、描述、默认工时、适用工作中心
- 工序分类（机加工/焊接/热处理/装配/检测/表面处理/清洗）
- 工序参数模板（支持不同工序类型的差异化参数定义）
- 工序与工作中心的关联关系

#### 2.1.4 工艺资源管理
- **设备管理**：设备编码、名称、型号、规格、加工能力、所属工作中心、状态
- **工装管理**：工装编码、名称、类型（夹具/模具/胎具）、适用设备、状态
- **刀具管理**：刀具编码、名称、规格、材质、适用设备、寿命
- **量具管理**：量具编码、名称、精度等级、量程、校准周期

#### 2.1.5 人员管理
- 从企业微信同步用户和组织架构
- 人员与角色/权限关联
- 人员资质（焊工资质、检测资质等）管理
- 人员与工作中心关联

### 2.2 工艺路线管理

#### 2.2.1 工艺路线编制
- 基于产品/零部件创建工艺路线
- 定义工序顺序（串行/并行/分支）
- 每个工序指定：工作中心、设备、工装、工时定额、操作人员要求
- 工序间关联关系（前序/后续）
- 支持工艺路线的拖拽排序
- 工艺路线模板管理（支持从模板快速创建）
- 从历史工艺路线中复制和复用

#### 2.2.2 工艺路线状态
- 编制中 → 提交审核 → 审核通过/驳回 → 已发布 → 已废弃
- 状态流转的权限控制
- 不同状态下的操作约束

#### 2.2.3 工艺路线版本
- 版本号规则：V1.0, V1.1, ..., V2.0
- 大版本（发布时升）、小版本（修订时升）
- 版本历史追溯、版本对比（高亮差异）
- 生效版本唯一性控制

### 2.3 工艺规程管理

#### 2.3.1 工序卡管理
- 每道工序对应一张工序卡片
- 卡片内容：工序号、工序名称、工作中心、设备、工装、夹具、刀具、量具
- 加工参数（切削速度、进给量、切削深度等 - 针对机加工）
- 焊接参数（电流、电压、焊接速度、预热温度等 - 针对焊接）
- 操作步骤详细描述
- 检验要求
- 可引用标准工序库快速填充

#### 2.3.2 作业指导书 (SOP)
- 图文并茂的操作指导文件
- 支持上传/引用图纸、示意图、照片
- 步骤化操作说明
- 安全注意事项
- 关键控制点（KCP）标注
- 关联对应的检验卡片

#### 2.3.3 检验卡片
- 检验项目、检验标准、检验方法、检验工具
- 抽样方案（按AQL标准）
- 关键尺寸及公差
- 检验频次
- 关联对应的工序卡片

#### 2.3.4 焊接工艺规程 (WPS)
- 基于焊接工艺评定（PQR）生成
- 包含焊接方法、母材、填充材料、预热/后热、电气特性
- 支持参数化生成和多变量组合

### 2.4 工时定额管理

#### 2.4.1 标准工时制定
- 方法：经验估工法、统计分析法、技术计算法
- 工时构成：准备时间 + 加工时间 + 辅助时间 + 宽放时间
- 按工序设定标准工时
- 支持工时计算公式定义（与加工参数关联）

#### 2.4.2 工时统计
- 按产品/零部件汇总工时
- 按工作中心/设备汇总工时
- 按时间段统计工时（日/周/月）
- 计划工时 vs 实际工时对比（来自MES报工数据）

### 2.5 材料定额管理

#### 2.5.1 材料消耗定额
- 按零部件定义材料定额（毛重、净重、废料）
- 材料利用率计算
- 按产品汇总材料需求
- 支持按材质、规格多维度统计

#### 2.5.2 定额同步
- 材料定额同步至U8系统（用于采购计划）
- 支持定额变更后的同步触发

### 2.6 审批流程管理

#### 2.6.1 流程定义
- 自定义审批流程模板
- 支持：单人审批、多人会签、多人或签、条件分支
- 审批节点配置（节点名称、审批人/角色、超时设置）
- 流程版本管理

#### 2.6.2 审批操作
- 提交审批：锁定被审批对象
- 审批通过：进入下一节点
- 审批驳回：退回至指定节点（含驳回意见）
- 撤回：提交者可在审批前撤回
- 转审：审批人可转给他人
- 加签：审批人可邀请他人加签

#### 2.6.3 审批通知
- 企业微信消息推送（审批待办提醒）
- 超时催办提醒
- 审批结果通知

### 2.7 工艺变更管理 (ECN)

#### 2.7.1 变更申请 (ECR)
- 变更原因分类（设计变更/工艺优化/质量问题/成本优化）
- 变更影响分析（关联的工艺路线/文件/在制品）
- 变更方案描述
- 附件上传

#### 2.7.2 变更执行 (ECN)
- 审批通过后自动生成ECN
- 变更内容执行（修改工艺数据）
- 变更通知下发（通知MES、生产、质量相关方）
- 变更记录归档

#### 2.7.3 变更追溯
- 完整变更历史记录
- 变更前后数据对比
- 变更统计报表

### 2.8 工艺文件输出

#### 2.8.1 输出格式
- PDF（标准格式，不可编辑）
- Word（可编辑，用于分发和修订建议）
- Excel（数据报表）
- HTML（在线预览）

#### 2.8.2 输出类型
- 工艺路线清单
- 工序卡片集
- 作业指导书
- 检验卡片
- 材料定额汇总表
- 工时定额汇总表
- 工装/刀具清单
- 焊接工艺规程 (WPS)

#### 2.8.3 打印控制
- 文件水印（含版本号、输出日期、输出人）
- 打印次数记录
- 受控文件标识

### 2.9 版本管理

#### 2.9.1 版本规则
- 版本号格式：V[主版本].[次版本]
- 发布审批通过触发主版本号升级
- 修订操作触发次版本号升级
- 有效版本标记

#### 2.9.2 版本功能
- 版本历史列表
- 任意版本查看
- 版本比对（差异高亮）
- 版本回退（需管理员权限）

## 三、非功能性需求

### 3.1 性能要求

| 指标 | 要求 |
|------|------|
| 并发用户数 | ≥ 50 并发 |
| 页面响应时间 | ≤ 2秒（常规操作） |
| 复杂查询响应 | ≤ 5秒（大BOM展开、工时汇总） |
| 文件生成 | PDF生成 ≤ 10秒 |
| 数据库连接池 | ≥ 20 |
| 接口响应时间 | ≤ 3秒（内部接口调用） |

### 3.2 安全性要求

| 安全维度 | 要求 |
|---------|------|
| 身份认证 | 支持企业微信OAuth2.0扫码登录 + 本地账号密码双模式 |
| 权限控制 | RBAC模型，支持"用户-角色-权限"三级控制 |
| 数据权限 | 支持按部门、按产品类型的数据隔离 |
| 传输安全 | HTTPS加密传输 |
| 存储安全 | 密码Hash存储(bcrypt)，关键数据AES加密 |
| 审计日志 | 记录所有关键操作（CRUD、登录、审批、导出） |
| 防攻击 | SQL注入防护（参数化查询）、XSS防护、CSRF令牌 |
| 会话管理 | JWT令牌 + 有效期控制 + 刷新机制 |

### 3.3 可用性要求

| 指标 | 要求 |
|------|------|
| 系统可用率 | ≥ 99.5%（全年） |
| 计划停机 | 每月不超过1次，每次≤2小时 |
| 故障恢复 | RTO ≤ 2小时，RPO ≤ 30分钟 |
| 数据备份 | 每日全量备份 + 增量备份，保留30天 |

### 3.4 可扩展性要求

- 采用模块化设计，各功能模块松耦合
- 接口层统一封装，便于对接新系统
- 支持插件化扩展（自定义报表、自定义工序类型）
- 支持水平扩展（Web服务器集群 + 数据库读写分离）
- 配置化设计：审批流程、工序类型、工艺参数模板等可通过配置实现

### 3.5 兼容性要求

| 对接系统 | 兼容版本 | 接口方式 |
|---------|---------|---------|
| 企业微信 | API V3+ | HTTPS RESTful + Webhook |
| CAXA PLM | 2023+ | 数据库直连 + API |
| 用友U8+ | V13.0+ | 数据库直连 + EAI接口 |
| MES系统 | 通用接口 | WebService / RESTful |
| MaxKB | 专业版 1.5+ | RESTful API |

## 五、用例描述

### 5.1 核心用例 - 工艺路线编制

```
参与者：工艺工程师
前置条件：用户已登录，具有工艺路线编制权限；产品/零部件信息已存在
主流程：
1. 用户点击"新建工艺路线"
2. 选择产品/零部件（可从PLM同步或手动选择）
3. 系统显示该零部件的物料信息（图号、材质、规格、重量）
4. 用户从标准工序库中选择工序，按顺序添加到工艺路线
5. 用户调整工序顺序（拖拽或上移/下移）
6. 为每道工序配置：工作中心、设备、工装、刀具、量具
7. 为每道工序输入/估算工时定额
8. 保存工艺路线 → 状态：编制中
9. 可选择"提交审核"或继续编辑
```

### 5.2 核心用例 - AI辅助工艺编制

```
参与者：工艺工程师
前置条件：MaxKB智能体已配置并在线
主流程：
1. 用户进入工艺路线编制页面
```
