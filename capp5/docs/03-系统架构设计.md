# CAPP系统 - 系统架构设计

> 版本：V1.0 | 日期：2026-06-07 | 状态：初稿

---

## 一、架构设计原则

| 原则 | 说明 |
|------|------|
| 分层分离 | 表现层、业务层、数据访问层严格分离，层次间单向依赖 |
| 模块化 | 按业务领域拆分为独立模块，支持按需组合部署 |
| 接口标准化 | 内部模块间和外部系统间均采用统一API规范 |
| 安全优先 | 认证鉴权前置，输入输出过滤，审计全记录 |
| 无框架原则 | 不使用任何PHP框架，所有基础能力自实现 |
| 可扩展 | 支持水平扩展，数据库读写分离，文件存储分离 |

## 五、安全架构

### 5.1 认证流程

```
用户 → 企业微信扫码 → 企业微信OAuth服务器 → 回调返回code
     → CAPP换取AccessToken → 获取用户信息 → JWT生成 → 前端存储Token
     → 后续请求携带Authorization: Bearer {token}
     → AuthMiddleware验证JWT有效性
```

### 5.2 安全措施分层

| 层级 | 措施 |
|------|------|
| 网络层 | HTTPS、WAF防火墙、IP白名单（可选） |
| 应用层 | JWT认证、RBAC鉴权、CSRF令牌、参数化查询、输入验证 |
| 数据层 | 密码bcrypt哈希、敏感字段AES加密、审计日志 |
| 运维层 | 定期安全扫描、日志监控、异常告警 |

### 5.3 审计日志

记录字段：操作人、操作时间、IP地址、操作类型（增删改查/登录/审批/导出）、操作对象（模块/表/ID）、操作前后数据快照（重要操作）

## 六、核心流程架构

### 6.1 请求生命周期

```
HTTP请求
  → public/index.php (统一入口)
  → 自动加载 (spl_autoload_register)
  → Router解析URL → 匹配路由规则
  → 全局中间件执行 (CORS → Session → Auth → CSRF)
  → 控制器方法调用
    → 参数验证
    → 业务逻辑处理 (Service层)
      → 数据操作 (Model层/Query Builder)
      → 缓存读写 (Redis)
      → 外部系统调用 (Integration层)
    → 返回数据 / 视图渲染
  → JSON响应 / HTML响应
```

### 6.2 服务容器模式

系统采用简单的服务容器实现依赖管理（非IOC容器，而是服务注册表模式）：

```php
// ServiceContainer.php
class ServiceContainer {
    private static $services = [];

    public static function register($name, callable $factory) {
        self::$services[$name] = $factory;
    }

    public static function get($name) {
        if (!isset(self::$services[$name])) {
            throw new Exception("Service not found: $name");
        }
        $factory = self::$services[$name];
        return $factory();
    }
}

// 使用示例
ServiceContainer::register('db', function() {
    return Database::getInstance();
});
ServiceContainer::register('wework', function() {
    return new WeWorkClient(config('wework'));
});
```
