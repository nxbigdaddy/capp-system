## 1. 系统环境要求

### 1.1 服务器配置要求

CAPP系统作为工业压缩机、压力容器研发设计生产企业的核心工艺管理系统，对服务器硬件配置有明确要求。根据企业用户规模（预计并发用户50-200人）及工艺文件存储需求，推荐以下服务器配置：

**生产环境最低配置：**
- CPU：Intel Xeon E5-2680 v4 或同等性能处理器，8核16线程及以上
- 内存：32GB DDR4 ECC内存（生产环境建议64GB）
- 系统盘：256GB SSD固态硬盘（RAID 1镜像）
- 数据盘：1TB SSD固态硬盘或SAS硬盘（RAID 5/10，根据数据重要性选择）
- 文件存储盘：2TB以上机械硬盘或NAS存储（用于工艺图纸、文档等附件存储）
- 网卡：千兆以太网双网卡（支持链路聚合）

**推荐配置（中型企业）：**
- CPU：Intel Xeon Gold 6248R 或 AMD EPYC 7302，16核32线程
- 内存：64GB DDR4 ECC
- 系统盘：512GB NVMe SSD（RAID 1）
- 数据盘：2TB SSD（RAID 10）
- 文件存储：4TB以上企业级NAS或SAN存储

### 1.2 操作系统要求

本系统支持以下操作系统环境：

**推荐操作系统：**
- CentOS 7.9 / Rocky Linux 8.x / AlmaLinux 8.x
- Ubuntu Server 20.04 LTS / 22.04 LTS

**系统内核要求：**
- Linux内核版本 3.10 及以上
- 文件系统：ext4 或 XFS（推荐XFS用于大文件存储）
- 时区设置：Asia/Shanghai（CST+8）

**系统基础组件：**
- OpenSSL 1.1.1 及以上版本
- curl 7.60 及以上版本
- wget、vim、unzip、git 等基础工具
- chrony 或 ntpd 时间同步服务

### 1.3 PHP环境要求

CAPP系统基于PHP原生开发，对PHP运行环境要求如下：

**PHP版本：** PHP 8.0.x 或 PHP 8.1.x（推荐PHP 8.1.20及以上稳定版本）

**必需扩展：**
- mysqli / pdo_mysql：MySQL数据库连接
- gd / imagick：图像处理（工艺图纸预览、缩略图生成）
- mbstring：多字节字符串处理
- json：JSON数据解析
- xml / simplexml：XML数据处理
- zip：压缩文件处理
- fileinfo：文件类型识别
- openssl：加密与HTTPS通信
- curl：HTTP请求（企业微信API对接、外部系统集成）
- session：用户会话管理
- opcache：PHP字节码缓存（生产环境必须启用）

**推荐扩展：**
- redis：缓存与会话存储（高并发场景）
- memcached：分布式缓存
- exif：图片EXIF信息读取
- intl：国际化支持

**PHP关键配置参数：**
```ini
memory_limit = 512M
upload_max_filesize = 100M
post_max_size = 100M
max_execution_time = 300
max_input_time = 300
max_file_uploads = 20
session.gc_maxlifetime = 3600
opcache.enable = 1
opcache.memory_consumption = 256
opcache.max_accelerated_files = 10000
```

### 1.4 MySQL数据库要求

**数据库版本：** MySQL 8.0.28 及以上版本，或 MariaDB 10.6 及以上版本

**推荐配置参数：**
```ini
[mysqld]
character-set-server = utf8mb4
collation-server = utf8mb4_unicode_ci
max_connections = 500
innodb_buffer_pool_size = 16G  # 根据物理内存调整，建议设置为内存的50-70%
innodb_log_file_size = 1G
innodb_flush_log_at_trx_commit = 2  # 生产环境可权衡性能与持久性
query_cache_type = 0
query_cache_size = 0
tmp_table_size = 64M
max_heap_table_size = 64M
slow_query_log = 1
slow_query_log_file = /var/log/mysql/slow.log
long_query_time = 2
log_error = /var/log/mysql/error.log
```

### 1.5 Web服务器配置

**Nginx（推荐）：**
- 版本：Nginx 1.20.x 及以上稳定版本
- 功能要求：支持反向代理、静态文件缓存、Gzip压缩、SSL/TLS终止
- 连接数配置：worker_processes 设置为CPU核心数，worker_connections 设置为4096

**Apache（备选）：**
- 版本：Apache 2.4.x 及以上
- 必需模块：mod_rewrite、mod_ssl、mod_deflate、mod_expires

### 1.6 网络环境要求

- 内网带宽：千兆局域网环境
- 外网带宽：如需企业微信集成、外部系统对接，需保证稳定的外网连接（建议10Mbps以上专线）
- 固定公网IP：用于企业微信回调配置（如使用企业微信扫码登录、消息推送）
- 域名：建议配置企业自有域名，并申请ICP备案（中国大陆部署）
- 防火墙：开放80/443端口（Web访问），3306端口（数据库，建议仅内网访问），22端口（SSH管理）

### 2.2 网络拓扑结构

在企业内网环境中，CAPP系统建议部署在独立的应用服务器网段：

- **DMZ区域**：部署Nginx反向代理服务器，对外提供HTTPS服务，对内转发请求
- **应用网段**：部署PHP应用服务器（可单台或多台），数据库连接仅允许来自应用服务器
- **数据库网段**：部署MySQL主从服务器，仅开放3306端口给应用服务器
- **存储网段**：部署NAS或文件服务器，通过NFS/SMB协议挂载到应用服务器
- **管理网段**：运维人员通过VPN或堡垒机访问服务器，进行日常维护

### 2.3 数据流向说明

1. **用户请求流**：用户浏览器 → 企业防火墙 → Nginx → PHP-FPM → MySQL/文件存储
2. **文件上传流**：用户上传工艺文件 → PHP接收 → 文件校验 → 存储到文件系统 → 记录数据库
3. **外部集成流**：企业微信/ERP/PLM → API网关 → PHP应用 → 数据库 → 返回响应
4. **备份数据流**：数据库定时导出 → 压缩加密 → 传输到备份服务器/异地存储

## 3. 安装部署步骤

### 3.1 操作系统初始化

**步骤1：系统更新与基础工具安装**
```bash
# CentOS/Rocky Linux
yum update -y
yum install -y vim wget curl net-tools unzip git chrony

# 配置时间同步
systemctl enable chronyd
systemctl start chronyd

# 配置主机名
hostnamectl set-hostname capp-server-prod

# 关闭SELinux（或配置为Permissive）
sed -i 's/SELINUX=enforcing/SELINUX=permissive/g' /etc/selinux/config
setenforce 0

# 配置防火墙（仅开放必要端口）
firewall-cmd --permanent --add-service=ssh
firewall-cmd --permanent --add-service=http
firewall-cmd --permanent --add-service=https
firewall-cmd --reload
```

**步骤2：创建应用运行用户**
```bash
# 创建专用用户（禁止登录）
useradd -r -s /sbin/nologin -d /var/www/capp -M capp

# 创建目录结构
mkdir -p /var/www/capp
mkdir -p /var/log/capp
mkdir -p /data/capp/uploads
mkdir -p /data/capp/backup

# 设置目录权限
chown -R capp:capp /var/www/capp
chown -R capp:capp /var/log/capp
chown -R capp:capp /data/capp
```

### 3.2 PHP运行环境安装

**步骤1：安装PHP 8.1（以Remi源为例）**
```bash
# CentOS/Rocky Linux 8
yum install -y epel-release
yum install -y https://rpms.remirepo.net/enterprise/remi-release-8.rpm
yum module reset php
yum module enable php:remi-8.1
yum install -y php php-cli php-fpm php-mysqlnd php-gd php-mbstring \
    php-json php-xml php-zip php-fileinfo php-opcache php-curl \
    php-session php-openssl php-intl php-exif

# 验证安装
php -v
php -m
```

**步骤2：配置PHP-FPM**
```bash
# 编辑 /etc/php-fpm.d/www.conf
# 修改用户和组
cat > /etc/php-fpm.d/www.conf << 'EOF'
[capp]
user = capp
group = capp
listen = /run/php-fpm/capp.sock
listen.owner = nginx
listen.group = nginx
listen.mode = 0660
pm = dynamic
pm.max_children = 50
pm.start_servers = 10
pm.min_spare_servers = 5
pm.max_spare_servers = 20
pm.max_requests = 500
slowlog = /var/log/php-fpm/slow.log
request_slowlog_timeout = 5s
php_admin_value[error_log] = /var/log/php-fpm/error.log
php_admin_flag[log_errors] = on
EOF

# 创建运行目录
mkdir -p /run/php-fpm
chown -R capp:capp /run/php-fpm

# 启动PHP-FPM
systemctl enable php-fpm
systemctl start php-fpm
```

### 3.3 MySQL数据库安装

**步骤1：安装MySQL 8.0**
```bash
# 下载并安装MySQL官方YUM源
wget https://dev.mysql.com/get/mysql80-community-release-el8-9.noarch.rpm
rpm -Uvh mysql80-community-release-el8-9.noarch.rpm
yum install -y mysql-community-server

# 启动MySQL
systemctl enable mysqld
systemctl start mysqld

# 获取初始密码
TEMP_PASS=$(grep 'temporary password' /var/log/mysqld.log | awk '{print $NF}')
echo "临时密码: $TEMP_PASS"
```

**步骤2：安全初始化**
```bash
# 运行安全脚本
mysql_secure_installation

# 或手动配置
mysql -uroot -p -e "ALTER USER 'root'@'localhost' IDENTIFIED BY 'YourStrongPassword123!';
DELETE FROM mysql.user WHERE User='';
DELETE FROM mysql.user WHERE User='root' AND Host NOT IN ('localhost', '127.0.0.1', '::1');
DROP DATABASE IF EXISTS test;
FLUSH PRIVILEGES;"
```

### 3.4 Nginx安装与配置

**步骤1：安装Nginx**
```bash
# 安装Nginx
yum install -y nginx

# 启动Nginx
systemctl enable nginx
systemctl start nginx
```

**步骤2：配置Nginx虚拟主机**
```bash
# 创建配置文件 /etc/nginx/conf.d/capp.conf
cat > /etc/nginx/conf.d/capp.conf << 'EOF'
server {
    listen 80;
    server_name capp.yourcompany.com;
    root /var/www/capp/public;
    index index.php index.html;

    # 日志配置
    access_log /var/log/nginx/capp_access.log;
    error_log /var/log/nginx/capp_error.log;

    # 客户端上传限制
    client_max_body_size 100M;
    client_body_timeout 300s;

    # 静态文件缓存
    location ~* \.(jpg|jpeg|png|gif|ico|css|js|pdf|dwg|zip|rar)$ {
        expires 30d;
        add_header Cache-Control "public, immutable";
        try_files $uri $uri/ =404;
    }

    # 禁止访问敏感文件
    location ~* \.(git|svn|env|ini|log|sql)$ {
        deny all;
        return 403;
    }

    # 禁止访问目录
    location ~ ^/(config|logs|vendor|storage/private)/ {
        deny all;
        return 403;
    }

    # PHP处理
    location ~ \.php$ {
        try_files $uri =404;
        fastcgi_pass unix:/run/php-fpm/capp.sock;
        fastcgi_index index.php;
        fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
        include fastcgi_params;
        fastcgi_connect_timeout 300;
        fastcgi_send_timeout 300;
        fastcgi_read_timeout 300;
        fastcgi_buffer_size 128k;
        fastcgi_buffers 4 256k;
    }

    # 重写规则（URL美化）
    location / {
        try_files $uri $uri/ /index.php?$query_string;
    }
}
EOF

# 测试配置并重启
nginx -t
systemctl reload nginx
```

### 3.5 应用代码部署

**步骤1：代码上传**
```bash
# 方式1：Git克隆（推荐）
cd /var/www/capp
git clone https://your-git-server.com/capp-system.git .

# 方式2：压缩包上传
# 将代码压缩包上传至 /tmp/capp.zip
unzip /tmp/capp.zip -d /var/www/capp/
```

## 7. 备份策略

### 7.1 数据库备份策略

**备份频率与保留策略：**

| 备份类型 | 频率 | 保留时间 | 存储位置 |
|----------|------|----------|----------|
| 全量备份 | 每日凌晨02:00 | 30天 | 本地备份盘 + 异地备份服务器 |
| 增量备份 | 每6小时 | 7天 | 本地备份盘 |
| 实时Binlog | 持续 | 15天 | 本地备份盘 |

**全量备份脚本（/var/www/capp/scripts/backup_db.sh）**
```bash
#!/bin/bash
# 数据库备份脚本

BACKUP_DIR="/data/capp/backup/db"
DATE=$(date +%Y%m%d_%H%M%S)
DB_NAME="capp_db"
DB_USER="capp_backup"
DB_PASS="BackupPassword2024!"
RETENTION_DAYS=30

# 创建备份目录
mkdir -p ${BACKUP_DIR}

# 执行全量备份
mysqldump -u${DB_USER} -p${DB_PASS} \
    --single-transaction \
    --routines \
    --triggers \
    --events \
    --hex-blob \
    --skip-lock-tables \
    ${DB_NAME} | gzip > ${BACKUP_DIR}/${DB_NAME}_${DATE}.sql.gz

# 验证备份文件
if [ -f "${BACKUP_DIR}/${DB_NAME}_${DATE}.sql.gz" ]; then
    echo "[$(date)] 数据库备份成功: ${DB_NAME}_${DATE}.sql.gz"
    # 计算MD5校验值
    md5sum ${BACKUP_DIR}/${DB_NAME}_${DATE}.sql.gz > ${BACKUP_DIR}/${DB_NAME}_${DATE}.sql.gz.md5
else
    echo "[$(date)] 数据库备份失败!" >&2
    exit 1
fi

# 清理过期备份
find ${BACKUP_DIR} -name "${DB_NAME}_*.sql.gz" -mtime +${RETENTION_DAYS} -delete
find ${BACKUP_DIR} -name "${DB_NAME}_*.sql.gz.md5" -mtime +${RETENTION_DAYS} -delete

# 同步到异地备份服务器（可选）
# rsync -avz ${BACKUP_DIR}/ backup-server:/backup/capp/db/
```

**系统监控脚本（/var/www/capp/scripts/monitor_system.sh）**
```bash
#!/bin/bash
# 系统监控数据采集

LOG_FILE="/var/log/capp/monitor/system_$(date +%Y%m%d).log"
mkdir -p $(dirname ${LOG_FILE})

# CPU和内存
CPU_IDLE=$(top -bn1 | grep "Cpu(s)" | awk '{print $8}')
MEM_USED=$(free | grep Mem | awk '{print $3/$2 * 100.0}')
LOAD_AVG=$(uptime | awk -F'load average:' '{print $2}')

# 磁盘
DISK_USED=$(df -h /data | tail -1 | awk '{print $5}' | tr -d '%')

# PHP-FPM进程数
FPM_PROCS=$(pgrep -c "php-fpm")

# 记录日志
echo "$(date '+%Y-%m-%d %H:%M:%S') CPU_IDLE=${CPU_IDLE} MEM_USED=${MEM_USED} LOAD_AVG=${LOAD_AVG} DISK_USED=${DISK_USED} FPM_PROCS=${FPM_PROCS}" >> ${LOG_FILE}
```

### 8.2 应用监控

**监控指标：**

| 指标名称 | 说明 | 告警阈值 |
|----------|------|----------|
| HTTP响应时间 | 页面平均响应时间 | > 3秒告警 |
| HTTP错误率 | 5xx错误占比 | > 1%告警 |

**应用健康检查接口：**
```php
// /public/health.php
<?php
header('Content-Type: application/json');

$checks = [
    'status' => 'ok',
    'timestamp' => date('Y-m-d H:i:s'),
    'checks' => []
];

// 数据库连接检查
try {
    $pdo = new PDO('mysql:host=localhost;dbname=capp_db', 'capp_user', 'password');
    $checks['checks']['database'] = 'ok';
} catch (Exception $e) {
    $checks['status'] = 'error';
    $checks['checks']['database'] = 'error: ' . $e->getMessage();
}

// 文件系统检查
if (is_writable('/data/capp/uploads')) {
    $checks['checks']['filesystem'] = 'ok';
} else {
    $checks['status'] = 'error';
    $checks['checks']['filesystem'] = 'not writable';
}

// 磁盘空间检查
$disk_free = disk_free_space('/data');
$disk_total = disk_total_space('/data');
$disk_usage = ($disk_total - $disk_free) / $disk_total * 100;
$checks['checks']['disk_usage_percent'] = round($disk_usage, 2);

if ($disk_usage > 90) {
    $checks['status'] = 'warning';
}

http_response_code($checks['status'] === 'ok' ? 200 : 503);
echo json_encode($checks, JSON_PRETTY_PRINT | JSON_UNESCAPED_UNICODE);
```

| 慢查询数量 | 每分钟慢查询数 | > 10条/分钟告警 |
| 主从延迟 | 从库复制延迟（如有主从） | > 5秒告警 |
| 锁等待 | 当前锁等待事务数 | > 5告警 |
| 临时表使用率 | 内存临时表转磁盘比例 | > 50%告警 |

**MySQL监控查询：**
```sql
-- 连接数监控
SHOW STATUS LIKE 'Threads_connected';
SHOW STATUS LIKE 'Max_used_connections';

-- 慢查询监控
SHOW GLOBAL STATUS LIKE 'Slow_queries';

-- 锁监控
SELECT * FROM information_schema.INNODB_LOCK_WAITS;

-- 主从延迟（从库执行）
SHOW SLAVE STATUS\G
-- 查看 Seconds_Behind_Master 字段
```

### 8.4 日志监控

**日志收集与分析：**

| 日志类型 | 路径 | 监控重点 | 分析工具 |
|----------|------|----------|----------|

## 9. 告警方案

### 9.1 告警规则定义

**告警级别划分：**

| 级别 | 标识 | 说明 | 响应时间要求 |
|------|------|------|-------------|
| P0 | 紧急 | 系统完全不可用、数据丢失风险 | 5分钟内响应 |
| P1 | 严重 | 核心功能受影响、性能严重下降 | 15分钟内响应 |
| P2 | 一般 | 非核心功能异常、性能轻微下降 | 1小时内响应 |
| P3 | 提示 | 资源使用预警、非紧急问题 | 4小时内响应 |

**具体告警规则：**

| 规则名称 | 触发条件 | 级别 | 通知方式 |
|----------|----------|------|----------|
| 服务宕机 | Nginx/PHP-FPM/MySQL进程不存在 | P0 | 电话+短信+企业微信 |
| 磁盘空间不足 | 磁盘使用率 > 90% | P1 | 企业微信+邮件 |
| 内存不足 | 内存使用率 > 85% | P1 | 企业微信+邮件 |
| CPU过载 | CPU使用率 > 90% 持续5分钟 | P1 | 企业微信+邮件 |
| 数据库连接耗尽 | 连接数使用率 > 85% | P1 | 企业微信+短信 |
| 慢查询激增 | 慢查询 > 20条/分钟 | P2 | 企业微信 |
| 备份失败 | 备份脚本返回非0 | P1 | 企业微信+邮件 |
| 登录异常 | 同一IP失败 > 10次/分钟 | P2 | 企业微信 |
| 文件上传异常 | 上传失败率 > 5% | P2 | 企业微信 |
| SSL证书过期 | 证书剩余有效期 < 30天 | P3 | 邮件 |

### 9.2 告警通知方式

**企业微信告警机器人集成：**
```php
<?php
// 告警通知类
class AlertService {
    private $webhookUrl;
    
    public function __construct() {
        $this->webhookUrl = 'https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=YOUR_WEBHOOK_KEY';
    }
    
    public function sendAlert($level, $title, $content) {
        $colors = [
            'P0' => 'FF0000',  // 红色

            'msgtype' => 'markdown',
            'markdown' => [

                    "> 服务器：" . gethostname() . "\n" .
```

**通知渠道优先级：**
- P0级：电话 → 短信 → 企业微信 → 邮件（同时发送）
- P1级：企业微信 → 短信 → 邮件
- P2级：企业微信 → 邮件
- P3级：邮件

### 9.3 告警升级机制

**升级规则：**
- P0告警：5分钟内未确认，自动升级通知至部门负责人
- P1告警：15分钟内未处理，升级通知至技术主管
- 连续3次同类告警未解决，自动创建故障工单

**告警抑制：**
- 相同告警在30分钟内不重复发送（仅更新计数）
- 维护窗口期（00:00-06:00部分低优先级告警静默）
- 批量告警合并发送（1分钟内超过5条同类告警合并为一条）

## 10. 故障处理

### 10.1 常见问题排查

**问题1：页面访问502 Bad Gateway**

排查步骤：
1. 检查PHP-FPM进程是否运行：`systemctl status php-fpm`
2. 检查PHP-FPM监听地址： `ss -ln | grep 9000` 或 `ls -la /run/php-fpm/`
3. 检查Nginx配置中的fastcgi_pass是否与PHP-FPM监听一致
4. 检查PHP-FPM错误日志：`tail -f /var/log/php-fpm/error.log`
5. 检查SELinux是否阻止连接：`getenforce`（如为Enforcing，尝试设为Permissive）

**问题2：数据库连接失败**

排查步骤：
1. 检查MySQL服务状态：`systemctl status mysqld`
2. 检查连接参数（host/port/username/password）
3. 检查MySQL用户权限：`SHOW GRANTS FOR 'capp_user'@'localhost';`
4. 检查连接数是否耗尽：`SHOW STATUS LIKE 'Threads_connected';`
5. 检查防火墙是否阻止3306端口

**问题3：文件上传失败**

排查步骤：
1. 检查PHP配置：`upload_max_filesize`、`post_max_size`
2. 检查Nginx配置：`client_max_body_size`
3. 检查上传目录权限：`ls -la /data/capp/uploads`
4. 检查磁盘空间：`df -h /data`
5. 检查文件类型限制：对比 `allowed_file_types` 配置

**问题4：系统响应缓慢**

排查步骤：
1. 检查系统负载：`top`、`uptime`
2. 检查慢查询日志：`tail -f /var/log/mysql/slow.log`
3. 检查PHP慢日志：`tail -f /var/log/php-fpm/slow.log`
4. 检查磁盘I/O：`iostat -x 1`
5. 检查内存使用：`free -h`，是否使用Swap
6. 检查OPcache命中率：`php -r 'print_r(opcache_get_status());'`

### 10.2 应急处理方案

**场景1：数据库主库故障**

应急步骤：
1. 立即停止应用服务，防止数据写入异常
2. 如配置主从复制，将从库提升为主库：
   ```sql
   -- 在从库执行
   STOP SLAVE;
   RESET SLAVE ALL;
   -- 修改应用配置指向从库（新主库）
   ```
3. 修改应用数据库配置，指向新主库
4. 重启应用服务
5. 通知用户系统恢复，部分数据可能需要人工核对
6. 修复原主库后，重新配置主从关系

**场景2：磁盘空间耗尽**

应急步骤：
1. 快速定位大文件：`du -sh /data/capp/* | sort -rh | head -20`
2. 清理临时文件：`rm -rf /var/www/capp/storage/temp/*`
3. 清理过期日志：执行logrotate或手动清理
4. 清理过期备份（保留最近3天）
5. 如空间仍不足，临时扩容或迁移部分文件到备用存储
6. 事后分析增长原因，调整存储策略

**场景3：应用服务被攻击**

应急步骤：
1. 分析访问日志，识别攻击源IP
2. 在防火墙封禁恶意IP：`firewall-cmd --add-rich-rule='rule family=ipv4 source address=1.2.3.4 reject'`
3. 如为CC攻击，启用Nginx限流配置
4. 如为SQL注入尝试，检查WAF规则
5. 必要时临时关闭外网访问，仅保留VPN访问
6. 保留攻击日志，用于事后分析和报警

### 10.3 故障恢复流程

**标准故障恢复流程：**

```
1. 发现故障
   └─> 监控系统告警 / 用户反馈 / 巡检发现

2. 故障确认
   └─> 登录服务器确认故障现象
   └─> 判断故障级别（P0/P1/P2/P3）
   └─> 通知相关责任人

3. 故障处理
   └─> 启动应急预案（如需要）
   └─> 执行修复操作
   └─> 验证修复结果

4. 服务恢复
   └─> 逐步恢复服务
   └─> 监控关键指标确认正常
   └─> 通知用户系统恢复

5. 事后复盘
   └─> 记录故障时间线
   └─> 分析根因
   └─> 制定改进措施
   └─> 更新应急预案
```

## 11. 升级方案

### 11.1 版本升级流程

**升级前准备：**
1. 阅读版本发布说明，了解变更内容、兼容性影响
2. 在测试环境完整验证新版本
3. 制定升级计划，明确升级时间窗口（建议选择业务低峰期）
4. 完整备份数据库和文件
5. 通知用户升级计划，必要时暂停系统使用

**升级执行步骤：**
```bash
#!/bin/bash
# 升级脚本 /var/www/capp/scripts/upgrade.sh

VERSION=$1
BACKUP_DIR="/data/capp/backup/pre_upgrade_$(date +%Y%m%d_%H%M%S)"

echo "=== CAPP系统升级开始 ==="
echo "目标版本: ${VERSION}"
echo "备份目录: ${BACKUP_DIR}"

# 1. 创建升级前备份
mkdir -p ${BACKUP_DIR}
mysqldump -ucapp_backup -p'BackupPassword2024!' --single-transaction capp_db | gzip > ${BACKUP_DIR}/db_pre_upgrade.sql.gz
tar czf ${BACKUP_DIR}/code_pre_upgrade.tar.gz -C /var/www/capp .

# 2. 进入维护模式（如支持）
touch /var/www/capp/storage/maintenance.flag

# 3. 停止应用服务
systemctl stop php-fpm

# 4. 更新代码
cd /var/www/capp
git fetch origin
git checkout ${VERSION}
# 或解压新版本代码包

# 5. 执行数据库迁移
php /var/www/capp/scripts/migrate.php

# 6. 更新配置文件（如有变更）
# 对比新旧配置，合并自定义配置

# 7. 清理缓存
rm -rf /var/www/capp/storage/cache/*

# 8. 设置权限
chown -R capp:capp /var/www/capp
find /var/www/capp -type f -exec chmod 644 {} \;
find /var/www/capp -type d -exec chmod 755 {} \;
chmod -R 775 /var/www/capp/storage

# 9. 启动服务
systemctl start php-fpm

# 10. 健康检查
sleep 5
curl -f http://localhost/health.php || {
    echo "健康检查失败，准备回滚!"
    # 触发回滚
    exit 1
}

# 11. 退出维护模式
rm -f /var/www/capp/storage/maintenance.flag

echo "=== 升级完成 ==="
```

### 11.2 数据库迁移方案

**迁移脚本规范：**
```php
<?php
// /scripts/migrate.php
// 数据库迁移脚本示例

$migrations = [
    '1.0.0' => 'migration_1_0_0.sql',
    '1.1.0' => 'migration_1_1_0.sql',
    '1.2.0' => 'migration_1_2_0.sql',
];

$currentVersion = getCurrentDbVersion();  // 从数据库读取当前版本
$targetVersion = getTargetVersion();      // 从配置文件读取目标版本

foreach ($migrations as $version => $file) {
    if (version_compare($version, $currentVersion, '>') && 
        version_compare($version, $targetVersion, '<=')) {
        echo "执行迁移: {$version} -> {$file}\n";
        executeSqlFile(__DIR__ . '/migrations/' . $file);
        updateDbVersion($version);
    }
}
```

**迁移脚本命名规范：**
- 格式：`migration_{版本号}.sql`
- 示例：`migration_1_1_0.sql`
- 内容要求：每个迁移脚本必须包含回滚语句（注释形式），便于问题排查

### 11.3 回滚策略

**自动回滚触发条件：**
- 升级后健康检查失败
- 关键业务流程测试失败
- 数据库迁移报错

**回滚脚本：**
```bash
#!/bin/bash
```

**回滚决策流程：**
1. 升级后15分钟内完成核心功能验证
2. 如发现问题，评估修复时间

4. 回滚完成后，在测试环境分析问题，修复后重新安排升级

### 12.3 访问控制策略

**应用层访问控制：**

   - 外部系统API调用需携带有效Token
   - Token有效期限制（建议2小时）
   - API调用频率限制（每分钟100次）
   - 敏感接口记录完整请求日志

**数据库访问控制：**
```sql
-- 删除匿名用户
DELETE FROM mysql.user WHERE User='';
```

### 12.4 漏洞修复机制

**漏洞管理流程：**

1. **漏洞发现渠道：**
   - 订阅PHP、MySQL、Nginx官方安全通告邮件列表
   - 关注CNVD、CVE漏洞库
   - 定期使用漏洞扫描工具（Nessus、OpenVAS）
   - 第三方安全渗透测试（每年至少一次）

2. **漏洞评估：**
   - 收到漏洞通告后，48小时内完成影响评估
   - 判断漏洞是否影响本系统（版本匹配、功能匹配）
   - 评估漏洞风险等级（CVSS评分）

3. **漏洞修复：**
   - 高危漏洞（CVSS >= 7.0）：7天内修复
   - 中危漏洞（CVSS 4.0-6.9）：30天内修复
   - 低危漏洞（CVSS < 4.0）：下次版本更新时修复

4. **修复验证：**
   - 在测试环境验证补丁兼容性
   - 生产环境修复后，验证业务功能正常
   - 重新扫描确认漏洞已修复

```bash
#!/bin/bash

```
