## 1. 概述

### 1.1 编写目的

本文档为工业压缩机、压力容器研发设计生产企业 CAPP（计算机辅助工艺规划）系统的外部系统对接设计说明书，旨在明确 CAPP 系统与 CAXA PLM、用友 U8 ERP、MES 等核心业务系统之间的数据交互方式、接口规范、同步策略及异常处理机制，确保各系统间数据流转的准确性、实时性与安全性，实现研发设计、工艺规划、生产制造、企业资源管理的全链路贯通。

### 1.2 适用范围

本文档适用于以下范围：

- CAPP 系统与 CAXA PLM 系统的产品数据、BOM 数据、工艺数据及图纸文件的双向同步对接；
- CAPP 系统与用友 U8 ERP 系统的物料主数据、BOM、库存、生产订单及成本数据的交互对接；
- CAPP 系统与 MES 系统的工艺路线下发、工序报工、质量数据及设备状态的实时交互对接；
- CAPP 系统统一对接网关、数据转换引擎、消息队列、监控告警及日志审计等通用对接框架的设计。

## 2. CAXA PLM 系统对接

### 2.1 CAXA PLM 系统简介

CAXA PLM 是北京数码大方科技股份有限公司（CAXA）推出的产品生命周期管理解决方案，广泛应用于机械装备制造行业。该系统涵盖图文档管理、产品数据管理（PDM）、零部件管理、BOM 管理、工艺管理、变更管理、项目管理等核心功能模块，支持 CAD 集成（CAXA CAD、AutoCAD、SolidWorks 等），具备完善的版本控制、权限管理、流程审批及电子签章机制。

在本企业应用场景中，CAXA PLM 作为研发设计数据的源头系统，管理工业压缩机、压力容器等产品的设计图纸、三维模型、技术参数、零部件信息、设计 BOM 及变更记录。CAPP 系统需与 CAXA PLM 实现深度集成，确保工艺规划所需的产品数据及时、准确、完整地同步至 CAPP 系统，同时将工艺规划结果（工艺路线、工艺卡片、工艺文件）回传至 PLM 系统，形成设计-工艺闭环管理。

### 2.2 对接目标与范围

#### 2.2.1 对接目标

1. **数据一致性**：确保 CAPP 系统与 CAXA PLM 系统之间的产品数据、BOM 数据、工艺数据及图纸文件保持一致，避免信息孤岛与数据冗余。
2. **流程贯通**：实现设计变更到工艺变更的自动触发与联动，缩短设计-工艺协同周期。
3. **文件共享**：实现图纸文件、工艺文件的双向传输与统一存储索引，支持在线浏览与版本追溯。
4. **效率提升**：通过自动化数据同步减少人工录入与核对工作量，降低差错率。

#### 2.2.2 对接范围

| 数据类别 | 数据内容 | 同步方向 | 说明 |
|---------|---------|---------|------|
| 产品数据 | 产品编码、产品名称、型号规格、技术参数、设计状态 | PLM → CAPP | 以 PLM 为产品主数据源 |
| BOM 数据 | 设计 BOM 结构、零部件关系、数量、版本 | PLM → CAPP | 支持 EBOM 到 PBOM 的转换基础 |
| 工艺数据 | 工艺路线、工序内容、工艺参数、工装设备、工时定额 | CAPP → PLM | 工艺规划结果回传 |
| 图纸文件 | 二维图纸（DWG/PDF）、三维模型、工艺卡片文件 | 双向 | 支持文件元数据同步与实体文件传输 |
| 变更数据 | 设计变更单、变更内容、变更影响范围 | PLM → CAPP | 变更通知与工艺联动 |
| 物料主数据 | 物料编码、物料名称、规格型号、材质、计量单位 | PLM → CAPP | 与 ERP 物料数据对齐 |

### 2.4 对接方式与技术方案

综合考虑 CAXA PLM 的技术架构、企业网络环境、数据安全要求及实施成本，CAPP 与 CAXA PLM 的对接采用 **"WebService API + 数据库中间表 + 文件 FTP/SFTP"** 的混合模式。

#### 2.4.1 WebService API 对接（主通道）

CAXA PLM 提供基于 SOAP 协议的 WebService 接口，CAPP 系统通过 PHP 的 `SoapClient` 扩展调用 PLM 标准服务，实现产品数据、BOM 数据、工艺数据的实时查询与写入。

**接口调用示例（PHP）**：

```php
// 初始化 SOAP 客户端
$client = new SoapClient(
    'http://plm-server/caxa/services/ProductService?wsdl',
    [
        'soap_version' => SOAP_1_2,
        'compression' => SOAP_COMPRESSION_ACCEPT | SOAP_COMPRESSION_GZIP,
        'connection_timeout' => 30,
        'login' => 'capp_user',
        'password' => 'encrypted_password',
        'trace' => true
    ]
);

// 调用获取产品信息方法
$params = [
    'productCode' => 'GM-2024-001',
    'version' => 'V1.0',
    'includeBOM' => true,
    'includeFiles' => true
];
$response = $client->GetProductDetail($params);
```

#### 2.4.2 数据库中间表对接（辅助通道）

对于大批量数据同步场景（如全量 BOM 同步、历史数据迁移），采用数据库中间表方式。在 PLM 数据库与 CAPP 数据库之间建立独立的中间库 `capp_plm_sync`，双方通过读写中间表实现数据交换，避免直接操作对方业务表。

**中间库架构**：

```
┌─────────────┐     ┌─────────────────────────┐     ┌─────────────┐
│  CAXA PLM   │     │    中间库 (capp_plm_sync)  │     │   CAPP      │
│   数据库     │────►│  plm_product_sync_out   │────►│   数据库     │
│             │     │  plm_bom_sync_out       │     │             │
│             │◄────│  plm_process_sync_in    │◄────│             │
│             │     │  plm_file_sync_out      │     │             │
│             │◄────│  plm_file_sync_in       │◄────│             │
└─────────────┘     └─────────────────────────┘     └─────────────┘
```

#### 2.4.3 文件传输（FTP/SFTP）

图纸文件、工艺文件等二进制大对象（BLOB）通过 SFTP 协议传输。PLM 系统在完成文件归档后，将文件推送至企业文件服务器（SFTP Server）指定目录，CAPP 系统通过定时任务扫描目录并下载文件，同时更新文件元数据。反向传输时，CAPP 将工艺文件上传至 SFTP 目录，PLM 系统接收并入库。

**SFTP 传输配置**：

| 配置项 | 值 | 说明 |
|-------|-----|------|
| 服务器地址 | 203.0.113.10 | 企业文件服务器内网地址 |
| 端口 | 22 | SFTP 默认端口 |
| 认证方式 | 密钥 + 密码双因素 | 提升安全性 |
| CAPP 下载目录 | /data/sync/plm_to_capp/ | PLM → CAPP 文件目录 |
| CAPP 上传目录 | /data/sync/capp_to_plm/ | CAPP → PLM 文件目录 |
| 扫描间隔 | 5 分钟 | 定时任务扫描频率 |
| 文件保留策略 | 同步成功后保留 7 天 | 防止磁盘空间无限增长 |

### 2.5 同步策略

#### 2.5.1 实时同步

适用于对时效性要求高的数据同步场景：

- **设计变更触发**：PLM 系统中设计变更单审批通过后，通过 WebService 主动推送变更事件至 CAPP 系统，CAPP 接收后自动触发工艺影响分析。
- **工艺审批回传**：CAPP 系统中工艺文件审批完成后，实时调用 PLM API 回传工艺数据及文件。

#### 2.5.2 定时同步

适用于大批量、周期性数据同步场景：

| 同步任务 | 频率 | 数据范围 | 同步方向 |
|---------|------|---------|---------|
| 产品主数据同步 | 每 30 分钟 | 新增/修改的产品 | PLM → CAPP |
| BOM 数据同步 | 每 30 分钟 | 新增/修改的 BOM | PLM → CAPP |
| 物料主数据同步 | 每 60 分钟 | 新增/修改的物料 | PLM → CAPP |
| 图纸文件元数据同步 | 每 15 分钟 | 新增/修改的文件记录 | PLM → CAPP |
| 工艺数据回传 | 每 60 分钟 | 已审批的工艺 | CAPP → PLM |

#### 2.5.3 手动同步

提供管理后台手动触发功能，适用于：

- 系统初始化时的历史数据全量同步；
- 定时同步失败后的手动补偿；
- 特定产品/项目的强制刷新同步。

#### 2.5.4 增量同步

所有定时同步任务均采用增量同步机制，通过时间戳（`last_sync_time`）或变更标识（`is_synced`、`sync_version`）识别新增与变更数据，避免全量扫描带来的性能开销。

**增量识别规则**：

```sql
-- PLM 侧查询增量数据示例
SELECT * FROM plm_product 
WHERE update_time > '2024-01-01 12:00:00' 
   OR (is_synced = 0 AND create_time > '2024-01-01 00:00:00');
```

### 2.7 冲突处理机制

#### 2.7.1 冲突类型定义

| 冲突类型 | 说明 | 示例 |
|---------|------|------|
| 数据版本冲突 | 同一数据在双方系统均发生变更 | PLM 与 CAPP 同时修改了某产品的技术参数 |
| 主键重复冲突 | 同步数据的主键在目标系统已存在 | 同步的产品编码在 CAPP 中已存在 |
| 外键依赖冲突 | 同步数据依赖的关联数据不存在 | BOM 同步时父件或子件产品尚未同步 |
| 业务规则冲突 | 数据违反目标系统业务规则 | 同步的工时定额超出系统允许范围 |
| 文件冲突 | 同名文件内容不一致 | 图纸文件版本相同但 MD5 不一致 |

#### 2.7.2 冲突解决策略

| 策略 | 适用场景 | 处理方式 |
|------|---------|---------|
| PLM 优先 | 产品数据、BOM 数据、图纸文件 | 以 PLM 数据为准，覆盖 CAPP 本地数据 |
| CAPP 优先 | 工艺数据、工时定额 | 以 CAPP 数据为准，回传 PLM 时覆盖 |
| 人工裁决 | 重大版本冲突、业务规则冲突 | 标记冲突状态，推送消息至工艺员/设计员人工处理 |
| 合并策略 | 非互斥字段冲突 | 自动合并双方变更，保留最新值 |
| 忽略策略 | 低优先级字段冲突 | 记录日志但不阻断同步流程 |

### 2.8 对接安全设计

#### 2.8.1 传输安全

- **协议加密**：WebService API 调用强制使用 HTTPS（TLS 1.2+），SFTP 文件传输使用 SSH2 加密通道；
- **数据加密**：敏感字段（如技术参数中的压力/温度设计值）在传输前使用 AES-256 加密，密钥通过独立的安全通道分发；
- **签名验证**：API 请求参数按字典序排序后拼接，附加时间戳与随机数，使用 HMAC-SHA256 签名，服务端校验签名有效性防止请求篡改与重放攻击。

#### 2.8.2 访问控制

- **账号隔离**：CAPP 系统使用独立的 PLM 服务账号（`capp_sync`），权限仅限于数据查询与工艺数据写入，禁止操作 PLM 核心流程；
- **IP 白名单**：PLM 服务器防火墙配置仅允许 CAPP 应用服务器 IP 访问同步接口；
- **Token 机制**：API 调用前需获取临时 Token（有效期 30 分钟），Token 与客户端 IP 绑定，异常登录触发告警。

#### 2.8.3 数据安全

- **中间库隔离**：同步中间库独立部署，与 PLM 业务库、CAPP 业务库物理或逻辑隔离；
- **敏感数据脱敏**：非生产环境同步时，客户名称、合同金额等敏感字段自动脱敏；
- **审计追踪**：所有同步操作记录完整审计日志，包括操作人、操作时间、数据变更前后值、客户端 IP 等，日志保留期限不少于 3 年。

## 3. 用友 U8 ERP 系统对接

### 3.1 U8 系统简介

用友 U8+ 是用友网络科技股份有限公司面向成长型企业推出的 ERP 管理软件，涵盖财务管理、供应链管理、生产制造管理、人力资源管理、客户关系管理等核心模块。在本企业应用场景中，用友 U8 主要承担企业资源计划与运营管理职能，包括物料主数据管理、采购管理、销售管理、库存管理、生产订单管理、成本核算等。

CAPP 系统与用友 U8 的对接，旨在打通工艺规划与生产运营之间的数据壁垒，实现物料主数据与 BOM 的统一管理、生产订单的闭环跟踪以及成本数据的精准回传，为企业经营决策提供完整的数据支撑。

### 3.2 对接目标与范围

#### 3.2.1 对接目标

1. **物料主数据统一**：以 U8 为物料主数据权威源，CAPP 系统实时同步物料编码、名称、规格、材质、计量单位等基础数据，确保工艺规划引用物料的准确性。
2. **BOM 数据贯通**：CAPP 系统将工艺 BOM（PBOM）及工艺路线信息下发至 U8，支撑生产订单的物料需求计划与成本核算。
3. **生产订单协同**：U8 生产订单下达后同步至 CAPP，CAPP 基于订单要求调整工艺方案，实现按单工艺。
4. **成本数据回传**：CAPP 系统将工序成本、工时成本、材料定额等数据回传 U8，支撑精细化成本核算。

### 3.4 对接方式与技术方案

用友 U8 提供多种系统对接方式，本方案根据数据类型与实时性要求，采用 **"U8 OpenAPI + U8 EAI + 数据库中间库"** 的组合方案。

#### 3.4.1 U8 OpenAPI（推荐方式）

用友 U8 12.0 及以上版本提供 OpenAPI 平台，基于 RESTful 接口规范，支持 JSON 数据格式，涵盖物料、BOM、生产订单、库存等核心业务的增删改查操作。

**OpenAPI 调用特点**：

- 支持 OAuth 2.0 认证，Token 有效期 2 小时；
- 接口限流：默认 1000 次/分钟；
- 支持批量操作，单次最大 500 条记录；
- 返回统一格式：`{ "code": 0, "message": "success", "data": {} }`。

**PHP 调用示例**：

```php
class U8OpenApiClient {
    private $baseUrl = 'http://u8-server/api/';
    private $appKey = 'CAPP_SYNC_KEY';
    private $appSecret = 'YOUR_SECRET';
    private $token;

    public function getToken() {
        $url = $this->baseUrl . 'auth/getToken';
        $params = [
            'appKey' => $this->appKey,
            'appSecret' => $this->appSecret,
            'grantType' => 'client_credentials'
        ];
        $response = $this->httpPost($url, $params);
        $this->token = YOUR_SECRET'access_token'];
        return $this->token;
    }

    public function syncMaterial($materialData) {
        $url = $this->baseUrl . 'inventory/batchAdd';
        $headers = ['Authorization: Bearer ' . $this->token];
        return $this->httpPost($url, $materialData, $headers);
    }
}
```

#### 3.4.2 U8 EAI（企业应用集成）

对于 U8 早期版本或 OpenAPI 未覆盖的业务场景，使用 U8 EAI 工具进行数据交换。EAI 支持 XML/JSON 格式的数据导入导出，通过配置映射规则实现异构系统间的数据转换。

**EAI 适用场景**：

- 生产订单状态回写；
- 成本数据批量导入；
- 历史数据迁移。

#### 3.4.3 数据库中间库

与 PLM 对接类似，建立独立的中间库 `capp_u8_sync`，双方通过读写中间表交换数据。此方式适用于大批量、定时同步场景，降低对 U8 业务库的直接影响。

### 3.6 业务场景详细设计

#### 3.6.1 物料同步场景

**业务流程**：

1. U8 系统中新增或修改物料档案（存货档案）；
2. U8 触发数据变更事件，将变更数据写入中间表 `u8_inventory_sync_out`；
3. CAPP 定时任务（每 60 分钟）扫描中间表；
4. CAPP 读取待同步物料数据，进行字段映射与数据校验；
5. 校验通过后写入 CAPP 物料基础表 `base_material`；
6. 更新中间表状态为已同步，记录同步日志。

**特殊处理**：

- **编码映射**：U8 物料编码规则与 CAPP 可能存在差异，通过 `ext_code_mapping` 表维护编码对照关系；
- **分类映射**：U8 存货分类与 CAPP 物料类别映射，支持多级分类转换；
- **计量单位**：U8 计量单位编码与 CAPP 单位字典映射，不存在时自动创建单位记录。

#### 3.6.2 BOM 下发场景

**业务流程**：

1. CAPP 系统中完成工艺 BOM（PBOM）编制与审批；
2. 工艺员在 CAPP 中点击 "下发至 ERP" 按钮，触发 BOM 下发流程；
3. CAPP 组装 BOM 数据包（母件 + 子件 + 工序 + 用量）；
4. 调用 U8 OpenAPI `bom/batchAdd` 接口写入 U8；
5. U8 返回写入结果，CAPP 记录下发状态；
6. 若失败，进入重试队列，最多重试 3 次，仍失败则推送告警通知。

**BOM 版本控制**：

- CAPP 下发 BOM 时携带版本号，U8 中同一母件支持多版本 BOM；
- 生效日期/失效日期由 CAPP 根据生产计划自动计算；
- 替代料关系在 CAPP 中维护，随 BOM 一并下发。

#### 3.6.3 生产订单接收场景

**业务流程**：

1. U8 销售管理模块生成销售订单，或计划部门直接下达生产订单；
2. U8 生产订单保存/审核后，通过 OpenAPI 或中间库将订单数据推送至 CAPP；
3. CAPP 接收订单数据，创建 "生产订单工艺任务"；
4. 工艺员在 CAPP 中查看订单的工艺要求（如特殊材质、压力等级、交期要求）；
5. CAPP 基于标准工艺库生成订单工艺方案，支持工艺调整与优化；
6. 工艺方案审批后下发至 MES 系统执行。

#### 3.6.4 成本回传场景

**业务流程**：

1. CAPP 系统中维护工序标准成本（人工费率、设备费率、材料定额）；
2. 每日 23:00，CAPP 汇总当日完工工艺的实动工时、实际材料消耗；
3. 计算工序实际成本与标准成本差异；
4. 通过 EAI 或中间库将成本数据写入 U8 成本管理模块；
5. U8 成本会计基于回传数据进行成本卷积与差异分析。

**回传数据内容**：

| 数据项 | 说明 |
|-------|------|
| 产品编码 | 成本对象 |
| 生产订单号 | 成本归集对象 |
| 工序编码 | 成本中心 |
| 标准工时 | 定额工时 |
| 实动工时 | 实际消耗工时 |
| 标准材料成本 | 定额材料成本 |
| 实际材料成本 | 实际领料成本 |
| 人工成本 | 人工费率 × 实动工时 |
| 制造费用 | 设备费率 × 实动机时 |

### 3.8 异常处理与补偿机制

#### 3.8.1 异常分类

| 异常级别 | 异常类型 | 示例 | 处理策略 |
|---------|---------|------|---------|
| 致命 | 网络中断、服务宕机 | U8 服务器无法连接 | 立即告警，暂停同步，人工排查 |
| 严重 | 认证失败、权限不足 | Token 过期、账号锁定 | 自动刷新 Token，失败则告警 |
| 一般 | 数据校验失败 | 物料编码为空、数量非法 | 记录失败明细，跳过该条继续同步 |
| 轻微 | 重复同步、无变更 | 数据已是最新状态 | 记录日志，标记成功 |

#### 3.8.2 补偿机制

1. **失败重试**：同步失败自动进入重试队列，按指数退避策略（间隔 1 分钟、5 分钟、15 分钟）重试，最多 3 次；
2. **断点续传**：大批量同步支持断点续传，记录已同步位置，中断后从断点继续；
3. **反向补偿**：U8 数据回滚时，CAPP 接收回滚通知，同步作废已同步数据；
4. **对账机制**：每日凌晨 02:00 执行对账任务，比对双方关键表的数据量与关键字段哈希值，发现差异自动补偿。

## 4. MES 系统对接

### 4.1 MES 系统简介

MES（Manufacturing Execution System，制造执行系统）是面向制造企业车间执行层的生产信息化管理系统，位于上层计划管理系统（ERP）与底层工业控制（PLC/SCADA）之间，起到承上启下的作用。本企业采用的 MES 系统覆盖生产调度、工单管理、工序报工、质量管理、设备管理、物料追溯等核心功能，实现工业压缩机、压力容器生产过程的数字化管控。

CAPP 系统与 MES 的对接，是连接工艺规划与生产执行的关键桥梁，确保工艺路线、工序参数、质量要求准确无误地下达至生产现场，同时实时接收生产执行反馈，形成工艺-制造闭环。

### 4.2 对接目标与范围

#### 4.2.1 对接目标

1. **工艺路线下发**：CAPP 编制的工艺路线、工序卡片、作业指导书实时下发至 MES，指导现场生产；
2. **工单协同**：MES 基于 ERP 生产订单生成的工单信息同步至 CAPP，CAPP 可按工单调整工艺参数；
3. **报工数据回传**：MES 采集的工序开工、完工、合格、报废数量及实动工时实时回传 CAPP；
4. **质量追溯**：MES 采集的工序检验数据（尺寸、压力、探伤结果等）回传 CAPP，支撑质量追溯与分析；
5. **设备联动**：MES 设备状态数据（运行、停机、故障）辅助 CAPP 优化工艺参数与设备选择。

#### 4.2.2 对接范围

### 4.4 对接方式与技术方案

MES 系统通常具备较强的实时性与开放性，本方案采用 **"REST API + 消息队列（RabbitMQ）+ 数据库中间表"** 的多通道混合架构，满足不同场景的数据交互需求。

| /api/mes/wo/feedback | POST | MES 上报工单执行反馈 |
| /api/mes/quality/report | POST | MES 上报质量检验数据 |
| /api/mes/device/status | POST | MES 上报设备状态 |

### 4.6 业务场景详细设计

#### 4.6.1 工艺下发场景

**业务流程**：

1. CAPP 系统中完成工艺路线编制与审批；
2. 工艺审批通过后，自动触发 "工艺下发 MES" 流程；
3. CAPP 将工艺数据写入消息队列 `queue.capp.process`；
4. MES 消费消息，解析工艺数据；
5. MES 校验工艺数据（产品编码是否存在、工序编码是否合法、设备是否存在）；
6. MES 将工艺路线写入工单工艺表，关联至对应工单；
7. MES 返回确认消息至 CAPP；
8. CAPP 更新工艺下发状态为 "已下发"。

**异常处理**：

- MES 消费消息失败时，消息队列自动重试（最多 5 次），超过阈值进入死信队列；
- CAPP 监听死信队列，推送告警通知工艺员人工处理；
- 工艺员可在 CAPP 中查看下发失败原因，修正后重新下发。

#### 4.6.2 工单接收场景

**业务流程**：

1. U8 ERP 下达生产订单至 MES；
2. MES 基于生产订单生成车间工单（WO）；
3. MES 调用 CAPP API `/api/capp/wo/feedback` 推送工单信息；
4. CAPP 接收工单，创建 "工单工艺任务"；
5. CAPP 自动匹配标准工艺路线，生成工单工艺方案；
6. 若产品存在特殊工艺要求（如高压测试、特殊材质），CAPP 提示工艺员确认或调整；
7. 工艺方案确认后，CAPP 将工艺路线下发至 MES。

#### 4.6.3 报工数据回传场景

**业务流程**：

1. 车间操作工在 MES 终端完成某工序加工，提交报工；
2. MES 校验报工数据（数量逻辑、工时合理性）；
3. MES 将报工消息推送至 RabbitMQ `queue.mes.report`；
4. CAPP 消费消息，解析报工数据；
5. CAPP 写入工序报工表 `mes_operation_report`；
6. CAPP 更新工单进度、累计工时；
7. CAPP 触发工时差异分析（实动工时 vs 标准工时），差异超阈值时推送预警；
8. CAPP 将报工数据汇总后，定时回传 U8 ERP 成本模块。

#### 4.6.4 质量追溯场景

**业务流程**：

1. MES 工序检验员完成检验，在 MES 中录入检验数据；
2. MES 将质量消息推送至 RabbitMQ `queue.mes.quality`；
3. CAPP 消费消息，解析质量数据；
4. CAPP 写入质量检验表 `mes_quality_record`；
5. CAPP 关联至对应工序、工单、产品；
6. 若检验不合格，CAPP 自动触发质量异常流程：
   - 推送不合格告警至质量工程师；
   - 记录不合格原因、处置方式（返工/返修/报废/让步接收）；
   - 更新工艺质量统计报表；
7. 质量数据长期归档，支撑产品全生命周期质量追溯。

### 4.8 实时数据交互设计

#### 4.8.1 消息队列高可用架构

```
┌─────────────┐         ┌─────────────────────────┐         ┌─────────────┐
│    MES      │────────►│    RabbitMQ Cluster     │◄────────│    CAPP     │
│  生产者      │  报工    │  (镜像队列，3节点集群)    │  工艺下发  │   消费者     │
│             │  质量    │                         │          │             │
│             │  设备    │  ┌─────────────────┐    │          │             │
└─────────────┘         │  │  queue.mes.*    │    │          └─────────────┘
                        │  │  queue.capp.*   │    │
                        │  │  DLX (死信交换机)│   │
                        │  └─────────────────┘    │
                        └─────────────────────────┘
```

**RabbitMQ 配置要点**：

- 采用镜像队列（Mirrored Queue）实现高可用，队列在集群所有节点同步复制；
- 生产者开启消息持久化（`delivery_mode = 2`），确保消息不丢失；
- 消费者采用手动 ACK 模式，处理完成后确认，失败则消息重新入队；
- 配置死信交换机（DLX），超过重试次数的消息转入死信队列，人工处理；
- 队列设置 TTL 与最大长度限制，防止内存溢出。

#### 4.8.2 WebSocket 实时推送（可选增强）

对于需要前端实时展示的场景（如车间看板、工艺监控大屏），CAPP 后端可集成 WebSocket 服务，将 MES 实时数据推送至浏览器端。

**WebSocket 推送场景**：

- 关键工序完工实时推送；
- 质量不合格实时告警；
- 设备故障实时通知；
- 工单进度实时更新。

**PHP WebSocket 实现方案**：

采用 Swoole 或 Workerman 扩展构建 WebSocket 服务器，与 RabbitMQ 消费者集成，接收消息后广播至对应客户端。

```php

    $connection->send(json_encode([
        'type' => 'quality_alert',
        'data' => $data
    ]));
};
Worker::runAll();
```

## 5. 通用对接框架

### 5.1 统一对接网关设计

为降低多系统对接的复杂度、实现对接能力的复用与统一管理，CAPP 系统构建统一的对外对接网关（Integration Gateway）。

#### 5.1.1 网关架构

│  │  协议适配层  │  │  认证授权层  │  │  路由转发层  │           │
│  │  HTTP/HTTPS │  │  OAuth2.0   │  │  PLM路由    │           │
│  │  SOAP       │  │  HMAC签名   │  │  ERP路由    │           │
│  │  REST       │  │  IP白名单   │  │  MES路由    │           │
│  │  MQ Consumer│  │  限流熔断   │  │  自定义路由  │           │
│  └─────────────┘  └─────────────┘  └─────────────┘           │
│  ┌─────────────┐  ┌─────────────┐  ┌─────────────┐           │

#### 5.1.2 网关核心功能

| 功能模块 | 说明 |
|---------|------|
| 协议适配 | 统一封装 HTTP/HTTPS、SOAP、REST、消息队列等多种协议的调用细节，业务代码只需关注数据逻辑 |
| 认证授权 | 集成 OAuth 2.0、HMAC-SHA256 签名、API Key 等多种认证方式，支持按系统配置 |
| 路由转发 | 根据请求目标系统编码自动路由至对应后端服务，支持负载均衡与故障转移 |
| 限流熔断 | 基于令牌桶算法实现接口限流，异常率超过阈值时自动熔断并触发降级策略 |
| 数据转换 | 调用数据转换引擎完成字段映射、格式转换、编码转换 |
| 日志审计 | 记录所有经过网关的请求与响应，支持按系统、按时间、按状态检索 |
| 监控告警 | 实时采集接口调用指标（QPS、延迟、错误率），异常时推送告警 |

#### 5.1.3 PHP 网关核心类设计

```php
class IntegrationGateway {
    private $config;
    private $httpClient;
    private $transformEngine;
    private $logger;
    private $monitor;

    public function __construct(IntegrationConfig $config) {
        $this->config = $config;
        $this->httpClient = new HttpClient();
        $this->transformEngine = new DataTransformEngine();
        $this->logger = new SyncLogger();
        $this->monitor = new MonitorCollector();
    }

    /**
     * 统一发送请求
     */
    public function send(string $systemCode, string $apiCode, array $data): GatewayResponse {
        $startTime = microtime(true);
        $systemConfig = $this->config->getSystemConfig($systemCode);
        
        try {
            // 1. 数据转换
            $transformedData = $this->transformEngine->transform(
                $data, 
                $systemConfig->getMappingId()
            );
            
            // 2. 构建请求
            $request = $this->buildRequest($systemConfig, $apiCode, $transformedData);
            
            // 3. 认证签名
            $request = $this->authenticate($systemConfig, $request);
            
            // 4. 限流检查
            $this->checkRateLimit($systemCode, $apiCode);
            
            // 5. 发送请求
            $response = $this->httpClient->send($request);
            
            // 6. 响应转换
            $result = $this->transformEngine->reverseTransform(
                $response->getBody(),
                $systemConfig->getMappingId()
            );
            
            // 7. 记录日志与监控
            $this->logSuccess($systemCode, $apiCode, $request, $response, $startTime);
            
            return new GatewayResponse(true, $result);
            
        } catch (Exception $e) {
            $this->logFailure($systemCode, $apiCode, $request ?? null, $e, $startTime);
            $this->monitor->recordError($systemCode, $apiCode, $e);
            throw $e;
        }
    }
}
```

### 5.2 数据转换引擎

数据转换引擎负责解决异构系统间的数据格式差异、字段命名差异、编码差异、业务语义差异。

#### 5.2.1 引擎架构

```
[源数据] ──► [输入解析器] ──► [数据清洗] ──► [字段映射] ──► [类型转换] ──► [业务规则] ──► [输出组装] ──► [目标数据]
              (JSON/XML/    (去空/trim/    (字段名/      (字符串/        (字典映射/      (JSON/XML/
               CSV/数组)     默认值)        字段值映射)    数值/日期)      公式计算)       数组)
```

#### 5.2.2 转换规则配置

转换规则通过数据库配置表 `ext_data_mapping` 维护，支持可视化配置与热更新，无需重启服务。

**规则类型**：

| 规则类型 | 说明 | 示例 |
|---------|------|------|
| 字段映射 | 源字段与目标字段的对应关系 | `cInvCode` → `material_code` |
| 类型转换 | 数据类型的转换规则 | 字符串 "123" → 整数 123 |
| 字典映射 | 枚举值的转换规则 | U8 "自制" → CAPP 0 |
| 格式转换 | 日期/数值/字符串的格式化 | `2024/06/07` → `2024-06-07` |
| 公式计算 | 基于多字段的计算规则 | `amount = price * quantity` |
| 条件分支 | 基于条件选择不同转换逻辑 | 若 `type=1` 则映射 A，否则映射 B |
| 自定义脚本 | PHP 代码片段实现复杂转换 | 自定义函数处理特殊逻辑 |

#### 5.2.3 转换引擎执行流程

```php
class DataTransformEngine {
    public function transform(array $sourceData, int $mappingId): array {
        $rules = $this->loadRules($mappingId);
        $result = [];
        
        foreach ($rules as $rule) {
            $sourceValue = $this->getValue($sourceData, $rule['source_field']);
            
            // 数据清洗
            $sourceValue = $this->clean($sourceValue, $rule['clean_rules']);
            
            // 类型转换
            $targetValue = $this->convertType($sourceValue, $rule['data_type']);
            
            // 字典映射
            if (isset($rule['mapping_dict'])) {
                $targetValue = $rule['mapping_dict'][$targetValue] ?? $targetValue;
            }
            
            // 公式计算
            if (isset($rule['formula'])) {
                $targetValue = $this->calculate($rule['formula'], $sourceData);
            }
            
            // 自定义脚本
            if (isset($rule['script'])) {
                $targetValue = $this->executeScript($rule['script'], $sourceValue, $sourceData);
            }
            
            // 默认值
            if ($targetValue === null && isset($rule['default_value'])) {
                $targetValue = $rule['default_value'];
            }
            
            $this->setValue($result, $rule['target_field'], $targetValue);
        }
        
        return $result;
    }
}
```

#### 5.3.3 消息可靠性保障

1. **生产者确认**：开启 Publisher Confirm 机制，消息成功写入队列后返回 ACK；
2. **消费者确认**：采用手动 ACK，业务处理成功后发送确认，失败则消息重新入队；
3. **消息持久化**：交换机、队列、消息均标记为持久化（`durable = true`）；
4. **集群部署**：3 节点 RabbitMQ 集群，镜像队列策略为 `ha-mode: all`；
5. **死信处理**：配置死信交换机与死信队列，消费失败超过 5 次的消息转入死信队列，人工处理；
6. **消息追踪**：开启 RabbitMQ Tracing 插件，记录消息流转轨迹。

## 6. 安全与性能保障

### 6.1 传输安全

1. **全链路加密**：所有外部系统对接接口强制使用 HTTPS（TLS 1.2+），SFTP 使用 SSH2 加密，禁止明文 HTTP/FTP 传输；
2. **证书管理**：建立企业级证书管理体系，定期更新 SSL 证书，过期前 30 天自动预警；
3. **VPN/专线**：对于跨厂区、跨地域的系统对接，优先采用 MPLS 专线或 IPSec VPN，确保网络层安全隔离；
4. **敏感数据加密**：技术参数、成本数据、客户信息等敏感字段在传输前使用 AES-256-GCM 加密，密钥通过 KMS（密钥管理系统）统一管理。

### 6.2 访问控制

1. **最小权限原则**：CAPP 系统在各外部系统中使用独立服务账号，权限严格限制为业务所需的最小集合；
2. **多因素认证**：关键系统对接账号启用多因素认证（密码 + 动态令牌/证书）；
3. **IP 白名单**：外部系统服务端配置 CAPP 应用服务器 IP 白名单，拒绝非授权来源请求；
4. **Token 生命周期**：API 访问 Token 设置合理有效期（15-30 分钟），支持自动刷新与强制失效；
5. **操作审计**：所有账号登录、Token 申请、权限变更操作记录完整审计日志。

### 6.3 性能优化

1. **连接池管理**：PHP 使用持久化 HTTP 连接（HTTP Keep-Alive）或连接池，减少 TCP 握手开销；
2. **批量操作**：大批量数据同步采用批量接口，单次提交 100-500 条记录，减少接口调用次数；
3. **异步处理**：非实时性要求的数据同步采用异步队列处理，避免阻塞用户操作；
4. **数据压缩**：API 请求/响应启用 Gzip 压缩，减少网络传输量；
5. **缓存策略**：热点数据（物料主数据、标准工艺）使用 Redis 缓存，减少重复查询；
6. **数据库优化**：同步中间表建立合理索引，定期归档历史数据，分区表存储大容量同步日志；
7. **限流降级**：接口调用频率超过阈值时自动限流，外部系统故障时启用降级策略（返回缓存数据或延迟处理）。
