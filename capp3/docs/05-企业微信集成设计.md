## 1. 概述

### 1.1 设计目标

本文档旨在为CAPP（计算机辅助工艺规划）系统与企业微信的深度集成提供完整的技术设计方案。通过企业微信集成，实现以下核心目标：

- **统一身份认证**：利用企业微信扫码登录，简化用户登录流程，实现单点登录体验。
- **组织架构同步**：自动同步企业微信通讯录中的部门与人员信息，确保CAPP系统用户数据与企业微信保持一致。
- **即时消息触达**：通过企业微信消息推送能力，将审批通知、任务提醒、系统公告等信息实时推送给相关人员。
- **移动办公能力**：借助企业微信JS-SDK，在移动端实现扫码、拍照、定位等原生能力，提升现场作业效率。
- **审批流程打通**：将CAPP系统内的工艺审批流程与企业微信审批应用对接，实现审批流程的移动化与统一化。

### 1.2 适用范围

本设计适用于工业压缩机、压力容器研发设计生产企业的CAPP系统，覆盖工艺设计、工艺审批、生产排产、质量检验等业务场景的企业微信集成需求。

### 1.3 技术约束

- **后端技术**：PHP原生开发，不依赖任何框架。
- **数据库**：MySQL 5.7+。
- **企业微信版本**：企业微信API版本基于企业微信官方最新开放接口规范。
- **部署环境**：支持内网部署及公网可访问的回调地址配置。

### 1.4 术语定义

| 术语 | 说明 |
|------|------|
| CorpID | 企业微信唯一标识，每个企业拥有一个固定的CorpID |
| AgentID | 自建应用的唯一标识 |
| Secret | 应用的密钥，用于获取access_token |
| access_token | 调用企业微信API的凭证，有效期2小时 |
| jsapi_ticket | 调用JS-SDK的临时票据，有效期2小时 |
| OAuth2.0 | 开放授权协议，用于用户身份验证 |
| UserID | 企业微信成员唯一标识，对应CAPP系统用户账号 |

## 2. 企业微信扫码登录流程

### 2.1 整体流程架构

企业微信扫码登录采用OAuth2.0授权码模式，整体流程分为三个阶段：

1. **前端引导阶段**：用户访问CAPP系统登录页，选择"企业微信扫码登录"，前端加载企业微信扫码SDK并展示二维码。
2. **授权回调阶段**：用户使用手机企业微信扫描二维码并确认授权后，企业微信服务器将授权码（code）回调至CAPP系统预设的回调地址。
3. **身份验证阶段**：CAPP系统后端使用授权码换取用户身份信息，完成登录态创建并跳转至系统首页。

### 2.2 详细时序设计

```
[用户] → [CAPP前端登录页] → [企业微信扫码SDK] → [企业微信服务器]
                                              ↓
[用户手机企业微信] ← 展示二维码 ← 获取扫码登录URL
       ↓
  扫码并确认授权
       ↓
[企业微信服务器] → 携带code回调 → [CAPP后端回调接口]
       ↓
[CAPP后端] → 使用code+access_token → [企业微信API]
       ↓
[企业微信API] → 返回UserID → [CAPP后端]
       ↓
[CAPP后端] → 查询本地用户映射表 → 创建Session → 跳转首页
```

### 2.3 接口详细设计

#### 2.3.1 获取扫码登录URL

**接口路径**：`GET /api/wechat/auth/qrcode_url`

**处理逻辑**：

1. 后端生成唯一状态标识`state`（UUID格式），存入Redis/Session，有效期5分钟，用于防止CSRF攻击。
2. 按照企业微信扫码登录URL规范拼接参数：
   - `appid`：企业微信CorpID
   - `agentid`：自建应用AgentID
   - `redirect_uri`：URL编码后的回调地址（如`https://capp.company.com/api/wechat/auth/callback`）
   - `state`：上述生成的状态标识
3. 返回完整URL给前端。

**PHP实现示例**：

```php
function getQrCodeUrl() {
    $corpId = WECHAT_CORP_ID;
    $agentId = WECHAT_AGENT_ID;
    $redirectUri = urlencode('https://' . $_SERVER['HTTP_HOST'] . '/api/wechat/auth/callback');
    $state = bin2hex(random_bytes(16));
    
    // 将state存入缓存，有效期300秒
    $redis = getRedisInstance();
    $redis->setex('wechat:auth:state:' . $state, 300, '1');
    
    $url = "https://open.work.weixin.qq.com/wwopen/sso/qrConnect?appid={$corpId}&agentid={$agentId}&redirect_uri={$redirectUri}&state={$state}";
    return ['url' => $url, 'state' => $state];
}
```

#### 2.3.2 授权回调处理

**接口路径**：`GET /api/wechat/auth/callback`

**请求参数**：

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| code | string | 是 | 授权码，有效期5分钟，一次性使用 |
| state | string | 是 | 原样返回的状态标识 |

**处理逻辑**：

1. **状态校验**：验证`state`是否存在于缓存中且未过期，验证通过后立即删除该`state`记录，防止重放攻击。
2. **获取access_token**：调用企业微信`gettoken`接口，使用CorpID和Secret获取应用级access_token。
3. **获取用户信息**：调用`user/getuserinfo`接口，传入access_token和code，获取用户UserID。
4. **本地用户映射**：根据UserID查询`wechat_user_mapping`表，获取对应的CAPP系统用户ID（uid）。
5. **用户绑定判断**：
   - 若存在映射关系且用户状态正常，直接创建登录Session。
   - 若不存在映射关系，跳转至账号绑定页面，引导用户输入CAPP系统账号密码完成绑定。
   - 若用户状态禁用，返回错误提示。
6. **Session创建**：生成CAPP系统登录Token（JWT或自定义Token），写入Session表，设置Cookie/LocalStorage。
7. **登录日志记录**：记录登录时间、IP地址、登录方式（企业微信扫码）至`login_log`表。
8. **跳转首页**：重定向至CAPP系统首页，携带登录Token。

**PHP实现示例**：

```php
function authCallback($code, $state) {
    // 1. 校验state
    $redis = getRedisInstance();
    $stateKey = 'wechat:auth:state:' . $state;
    if (!$redis->exists($stateKey)) {
        throw new Exception('STATE验证失败或已过期', 400);
    }
    $redis->del($stateKey);
    
    // 2. 获取access_token
    $accessToken = YOUR_SECRET);
    
    // 3. 使用code获取UserID
    $url = "https://qyapi.weixin.qq.com/cgi-bin/user/getuserinfo?access_token=YOUR_SECRET}&code={$code}";
    $response = httpGet($url);
    $data = json_decode($response, true);
    
    if (isset($data['errcode']) && $data['errcode'] != 0) {
        throw new Exception("企业微信接口错误: {$data['errmsg']}", 500);
    }
    
    $userId = $data['UserId'] ?? null;
    if (!$userId) {
        throw new Exception('无法获取用户标识', 500);
    }
    
    // 4. 查询本地映射
    $db = getDbInstance();
    $mapping = $db->query("SELECT * FROM wechat_user_mapping WHERE wechat_user_id = ? AND status = 1", [$userId]);
    
    if (empty($mapping)) {
        // 未绑定，跳转绑定页
        header('Location: /bind.html?wechat_id=' . urlencode($userId));
        exit;
    }
    
    // 5. 创建Session并登录
    $uid = $mapping[0]['uid'];
    $token = YOUR_SECRET, 'wechat_qr');
    header('Location: /index.html?token=' . $token);
    exit;
}
```

### 2.4 账号绑定流程

对于首次使用企业微信扫码登录且未绑定CAPP账号的用户，系统提供账号绑定机制：

1. **绑定页面**：用户扫码后被引导至`/bind.html`页面，页面显示企业微信头像和姓名，下方要求输入CAPP系统账号和密码。
2. **身份验证**：后端验证CAPP账号密码正确性。
3. **建立映射**：在`wechat_user_mapping`表中插入记录，关联CAPP用户ID与企业微信UserID。
4. **完成登录**：绑定成功后自动创建Session并跳转首页。
5. **管理员强制绑定**：管理员可在后台直接为CAPP用户配置企业微信UserID，无需用户自行绑定。

## 3. 企业微信用户同步机制

### 3.1 同步策略总览

CAPP系统与企业微信的用户数据同步采用**定时全量同步 + 实时增量同步**的双轨策略，确保两端数据高度一致。

| 同步类型 | 触发方式 | 同步范围 | 执行频率 | 适用场景 |
|----------|----------|----------|----------|----------|
| 全量同步 | 定时任务（Cron） | 全部部门与成员 | 每日凌晨2:00 | 数据兜底、初始化 |
| 增量同步 | 企业微信回调 + 手动触发 | 变更的部门与成员 | 实时/按需 | 日常维护、即时更新 |
| 手动同步 | 管理员后台操作 | 指定部门或成员 | 按需 | 异常修复、单点更新 |

### 3.2 全量同步流程

**执行时机**：每日凌晨2:00通过Linux Cron或Windows计划任务触发。

**处理步骤**：

1. **获取access_token**：调用企业微信`gettoken`接口。
2. **获取部门列表**：调用`department/list`接口，递归获取全部部门树。
3. **遍历部门获取成员**：对每个部门调用`user/list`接口，获取部门下全部成员详情。
4. **数据比对与更新**：
   - 将企业微信返回的部门数据与本地`wechat_department`表逐条比对。
   - 新增部门：插入记录，标记`sync_status = 1`。
   - 变更部门：更新名称、父部门ID、排序等字段，记录变更日志。
   - 删除部门：标记本地记录`status = 0`（软删除），并检查是否有下属成员，如有则触发告警。
5. **成员数据比对**：
   - 新增成员：插入`wechat_user_mapping`和`sys_user`表（若配置自动开户）。
   - 变更成员：更新姓名、部门、职位、手机号、邮箱、头像等字段。
   - 离职成员：标记`status = 0`，同步禁用CAPP系统账号（可配置是否自动禁用）。
6. **同步日志记录**：将本次同步的统计信息（新增数、更新数、删除数、耗时）写入`wechat_sync_log`表。

**PHP核心逻辑**：

```php
function fullSyncUsers() {
    $db = getDbInstance();
    $accessToken = YOUR_SECRET);
    
    // 1. 获取全部部门
    $deptUrl = "https://qyapi.weixin.qq.com/cgi-bin/department/list?access_token=YOUR_SECRET}";
    $deptRes = json_decode(httpGet($deptUrl), true);
    $wxDepartments = $deptRes['department'] ?? [];
    
    // 2. 获取全部成员（使用department/list接口递归获取）
    $userUrl = "https://qyapi.weixin.qq.com/cgi-bin/user/list?access_token=YOUR_SECRET}&department_id=1&fetch_child=1";
    $userRes = json_decode(httpGet($userUrl), true);
    $wxUsers = $userRes['userlist'] ?? [];
    
    $db->beginTransaction();
    try {
        // 3. 同步部门
        $localDepts = $db->query("SELECT dept_id FROM wechat_department");
        $localDeptIds = array_column($localDepts, 'dept_id');
        $wxDeptIds = array_column($wxDepartments, 'id');
        
        foreach ($wxDepartments as $dept) {
            if (in_array($dept['id'], $localDeptIds)) {
                $db->execute("UPDATE wechat_department SET name=?, parentid=?, order_num=? WHERE dept_id=?",
                    [$dept['name'], $dept['parentid'], $dept['order'], $dept['id']]);
            } else {
                $db->execute("INSERT INTO wechat_department (dept_id, name, parentid, order_num, status, create_time) VALUES (?,?,?,?,1,NOW())",
                    [$dept['id'], $dept['name'], $dept['parentid'], $dept['order']]);
            }
        }
        
        // 标记已删除的部门
        $deletedDepts = array_diff($localDeptIds, $wxDeptIds);
        foreach ($deletedDepts as $delId) {
            $db->execute("UPDATE wechat_department SET status=0, update_time=NOW() WHERE dept_id=?", [$delId]);
        }
        
        // 4. 同步成员（类似逻辑）
        $stats = ['add' => 0, 'update' => 0, 'disable' => 0];
        foreach ($wxUsers as $user) {
            $exists = $db->query("SELECT id FROM wechat_user_mapping WHERE wechat_user_id=?", [$user['userid']]);
            if ($exists) {
                $db->execute("UPDATE wechat_user_mapping SET name=?, dept_ids=?, position=?, mobile=?, email=?, avatar=?, status=1, update_time=NOW() WHERE wechat_user_id=?",
                    [$user['name'], json_encode($user['department']), $user['position'], $user['mobile'] ?? '', $user['email'] ?? '', $user['avatar'] ?? '', $user['userid']]);
                $stats['update']++;
            } else {
                $db->execute("INSERT INTO wechat_user_mapping (wechat_user_id, name, dept_ids, position, mobile, email, avatar, status, create_time) VALUES (?,?,?,?,?,?,?,1,NOW())",
                    [$user['userid'], $user['name'], json_encode($user['department']), $user['position'], $user['mobile'] ?? '', $user['email'] ?? '', $user['avatar'] ?? '']);
                $stats['add']++;
            }
        }
        
        // 标记离职成员
        $localUsers = $db->query("SELECT wechat_user_id FROM wechat_user_mapping WHERE status=1");
        $localUserIds = array_column($localUsers, 'wechat_user_id');
        $wxUserIds = array_column($wxUsers, 'userid');
        $deletedUsers = array_diff($localUserIds, $wxUserIds);
        foreach ($deletedUsers as $delUid) {
            $db->execute("UPDATE wechat_user_mapping SET status=0, update_time=NOW() WHERE wechat_user_id=?", [$delUid]);
            $stats['disable']++;
        }
        
        $db->commit();
        
        // 记录同步日志
        $db->execute("INSERT INTO wechat_sync_log (sync_type, add_count, update_count, disable_count, sync_time, status) VALUES ('full',?,?,?,NOW(),1)",
            [$stats['add'], $stats['update'], $stats['disable']]);
            
    } catch (Exception $e) {
        $db->rollback();
        throw $e;
    }
}
```

### 3.3 增量同步机制

#### 3.3.1 企业微信事件回调

企业微信支持配置接收服务器，当通讯录发生变更时，企业微信会主动推送事件消息至CAPP系统。

**配置步骤**：

1. 在CAPP系统后台配置企业微信"接收消息"的URL、Token、EncodingAESKey。
2. 企业微信验证URL有效性（GET请求验证签名）。
3. 验证通过后，企业微信将在成员/部门变更时推送XML格式事件。

**接收事件类型**：

| 事件类型 | 说明 | 处理动作 |
|----------|------|----------|
| change_contact | 通讯录变更 | 根据变更类型细分处理 |
| └ create_user | 新增成员 | 插入用户映射记录，可选自动创建CAPP账号 |
| └ update_user | 更新成员 | 更新姓名、部门、职位、手机号等字段 |
| └ delete_user | 删除成员 | 标记用户映射记录为禁用，可选禁用CAPP账号 |
| └ create_party | 新增部门 | 插入部门记录 |
| └ update_party | 更新部门 | 更新部门名称、父部门、排序 |
| └ delete_party | 删除部门 | 标记部门为禁用 |

**回调处理PHP示例**：

```php
function handleWechatCallback() {
    $xml = file_get_contents('php://input');
    $data = simplexml_load_string($xml, 'SimpleXMLElement', LIBXML_NOCDATA);
    $data = json_decode(json_encode($data), true);
    
    $event = $data['Event'] ?? '';
    $changeType = $data['ChangeType'] ?? '';
    
    if ($event === 'change_contact') {
        switch ($changeType) {
            case 'create_user':
                handleCreateUser($data);
                break;
            case 'update_user':
                handleUpdateUser($data);
                break;
            case 'delete_user':
                handleDeleteUser($data['UserID']);
                break;
            case 'create_party':
                handleCreateParty($data);
                break;
            case 'update_party':

                break;

        }
    }

}
```

### 4.4 消息发送控制与防重机制

1. **重复发送检查**：对于同一业务事件（如同一审批单），在`wechat_message_log`表中检查最近5分钟内是否已发送过相同类型的消息给同一用户，避免重复打扰。
2. **发送频率限制**：单应用每企业最多20次/秒，系统内维护发送队列，超限时分批延迟发送。
3. **失败重发**：发送失败的消息（如access_token过期、用户不在应用可见范围）记录失败原因，由定时任务在10分钟后重试，最多重试3次。
4. **消息阅读状态跟踪**：通过企业微信"已读未读"接口（需单独开通），在关键审批消息发送后30分钟检查阅读状态，未读时通过短信或电话提醒（需集成第三方）。

### 5.2 JS-SDK权限验证流程

企业微信JS-SDK的调用需要在页面加载时完成权限验证，流程如下：

1. **前端请求签名**：页面加载时，前端将当前页面URL发送至后端`POST /api/wechat/jssdk/sign`。
2. **后端生成签名**：
   - 获取jsapi_ticket（缓存2小时）。
   - 生成随机字符串noncestr。
   - 获取当前时间戳timestamp。
   - 拼接字符串：`jsapi_ticket={ticket}&noncestr={noncestr}&timestamp={timestamp}&url={url}`。
   - 使用SHA1算法生成签名signature。
3. **返回配置参数**：后端返回appId、timestamp、nonceStr、signature。
4. **前端注入配置**：调用`wx.config()`注入配置，成功后调用`wx.ready()`执行JS-SDK方法。

**PHP签名接口实现**：

```php
function getJsSdkSign() {
    $url = $_POST['url'] ?? '';
    if (empty($url)) {
        throw new Exception('URL参数不能为空', 400);
    }
    
    $ticket = getJsApiTicket(); // 从缓存获取，过期则刷新
    $nonceStr = bin2hex(random_bytes(8));
    $timestamp = time();
    
    $string = "jsapi_ticket={$ticket}&noncestr={$nonceStr}&timestamp={$timestamp}&url={$url}";
    $signature = sha1($string);
    
    return [
        'appId' => WECHAT_CORP_ID,
        'timestamp' => $timestamp,
        'nonceStr' => $nonceStr,
        'signature' => $signature
    ];
}

function getJsApiTicket() {
    $redis = getRedisInstance();
    $ticket = $redis->get('wechat:jsapi_ticket');
    
    if (!$ticket) {
        $accessToken = YOUR_SECRET);
        $url = "https://qyapi.weixin.qq.com/cgi-bin/get_jsapi_ticket?access_token=YOUR_SECRET}";
        $res = json_decode(httpGet($url), true);
        
        if (isset($res['ticket'])) {
            $ticket = $res['ticket'];
            // 缓存1小时50分钟（预留10分钟缓冲）
            $redis->setex('wechat:jsapi_ticket', 6600, $ticket);
        } else {
            throw new Exception('获取jsapi_ticket失败: ' . ($res['errmsg'] ?? '未知错误'));
        }
    }
    
    return $ticket;
}
```

## 7. 企业微信通讯录集成

### 7.1 部门同步策略

企业微信通讯录的部门树与CAPP系统的组织架构保持映射关系：

- **根部门映射**：企业微信根部门（ID=1）映射为CAPP系统的顶级组织节点。
- **层级保持**：企业微信的部门层级关系原样同步至CAPP系统`sys_department`表。
- **多部门支持**：企业微信支持一个成员属于多个部门，CAPP系统通过`dept_ids` JSON数组字段存储多部门关系，同时设置`main_dept_id`标识主属部门。
- **部门扩展字段**：CAPP系统在`wechat_department`表基础上，扩展`dept_code`（部门编码）、`dept_type`（部门类型：研发/生产/质量/管理）等自有字段，这些字段不参与同步，由CAPP系统管理员维护。

### 7.2 人员同步策略

#### 7.2.1 同步规则

1. **自动开户**：可配置是否在企业微信新增成员时自动在CAPP系统创建账号。自动开户时，默认角色为"普通工艺员"，初始密码随机生成并通过企业微信消息推送。
2. **账号绑定**：若不开自动开户，新增的企业微信成员需在CAPP系统中由管理员手动绑定或用户自行扫码绑定。
3. **信息覆盖策略**：同步时，企业微信侧的数据（姓名、部门、手机号）覆盖CAPP侧数据；CAPP侧的自有数据（岗位角色、技能等级、工艺权限）保留不变。
4. **离职处理**：企业微信成员删除后，CAPP系统可选择：
   - 自动禁用账号（默认）
   - 仅解除企业微信绑定，保留CAPP账号
   - 自动删除账号（不推荐，会导致历史数据归属问题）

#### 7.2.2 同步冲突处理

| 冲突场景 | 处理策略 |
|----------|----------|
| 企业微信UserID变更 | 视为新用户，原绑定关系失效，需重新绑定 |
| CAPP用户已存在同名不同人 | 以UserID为唯一键，姓名可重复，通过绑定关系区分 |
| 企业微信部门ID变更 | 全量同步时按ID匹配，若ID变更则视为新部门，旧部门标记删除 |
| 手机号冲突 | 以企业微信为准更新CAPP手机号，若CAPP中手机号已被他人使用，记录冲突日志待人工处理 |

## 8. 企业微信审批对接

### 8.1 对接模式选择

CAPP系统的工艺审批流程与企业微信审批对接，采用**"CAPP发起 + 企业微信审批 + 回调同步"**的混合模式：

- **CAPP端**：维护完整的工艺审批业务数据、审批流程模板、审批节点配置。
- **企业微信端**：作为审批操作入口，利用企业微信审批的移动端体验、消息提醒、已读未读能力。
- **数据同步**：审批状态变更通过企业微信回调通知CAPP系统，CAPP系统更新本地审批状态并触发后续业务逻辑。

### 8.2 发起审批流程

当CAPP系统中触发工艺审批时，调用企业微信"审批"接口创建审批单：

**接口**：`POST https://qyapi.weixin.qq.com/cgi-bin/oa/applyevent?access_token=YOUR_SECRET}`

**请求体结构**：


## 9. 安全与Token管理

### 9.1 access_token管理策略

access_token是调用企业微信API的核心凭证，有效期为7200秒（2小时），全局唯一且同时只能存在一个有效token。

**管理策略**：

1. **集中存储**：使用Redis作为access_token的统一缓存中心，所有PHP进程共享。
2. **单点刷新**：设置分布式锁（Redis `SETNX`），确保同一时刻只有一个进程负责刷新token，避免并发刷新导致旧token失效。
3. **提前刷新**：在token过期前10分钟（即缓存有效期设置为7100秒）主动刷新，避免边界时间请求失败。
4. **容错降级**：若Redis不可用，使用文件锁+本地文件缓存作为降级方案。
5. **监控告警**：记录每次获取token的耗时和结果，连续失败3次时触发告警通知管理员。

**PHP实现**：

```php
function getWechatAccessToken() {
    $redis = getRedisInstance();
    $cacheKey = 'wechat:access_token';
    $lockKey = 'wechat:access_token:lock';
    
    // 1. 先查缓存
    $token = YOUR_SECRET);
    if ($token) {
        return $token;
    }
    
    // 2. 获取分布式锁，防止并发刷新
    $locked = $redis->set($lockKey, '1', ['NX', 'EX' => 60]);
    if (!$locked) {
        // 未获取到锁，等待后重试
        usleep(500000); // 等待500ms
        $token = YOUR_SECRET);
        if ($token) {
            return $token;
        }
        throw new Exception('获取access_token时无法获取分布式锁');
    }
    
    try {
        // 3. 再次检查缓存（双重检查）
        $token = YOUR_SECRET);
        if ($token) {
            return $token;
        }
        
        // 4. 调用企业微信接口获取新token
        $url = "https://qyapi.weixin.qq.com/cgi-bin/gettoken?corpid=" . WECHAT_CORP_ID . "&corpsecret=" . WECHAT_SECRET;
        $res = json_decode(httpGet($url), true);
        
        if (isset($res['access_token'])) {
            $token = YOUR_SECRET'access_token'];
            $expiresIn = $res['expires_in'] ?? 7200;
            // 缓存有效期减去100秒作为缓冲
            $redis->setex($cacheKey, max(1, $expiresIn - 100), $token);
            return $token;
        } else {
            throw new Exception('获取access_token失败: ' . ($res['errmsg'] ?? '未知错误'));
        }
    } finally {
        // 5. 释放锁
        $redis->del($lockKey);
    }
}
```

### 9.2 jsapi_ticket管理策略

jsapi_ticket用于JS-SDK权限验证，有效期同样为7200秒，管理策略与access_token类似：

- 使用Redis缓存，键名为`wechat:jsapi_ticket`。
- 设置分布式锁防止并发刷新。
- 缓存有效期设置为6600秒（预留600秒缓冲）。
- 与access_token刷新逻辑解耦，但jsapi_ticket的获取依赖于access_token。

### 9.3 消息加密与解密

企业微信回调消息采用AES加密传输，CAPP系统需实现消息的加解密处理。

**加密流程**：

1. 企业微信使用EncodingAESKey对消息进行AES-256-CBC加密。
2. 将密文、签名、时间戳、随机数一并发送至CAPP回调URL。
3. CAPP系统使用相同EncodingAESKey解密消息内容。
4. 处理完成后，如需回复消息，同样进行加密后返回。

**PHP加解密实现要点**：

- 使用openssl扩展进行AES解密。
- 密钥由EncodingAESKey经过Base64解码后得到32字节。
- 解密后去除前16字节的随机字符串，再去除4字节的msg_len，剩余即为明文XML。
- 签名验证使用SHA1算法，拼接Token、时间戳、随机数和密文后计算签名，与企业微信传来的签名比对。

### 9.4 IP白名单与HTTPS

- **IP白名单**：在企业微信管理后台配置CAPP服务器的出口公网IP，防止未授权服务器调用API。
- **HTTPS强制**：所有与企业微信交互的接口必须使用HTTPS，禁止明文HTTP传输。
- **Secret安全**：企业微信Secret存储在服务器环境变量或加密配置文件中，禁止硬编码在代码仓库中。

## 10. 错误处理与重试机制

### 10.1 企业微信错误码分类处理

企业微信API返回的错误码需分类处理：

| 错误码 | 含义 | 处理策略 |
|--------|------|----------|
| 0 | 成功 | 正常处理 |
| 40001 | access_token过期或无效 | 清除缓存中的token，立即重新获取并重试原请求 |
| 40014 | access_token不合法 | 同40001处理 |
| 42001 | access_token过期 | 同40001处理 |
| 40029 | OAuth code无效或过期 | 引导用户重新扫码授权 |
| 60011 | 不在应用可见范围 | 记录日志，通知管理员调整应用可见范围 |
| 301055 | 审批模板不存在 | 检查模板ID配置，同步最新模板 |
| -1 | 系统繁忙 | 延迟3秒后重试，最多重试3次 |
| 其他 | 未知错误 | 记录详细日志，人工介入排查 |

### 10.2 统一HTTP请求封装

封装企业微信HTTP请求工具类，内置自动重试和token刷新逻辑：

```php
class WechatHttpClient {
    const MAX_RETRY = 3;
    const RETRY_DELAY = 3; // 秒
    
    public function request($url, $method = 'GET', $data = null) {
        $retryCount = 0;
        
        while ($retryCount < self::MAX_RETRY) {
            $response = $this->doRequest($url, $method, $data);
            $res = json_decode($response, true);
            
            // 成功
            if (isset($res['errcode']) && $res['errcode'] == 0) {
                return $res;
            }
            
            // access_token类错误，自动刷新并重试
            if (in_array($res['errcode'] ?? 0, [40001, 40014, 42001])) {
                clearAccessTokenCache();
                $url = $this->replaceAccessToken($url);
                $retryCount++;
                continue;
            }
            
            // 系统繁忙，延迟重试
            if (($res['errcode'] ?? 0) == -1) {
                sleep(self::RETRY_DELAY);
                $retryCount++;
                continue;
            }
            
            // 其他错误，直接抛出
            throw new WechatApiException($res['errmsg'] ?? '未知错误', $res['errcode'] ?? -1);
        }
        
        throw new WechatApiException('请求企业微信接口失败，已达最大重试次数');
    }
    
    private function doRequest($url, $method, $data) {
        $ch = curl_init();
        curl_setopt($ch, CURLOPT_URL, $url);
        curl_setopt($ch, CURLOPT_RETURNTRANSFER, true);
        curl_setopt($ch, CURLOPT_SSL_VERIFYPEER, true);
        curl_setopt($ch, CURLOPT_TIMEOUT, 30);
        
        if ($method === 'POST' && $data) {
            curl_setopt($ch, CURLOPT_POST, true);
            curl_setopt($ch, CURLOPT_POSTFIELDS, is_string($data) ? $data : json_encode($data, JSON_UNESCAPED_UNICODE));
            curl_setopt($ch, CURLOPT_HTTPHEADER, ['Content-Type: application/json']);
        }
        
        $response = curl_exec($ch);
        $httpCode = curl_getinfo($ch, CURLINFO_HTTP_CODE);
        curl_close($ch);
        
        if ($httpCode != 200 || $response === false) {
            throw new WechatApiException("HTTP请求失败，状态码: {$httpCode}");
        }
        
        return $response;
    }
    
    private function replaceAccessToken($url) {
        $newToken = getWechatAccessToken();
        return preg_replace('/access_token=[^&]+/', 'access_token=' . $newToken, $url);
    }
}
```

### 10.3 消息发送失败处理

消息发送失败时，记录至`wechat_message_log`表，状态标记为失败，并记录失败原因。定时任务每10分钟扫描失败记录，尝试重新发送，最多重试3次。超过3次仍未成功的，标记为"永久失败"，并可选通过短信或邮件方式通知用户。

### 10.4 日志与监控

- **API调用日志**：记录每次企业微信API调用的接口名、请求参数、响应结果、耗时、是否成功，保存至`wechat_api_log`表，保留30天。
- **异常告警**：当1小时内企业微信API错误率超过5%，或access_token连续获取失败时，通过企业微信消息或邮件通知系统管理员。
- **回调事件日志**：记录每次接收的企业微信回调事件类型、时间、处理结果，便于排查问题。
