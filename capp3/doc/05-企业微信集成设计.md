## 1. 概述

本文档针对工业压缩机、压力容器研发设计生产企业的CAPP（计算机辅助工艺规划）系统，详细设计企业微信集成方案。企业微信作为企业内部统一入口，承担身份认证、消息触达、移动办公、审批流转等核心职能。本设计遵循企业微信官方API规范，结合PHP原生技术栈与MySQL数据库，构建高可用、易扩展、安全可控的集成体系。

本集成方案覆盖以下核心场景：
- **统一身份认证**：员工通过企业微信扫码登录CAPP系统，实现单点登录；
- **组织架构同步**：定时同步企业微信通讯录，保持部门、人员数据一致性；
- **消息实时触达**：工艺审批、生产任务、质量预警等关键信息推送至企业微信；
- **移动能力扩展**：通过JS-SDK提供扫码报工、拍照上传、定位打卡等移动端能力；
- **审批流程打通**：CAPP系统内发起的工艺变更、工艺审批等流程对接企业微信审批引擎。

## 2. 企业微信扫码登录流程

### 2.1 OAuth2.0授权流程详细设计

CAPP系统采用企业微信OAuth2.0授权登录模式，支持Web端扫码登录及移动端静默登录两种模式。整个授权流程分为六个阶段，确保身份安全校验与系统账户绑定。

**阶段一：登录请求发起**

用户在CAPP系统登录页点击"企业微信扫码登录"按钮，前端向后端发起登录请求。后端生成唯一状态标识`state`（32位随机字符串），存入Redis/Session并设置5分钟有效期，同时记录客户端IP与User-Agent用于后续防CSRF校验。

**阶段二：构造授权URL**

后端根据应用类型构造企业微信授权URL：

- Web端（扫码登录）：使用`snsapi_login` scope，调用`/connect/oauth2/authorize`接口；
- 移动端（企业微信内打开）：使用`snsapi_base`或`snsapi_privateinfo` scope，调用`/connect/oauth2/authorize`接口。

授权URL参数包括：`appid`（企业ID）、`redirect_uri`（编码后的回调地址）、`response_type=code`、`scope`、`state`。

**阶段三：用户授权与Code获取**

Web端展示企业微信扫码页面，用户使用企业微信APP扫描二维码并确认授权；移动端在企业微信内直接跳转授权页。授权成功后，企业微信将用户重定向至预设的`redirect_uri`，并携带`code`及`state`参数。

**阶段四：Code校验与Token换取**

CAPP系统回调接口接收`code`与`state`，执行以下校验：
1. 校验`state`是否存在于缓存且未过期；
2. 校验`state`与当前会话绑定关系；
3. 使用`code`调用企业微信`getuserinfo`接口（Web登录）或`getuserinfo`接口（内登录），换取用户身份`UserId`；
4. 若需手机号等敏感信息，使用`code`调用`getuserdetail`接口（需`snsapi_privateinfo`授权）。

**阶段五：系统账户绑定与登录**

获取企业微信`UserId`后，查询`wx_user_mapping`表：
- 若已绑定CAPP系统账户，直接生成JWT/Session，完成登录；
- 若未绑定，根据企业微信返回的`UserId`查询通讯录接口获取用户详情（姓名、部门、手机号、邮箱），触发自动绑定或引导用户完成首次绑定。

**阶段六：登录态下发与跳转**

登录成功后，后端生成包含`user_id`、`wx_user_id`、`exp`等字段的JWT Token（有效期8小时，Refresh Token有效期7天），通过Cookie或Header下发给前端。前端携带Token访问CAPP系统各模块。

**时序图关键节点**：

```
用户 -> CAPP前端: 点击企业微信登录
CAPP前端 -> CAPP后端: GET /api/auth/wx/login
CAPP后端 -> CAPP后端: 生成state，存入缓存
CAPP后端 -> CAPP前端: 返回授权URL
CAPP前端 -> 企业微信: 跳转授权页（Web展示二维码）
用户 -> 企业微信: 扫码/确认授权
企业微信 -> CAPP后端: 回调 redirect_uri?code=xxx&state=xxx
CAPP后端 -> CAPP后端: 校验state有效性
CAPP后端 -> 企业微信API: 用code换取UserId
企业微信API -> CAPP后端: 返回UserId
CAPP后端 -> MySQL: 查询wx_user_mapping
MySQL -> CAPP后端: 返回绑定关系
CAPP后端 -> CAPP后端: 生成JWT Token
CAPP后端 -> CAPP前端: 返回Token及用户信息
CAPP前端 -> 用户: 跳转系统首页
```

### 2.2 登录状态管理与会话保持

CAPP系统采用双Token机制（Access Token + Refresh Token）管理登录状态：

- **Access Token**：JWT格式，有效期8小时，存储于前端LocalStorage及后端Redis白名单；
- **Refresh Token**：JWT格式，有效期7天，仅存储于HttpOnly Cookie，用于Access Token续期；
- **Token黑名单**：用户主动退出或检测到异常时，将Token加入Redis黑名单，立即失效。

Web端通过定时器（每15分钟）静默调用`/api/auth/refresh`接口续期Access Token。移动端在企业微信内运行时，每次打开应用重新校验登录态，避免长期离线导致的Token失效。

### 2.3 未绑定用户处理机制

对于首次登录且未在CAPP系统建立账户映射的企业微信用户，系统提供两种处理策略：

**策略A：自动开户（推荐）**

系统根据企业微信通讯录接口获取用户详细信息（姓名、部门ID、手机号、邮箱、职位），自动在`sys_user`表创建基础账户，状态设为"已激活"，并在`wx_user_mapping`表建立绑定关系。自动生成的CAPP账户登录名采用`wx_{UserId}`或手机号，初始密码随机生成并加密存储，用户首次登录后强制修改密码。

**策略B：人工审核开户**

适用于安全要求较高的场景。未绑定用户登录时跳转至"账户申请页"，填写补充信息（工号、岗位、工艺权限组），提交后由系统管理员在企业微信收到审批通知，审批通过后自动完成开户与绑定。

## 3. 企业微信用户同步机制

### 3.1 定时全量同步

全量同步作为兜底机制，每日凌晨02:00执行一次，确保CAPP系统用户数据与企业微信通讯录完全一致。全量同步流程如下：

1. **获取部门列表**：调用企业微信`department/list`接口，递归获取全部部门树；
2. **遍历部门获取成员**：对每个部门调用`user/list`接口，获取该部门下全部成员详情；
3. **数据比对与更新**：将获取到的企业微信用户数据与CAPP系统`wx_user_mapping`及`sys_user`表进行全量比对；
4. **差异处理**：
   - 新增用户：企业微信存在但CAPP不存在，执行自动开户或标记待审核；
   - 变更用户：关键字段（姓名、部门、职位、手机号、状态）发生变更，更新CAPP系统记录；
   - 离职用户：企业微信状态为"已删除/已禁用"且CAPP存在，根据策略禁用CAPP账户或移至离职人员表。

全量同步采用分页与限流机制，企业微信API调用频率限制为每应用每企业2000次/秒，CAPP系统通过任务队列控制并发，避免触发限流。

### 3.2 增量同步机制

增量同步依赖企业微信"通讯录变更事件"推送，实时性更高。CAPP系统需在企业微信管理后台配置接收服务器URL，订阅以下事件：

- `change_contact`：通讯录变更事件大类，包含：
  - `create_user`：新增成员
  - `update_user`：更新成员
  - `delete_user`：删除成员
  - `create_party`：新增部门
  - `update_party`：更新部门
  - `delete_party`：删除部门

**事件接收与处理流程**：

1. 企业微信将加密事件推送至CAPP系统回调接口；
2. CAPP系统使用企业微信SDK验证消息签名（`msg_signature`、`timestamp`、`nonce`），解密XML内容；
3. 解析事件类型及变更数据，写入`wx_sync_log`表作为原始记录；
4. 异步消费队列处理具体变更：
   - 新增/更新用户：调用`user/get`接口获取最新详情，更新本地映射表；
   - 删除用户：将CAPP系统对应账户状态改为"禁用"，保留历史数据；
   - 部门变更：更新`sys_department`表，同步调整该部门下人员的工艺权限范围。

若事件推送失败（CAPP系统宕机或网络异常），企业微信会重试推送最多8次（间隔递增：1秒、5秒、30秒、5分钟、30分钟、1小时、3小时、6小时）。CAPP系统需实现幂等处理，避免重复消费导致数据异常。

### 3.3 字段映射规则

企业微信用户字段与CAPP系统用户字段映射关系如下：

| 企业微信字段 | CAPP系统字段 | 数据类型 | 映射说明 |
|-------------|-------------|---------|---------|
| userid | wx_user_id | VARCHAR(64) | 企业微信唯一标识，主键映射 |
| name | user_name | VARCHAR(64) | 用户姓名 |
| department | dept_id | JSON/逗号分隔 | 所属部门ID列表，主部门取第一个 |
| mobile | phone | VARCHAR(20) | 手机号，用于短信及紧急通知 |
| email | email | VARCHAR(100) | 邮箱地址 |
| position | position | VARCHAR(64) | 职位信息 |
| gender | gender | TINYINT | 1男，2女，0未知 |
| avatar | avatar_url | VARCHAR(255) | 头像URL，缓存至本地CDN |
| status | wx_status | TINYINT | 1已激活，2已禁用，4未激活 |
| isleader | is_leader | TINYINT | 是否部门负责人，影响审批权限 |
| extattr | ext_attr | JSON | 扩展属性，映射工号、工艺资质等自定义字段 |
| alias | alias | VARCHAR(64) | 别名，用于显示优化 |

**自定义字段映射**：

企业微信支持在通讯录中配置自定义字段，CAPP系统利用此特性扩展工艺相关属性：
- `工号`（自定义字段1）映射至`sys_user.employee_no`；
- `工艺资质等级`（自定义字段2）映射至`sys_user.tech_level`，用于工艺审批权限判定；
- `特种设备操作证号`（自定义字段3）映射至`sys_user.cert_no`，用于压力容器生产岗位资质校验。

### 3.4 同步冲突解决策略

当企业微信与CAPP系统对同一用户数据存在不一致时，采用以下冲突解决策略：

- **企业微信为权威源**：通讯录基础字段（姓名、部门、手机号）以企业微信数据为准，CAPP系统本地修改仅作用于系统专属字段（密码、工艺权限、角色组）；
- **双向同步标记**：CAPP系统提供"同步锁定"功能，对特定用户标记`sync_lock=1`，该用户不再接受企业微信同步覆盖，适用于借调、跨项目兼职等特殊场景；
- **冲突告警**：同步过程中检测到关键字段冲突（如手机号与企业微信不一致且未加锁），向系统管理员推送企业微信消息告警，人工确认后处理。

## 4. 企业微信消息推送

### 4.1 审批通知推送

CAPP系统内涉及工艺审批的关键节点，通过企业微信应用消息实时通知审批人及申请人，确保工艺审批流程高效运转。

**推送场景**：
- 工艺路线审批提交：通知工艺主管及技术部长；
- 工艺变更申请：通知原工艺编制人、工艺审核人、质量负责人；
- 工艺文件签审：通知各级签审人员；
- 审批结果反馈：通知申请人审批通过/驳回/转办结果。

**消息模板设计（文本卡片消息）**：

```json
{
  "touser": "{审批人UserId}",
  "msgtype": "textcard",
  "agentid": 1000002,
  "textcard": {
    "title": "工艺审批通知",
    "description": "<div class=\"gray\">{提交时间}</div> <div class=\"normal\">您有一条待处理的工艺审批</div><div class=\"highlight\">工艺编号：{工艺编号}</div><div class=\"highlight\">产品名称：{产品名称}</div><div class=\"highlight\">审批类型：{审批类型}</div><div class=\"highlight\">提交人：{提交人}</div>",
    "url": "https://capp.company.com/mobile/approval/detail?id={审批ID}&wx_auth=1",
    "btntxt": "立即处理"
  }
}
```

点击消息卡片跳转至CAPP移动端审批详情页，携带`wx_auth`参数实现免登。

### 4.2 任务提醒推送

针对生产执行层的工艺任务，推送至一线操作人员及班组长：

- **工艺任务下达**：生产计划下发后，推送工序任务至操作者企业微信；
- **任务逾期预警**：工序计划完成时间前2小时未报工，自动推送催办消息；
- **质量检验任务**：首检、巡检、完工检任务分配后推送至质检员；
- **设备点检提醒**：基于工艺设备关联关系，推送设备日常点检任务。

任务提醒采用"任务卡片消息"（`taskcard`类型），支持点击确认完成，实现轻量级闭环管理。

### 4.3 系统公告推送

系统级公告通过企业微信"图文消息"或"markdown消息"推送至全员或指定部门：

- 工艺标准更新公告；
- 质量事故通报；
- 系统维护通知；
- 培训安排通知。

公告支持按部门标签（`toparty`）、人员标签（`totag`）精准推送，避免全员打扰。

### 4.4 消息模板管理

CAPP系统后台提供"消息模板管理"模块，管理员可维护模板列表，支持变量插值：

- 模板编码唯一标识；
- 模板内容支持HTML标签（企业微信文本卡片规范）；
- 变量采用`{变量名}`占位，运行时替换；
- 模板支持启用/禁用、预览测试、发送统计。

消息发送记录全部写入`wx_message_log`表，便于追踪送达状态及失败重发。

## 5. 企业微信JS-SDK集成

### 5.1 扫码功能集成

在CAPP移动端（企业微信内置浏览器）提供扫码能力，支撑以下业务场景：

- **工序扫码报工**：扫描工单条码或设备二维码，快速定位至当前工序任务；
- **物料扫码校验**：扫描原材料条码，校验物料批次与工艺BOM一致性；
- **工艺文件扫码查阅**：扫描产品铭牌二维码，跳转至该产品工艺文件及质量追溯页面；
- **设备扫码点检**：扫描设备二维码，进入该设备点检表单。

**JS-SDK调用流程**：

1. 前端页面加载时，向后端请求`jsapi_ticket`签名参数（`appId`、`timestamp`、`nonceStr`、`signature`）；
2. 调用`wx.config`进行权限配置，注册`scanQRCode`接口；
3. 用户点击扫码按钮，调用`wx.scanQRCode({ needResult: 1, scanType: ['qrCode', 'barCode'] })`；
4. 获取扫码结果后，前端解析内容并跳转至对应业务页面。

### 5.2 拍照与图片上传

工艺执行过程中需采集现场照片（如首件检验照片、异常现象照片、完工照片），通过JS-SDK调用原生相机：

- `chooseImage`：选择或拍摄照片，限制最多9张；
- `uploadImage`：上传图片至企业微信服务器，获取`media_id`；
- CAPP后端通过`media/get`接口下载图片至本地文件服务器，关联至工艺记录或质量报告。

图片存储采用"日期+随机码"目录结构，原始图与压缩缩略图分离存储，支持CDN加速访问。

### 5.3 定位功能集成

针对外协工序或现场服务场景，通过`getLocation`接口获取GPS坐标，用于：
- 外协厂家现场工艺指导签到；
- 压力容器安装现场服务定位；
- 工艺巡检轨迹记录。

定位数据与工艺任务绑定，写入`process_task_location`表，支持地图可视化展示。

### 5.4 JS-SDK权限验证

JS-SDK权限验证采用服务端签名机制，防止前端伪造：

1. 前端请求后端接口`/api/wx/jssdk/sign`，传入当前页面URL（去除`#`及后面部分）；
2. 后端使用`jsapi_ticket`、noncestr（16位随机字符串）、timestamp（当前时间戳）、url生成签名；
3. 签名算法：`sha1( string1 )`，其中`string1 = jsapi_ticket={ticket}&noncestr={noncestr}&timestamp={timestamp}&url={url}`；
4. 返回签名参数，前端在`wx.config`中使用；
5. `wx.ready`回调后调用具体JS接口，`wx.error`回调中记录错误并提示用户。

## 8. 企业微信审批对接

### 8.1 发起审批流程

CAPP系统内需要企业层级审批的工艺业务，通过企业微信"审批"应用发起正式审批流程，实现与企业现有审批体系的无缝融合。

**对接场景**：
- 工艺路线重大变更（涉及安全性能的压力容器焊接工艺变更）；
- 新工艺首次投产前的工艺验证审批；
- 工艺外协申请（工业压缩机关键零部件外协工艺方案审批）；
- 工艺文件作废与换版审批。

**发起流程**：

1. CAPP系统根据业务类型选择对应的企业微信审批模板（需提前在企业微信管理后台配置）；
2. 组装审批表单数据，包括：申请人、审批人、抄送人、表单控件值（工艺编号、产品型号、变更内容、影响分析等）；
3. 调用企业微信`approval/apply`接口提交审批；
4. 记录审批实例ID（`sp_no`）至`wx_approval`表，关联CAPP业务单据；
5. 审批人收到企业微信审批待办通知。

**审批模板控件映射**：

| 控件类型 | 企业微信控件 | CAPP数据示例 |
|---------|------------|-------------|
| 文本 | text | 工艺编号：GY-2024-001 |
| 多行文本 | textarea | 变更原因及技术依据 |
| 数字 | number | 影响批次数量 |
| 金额 | money | 变更成本估算 |
| 日期 | date | 计划生效日期 |
| 成员 | contact | 工艺审核人、质量负责人 |
| 附件 | file | 变更后工艺文件PDF |
| 明细 | detail | 影响工序清单 |

### 8.2 审批状态回调

企业微信审批状态变更后，通过事件推送通知CAPP系统：

- `open_approval_change`：审批状态变更事件，包含：
  - `apply`：审批申请状态变更（审批中、已通过、已驳回、已转交）；
  - `save`：审批申请暂存（较少使用）。

CAPP系统回调接口解析事件内容，更新`wx_approval`表状态，并驱动CAPP内部业务状态流转：

- 审批通过：更新工艺单据状态为"已批准"，触发工艺文件正式发布、ERP/MES接口下发；
- 审批驳回：更新工艺单据状态为"已驳回"，通知编制人修改，保留驳回原因；
- 审批转交：记录实际审批人，更新审批日志。

### 8.3 审批数据同步

除实时回调外，CAPP系统提供审批数据补全机制：

- 定时任务每30分钟调用`approval/getdetail`接口，查询近24小时内状态为"审批中"的单据，同步最新审批节点信息；
- 管理员可在CAPP后台手动"同步审批状态"，输入企业微信审批单号进行单次查询；
- 审批完成后，将审批流程图、各级审批意见、耗时等数据写入CAPP系统，形成完整的工艺变更审批档案。

## 9. 安全与Token管理

### 9.1 AccessToken缓存策略

企业微信Access Token是调用各API的凭证，有效期7200秒，全局唯一且存在获取频率限制（每企业每应用200次/天）。CAPP系统采用中心化缓存策略：

- **存储位置**：MySQL `wx_token_cache`表（主备）+ Redis（热缓存）；
- **获取逻辑**：
  1. 优先从Redis读取`access_token`，若存在且未过期（预留300秒缓冲），直接使用；
  2. Redis未命中，查询MySQL缓存表，若有效则回填Redis；
  3. 缓存均失效，调用`gettoken`接口获取新Token，同时更新Redis与MySQL；
  4. 获取新Token时加分布式锁（Redis `SETNX`），防止多进程并发刷新导致旧Token失效。
- **异常处理**：若Token获取失败（如网络异常、企业微信服务故障），记录告警日志，使用最近一次有效Token（允许短暂超期使用，企业微信通常有5分钟宽限期）。

### 9.2 JSAPI Ticket缓存策略

JSAPI Ticket用于JS-SDK权限签名，有效期7200秒，与Access Token独立获取：

- 缓存策略与Access Token一致，存储于`wx_token_cache`表，类型标记为`jsapi_ticket`；
- 前端请求签名时，后端直接使用缓存Ticket生成签名，避免频繁调用企业微信接口；
- Ticket与Access Token刷新解耦，避免同时失效导致服务中断。

### 9.3 密钥安全管理

企业微信集成涉及多组密钥，安全等级要求极高：

- **CorpID与CorpSecret**：CorpSecret等同于应用主密钥，存储于服务器环境变量（`.env`文件），禁止硬编码；
- **消息加解密Key与Token**：通讯录事件接收使用的`EncodingAESKey`与`Token`同样存储于环境变量；
- **数据库加密**：`wx_token_cache`表中Access Token字段采用AES-256加密存储，密钥托管于服务器KMS或环境变量；
- **传输加密**：所有与企业微信的交互强制HTTPS，CAPP系统回调接口配置TLS 1.2+；
- **日志脱敏**：任何日志、错误堆栈中禁止输出CorpSecret、Access Token、用户敏感信息，正则过滤替换为`***`。

## 10. 错误处理与重试机制

### 10.1 错误码分类与处理

企业微信API返回错误码按业务场景分类处理：

| 错误码 | 含义 | 处理策略 |
|-------|------|---------|
| 0 | 成功 | 正常处理 |
| 40001 | AccessToken失效 | 立即刷新Token并重试原请求 |
| 40014 | AccessToken不合法 | 强制刷新Token并重试 |
| 42001 | AccessToken过期 | 刷新Token并重试 |
| 42009 | JSAPI Ticket过期 | 刷新Ticket并重试签名 |
| 60011 | 用户不在应用可见范围 | 记录错误，通知管理员调整可见范围 |
| 81013 | 审批模板不存在 | 记录错误，告警通知 |
| 301055 | 审批申请已存在 | 幂等处理，直接返回已有实例ID |
| -1 | 系统繁忙 | 指数退避重试 |

### 10.2 重试机制设计

CAPP系统封装企业微信HTTP客户端，内置重试逻辑：

- **重试条件**：网络超时（CURL超时设为10秒）、HTTP 5xx错误、错误码`-1`（系统繁忙）、Token类错误（刷新后重试）；
- **重试策略**：指数退避，第1次等待1秒，第2次等待2秒，第3次等待4秒，最多重试3次；
- **降级处理**：消息推送类操作重试失败后，写入`wx_message_log`表标记为"待重发"，由定时任务后续补发；审批类操作重试失败后，标记为"推送异常"，由管理员人工介入；
- **熔断机制**：连续失败超过20次/分钟，暂停该API调用1分钟，避免雪崩效应。

### 10.3 日志与监控

所有企业微信API调用记录详细日志：

- 请求URL、参数（脱敏后）、响应状态码、响应内容（脱敏后）；
- 耗时、重试次数、最终状态；
- 异常堆栈、错误码解析结果。

日志写入`wx_api_log`表，保留90天。关键指标接入监控告警：
- Access Token刷新失败次数（>3次/小时触发告警）；
- 消息推送失败率（>5%触发告警）；
- 通讯录事件接收队列堆积（>100条未处理触发告警）。

## 13. 附录

### 附录A：企业微信API版本说明

本文档基于企业微信API 3.0版本设计，涉及的主要接口文档参考企业微信官方开发者文档。若企业微信后续升级API版本，CAPP系统需关注以下变更点：
- 认证方式变更（如从CorpSecret迁移至OAuth 2.0）；
- 消息类型新增或废弃；
- 审批接口字段调整。

### 附录B：PHP原生实现要点

- HTTP客户端：封装基于cURL的`WxHttpClient`类，统一处理GET/POST、JSON编码、SSL校验、超时与重试；
- 消息加解密：引入企业微信官方PHP示例代码中的`WXBizMsgCrypt`类，处理通讯录事件XML的加解密与签名验证；
- 缓存层：使用Redis扩展（`phpredis`）实现Token热缓存及分布式锁，MySQL作为持久化备份；
- 定时任务：通过Linux `crontab`触发PHP CLI脚本执行全量同步、消息补发、Token预刷新等任务。

### 附录C：工业压缩机/压力容器行业特殊适配

- **工艺安全等级**：压力容器焊接工艺变更属于特种设备工艺变更，审批模板需增加"安全影响分析"、"无损检测方案调整"等必填控件；
- **资质校验**：人员同步时读取"特种设备作业人员证"自定义字段，CAPP系统在分配焊接、探伤等关键工序时校验人员资质有效性；
- **外协工艺管理**：通过企业微信审批发起外协工艺方案审批，审批表单中嵌入外协厂家资质附件、工艺评定报告附件，审批通过后自动解锁外协工艺文件下载权限。
