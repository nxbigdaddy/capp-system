## 1. 数据库设计原则和规范

### 1.1 设计原则

1. **第三范式（3NF）优先**：消除数据冗余，确保数据一致性
2. **适度反范式**：在查询性能要求高的场景下，允许适度冗余
3. **业务导向**：表结构设计贴合工业压缩机、压力容器行业工艺设计业务流程
4. **可扩展性**：预留扩展字段，支持未来业务变化
5. **安全性**：敏感数据加密存储，操作记录可追溯

### 1.2 通用字段规范

每张表必须包含以下通用字段：

| 字段名 | 类型 | 说明 |
|--------|------|------|
| id | BIGINT UNSIGNED | 主键，自增 |
| created_at | DATETIME | 创建时间 |
| created_by | BIGINT UNSIGNED | 创建人ID |
| updated_at | DATETIME | 更新时间 |
| updated_by | BIGINT UNSIGNED | 更新人ID |
| deleted_at | DATETIME | 删除时间（软删除） |
| is_deleted | TINYINT(1) | 删除标记：0-未删除，1-已删除 |
| version | INT UNSIGNED | 乐观锁版本号 |

### 1.3 索引设计规范

1. 主键统一使用自增BIGINT
2. 外键字段建立普通索引
3. 频繁查询字段建立联合索引
4. 唯一业务键建立唯一索引
5. 避免过度索引，单表索引不超过5个

### 1.4 字符集和排序规则

- 字符集：`utf8mb4`
- 排序规则：`utf8mb4_general_ci`
- 存储引擎：`InnoDB`

## 2. 数据库命名规范

### 2.1 数据库命名

```
capp_prod      -- 生产环境
capp_test      -- 测试环境
capp_dev       -- 开发环境
```

### 2.2 表命名规范

- 格式：`模块前缀_业务名称`
- 使用小写字母和下划线
- 模块前缀对照表：

| 模块 | 前缀 | 示例 |
|------|------|------|
| 用户权限 | sys_ | sys_user |
| 企业微信 | wx_ | wx_user |
| 工艺设计 | process_ | process_route |
| 产品管理 | product_ | product_info |
| 资源管理 | resource_ | resource_equipment |
| 工时定额 | worktime_ | worktime_quota |
| 模板管理 | template_ | template_process |
| AI功能 | ai_ | ai_model |
| MaxKB | maxkb_ | maxkb_config |
| 外部集成 | integration_ | integration_config |
| 审批流程 | approval_ | approval_flow |
| 系统日志 | log_ | log_operation |

### 2.3 字段命名规范

- 使用小写字母和下划线
- 布尔类型字段以 `is_` 开头
- 状态字段以 `_status` 结尾
- 时间字段以 `_at` 结尾
- ID字段以 `_id` 结尾
- 数量字段以 `_count` 结尾

### 2.4 索引命名规范

- 主键：`pk_表名`
- 唯一索引：`uk_表名_字段名`
- 普通索引：`idx_表名_字段名`
- 联合索引：`idx_表名_字段1_字段2`

### D. 数据安全建议

1. **敏感字段加密**：password、api_key、auth_config 等字段使用 AES-256 加密存储
2. **数据备份**：每日全量备份 + 每小时增量备份
3. **权限控制**：基于 RBAC 模型，最小权限原则
4. **审计追踪**：关键操作记录操作日志，支持追溯
5. **软删除**：所有业务表使用 is_deleted + deleted_at 实现软删除
