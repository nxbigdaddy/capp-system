## 1. 数据库设计原则和规范

### 1.1 设计原则

1. **第三范式（3NF）优先**：消除传递依赖，减少数据冗余
2. **适度反范式**：对高频查询场景适当冗余，提升查询性能
3. **扩展性原则**：预留扩展字段，支持业务迭代
4. **一致性原则**：统一数据类型、长度、命名规范
5. **安全性原则**：敏感数据加密存储，操作记录可追溯

### 1.2 通用字段规范

所有业务表必须包含以下通用字段：

| 字段名 | 类型 | 说明 |
|--------|------|------|
| id | BIGINT UNSIGNED | 主键，自增 |
| creator_id | BIGINT UNSIGNED | 创建人ID |
| creator_name | VARCHAR(64) | 创建人姓名 |
| create_time | DATETIME | 创建时间 |
| updater_id | BIGINT UNSIGNED | 更新人ID |
| updater_name | VARCHAR(64) | 更新人姓名 |
| update_time | DATETIME | 更新时间 |
| is_deleted | TINYINT(1) | 逻辑删除标识：0-正常，1-删除 |
| remark | VARCHAR(500) | 备注 |

### 1.3 数据类型规范

| 场景 | 数据类型 | 说明 |
|------|----------|------|
| 主键 | BIGINT UNSIGNED AUTO_INCREMENT | 统一使用BIGINT |
| 状态/类型标识 | TINYINT UNSIGNED | 枚举值使用TINYINT |
| 金额 | DECIMAL(10,2) | 精确到分 |
| 时间 | DATETIME | 不使用TIMESTAMP |
| 长文本 | TEXT / LONGTEXT | 超过1000字符使用TEXT |
| JSON数据 | JSON | MySQL 8原生JSON类型 |
| 布尔值 | TINYINT(1) | 0表示否，1表示是 |

### 1.4 索引设计规范

1. 主键索引：所有表必须有主键
2. 唯一索引：业务唯一字段建立唯一索引
3. 联合索引：遵循最左前缀原则
4. 外键字段：建立普通索引
5. 状态字段：高频查询的状态字段建立索引
6. 时间字段：按时间范围查询的字段建立索引

## 2. 数据库命名规范

### 2.1 数据库命名

```
capp_prod    -- 生产环境
capp_dev     -- 开发环境
capp_test    -- 测试环境
```

### 2.2 表命名规范

- 格式：`模块前缀_业务实体`
- 全部小写，下划线分隔
- 使用单数形式

| 模块 | 前缀 | 示例 |
|------|------|------|
| 用户权限 | sys_ | sys_user |
| 企业微信 | wx_ | wx_user_bind |
| 工艺设计 | process_ | process_route |
| 产品管理 | product_ | product_info |
| 资源管理 | resource_ | resource_equipment |
| 工时定额 | worktime_ | worktime_quota |
| 模板管理 | template_ | template_process |
| AI功能 | ai_ | ai_model_config |
| 系统集成 | integration_ | integration_config |
| 审批流程 | approval_ | approval_flow |
| 系统日志 | log_ | log_operation |

### 2.3 字段命名规范

- 全部小写，下划线分隔
- 主键统一命名为 `id`
- 外键命名：`关联表名单数_id`，如 `user_id`
- 状态字段：`status`
- 类型字段：`type`
- 布尔字段：`is_` 前缀，如 `is_deleted`
- 时间字段：`_time` 后缀，如 `create_time`
