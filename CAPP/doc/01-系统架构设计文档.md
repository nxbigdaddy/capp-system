## 1. 系统概述

### 1.1 公司背景

本公司是一家专注于**工业压缩机**和**压力容器**研发、设计、生产的现代化制造企业。公司产品广泛应用于石油化工、天然气、医药、食品、电子等行业，具有技术含量高、工艺复杂、质量要求严格等特点。

**核心业务特征：**
- 产品属于特种设备，需符合国家压力容器相关法规标准
- 工艺流程复杂，涉及铸造、锻造、机加工、焊接、热处理、装配等多道工序
- 产品定制化程度高，多品种小批量生产模式
- 质量控制严格，需要完整的工艺追溯体系
- 设计变更频繁，工艺文件需要快速响应设计变更

### 1.2 系统目标

CAPP（Computer Aided Process Planning，计算机辅助工艺设计系统）旨在实现以下目标：

| 目标类别 | 具体目标 |
|---------|---------|
| 工艺标准化 | 建立企业标准工艺库，实现工艺知识的沉淀和复用 |
| 设计效率提升 | 工艺设计效率提升50%以上，减少重复劳动 |
| 数据一致性 | 实现与PLM、ERP、MES等系统的数据无缝对接 |
| 质量管控 | 建立完整的工艺质量追溯体系 |
| 智能化 | 引入AI技术，实现智能工艺推荐和辅助决策 |
| 移动化 | 通过企业微信实现移动审批、消息推送等功能 |

### 1.3 系统范围

CAPP系统覆盖以下业务范围：

```
┌─────────────────────────────────────────────────────────┐
│                    CAPP 系统业务范围                      │
├─────────────────────────────────────────────────────────┤
│  产品设计数据接收  │  工艺路线设计  │  工序卡片编制       │
│  材料定额计算      │  工装夹具设计  │  工时定额计算       │
│  工艺文件管理      │  工艺变更管理  │  工艺审批流程       │
│  工艺知识库        │  典型工艺管理  │  工艺数据统计       │
│  AI智能推荐        │  企业微信集成  │  外部系统集成       │
└─────────────────────────────────────────────────────────┘
```

### 1.4 设计原则

1. **高内聚低耦合**：模块间通过标准接口通信，降低系统耦合度
2. **安全性优先**：多层安全防护，保障企业核心工艺数据安全
3. **可扩展性**：采用分层架构，支持未来功能扩展和系统演进
4. **高性能**：优化数据库设计和缓存策略，保证系统响应速度
5. **易用性**：界面简洁直观，降低工艺人员学习成本
6. **标准化**：遵循国家CAPP相关标准和行业规范

### 3.3 数据库技术

#### 3.3.1 MySQL配置

| 配置项 | 参数 | 说明 |
|-------|------|------|
| 字符集 | utf8mb4 | 支持完整Unicode |
| 排序规则 | utf8mb4_general_ci | 通用排序 |
| 存储引擎 | InnoDB | 支持事务、行级锁 |
| 连接池 | 最大200 | 根据服务器配置调整 |

#### 3.3.2 数据库设计规范

- 所有表使用InnoDB引擎
- 主键统一使用自增BIGINT或UUID
- 必须包含created_at、updated_at、deleted_at字段

- 重要业务表采用软删除（deleted_at字段）

            case 'material_query':
                return $this->handleMaterialQuery($message, $context);
            case 'process_design':

        $vectors = $this->knowledgeBase->search($query);

#### 9.1.2 Redis缓存策略

```php
// Cache.php
class Cache {
    private $redis;
    
    // 缓存键前缀
    const PREFIX = 'capp:';
    
    // 缓存时间配置
    const TTL = [
        'user_info'       => 3600,      // 用户信息 1小时
        'permission'      => 1800,      // 权限数据 30分钟
        'config'          => 86400,     // 系统配置 24小时
        'process_template'=> 86400,     // 工艺模板 24小时
        'material_list'   => 3600,      // 物料列表 1小时
        'department_tree' => 7200,      // 部门树 2小时
        'menu_tree'       => 86400,     // 菜单树 24小时
    ];
    
    public function get($key) {
        return $this->redis->get(self::PREFIX . $key);
    }
    
    public function set($key, $value, $ttl = null) {
        return $this->redis->setex(
            self::PREFIX . $key,
            $ttl ?? 3600,
            serialize($value)
        );
    }
    
    public function remember($key, $callback, $ttl = null) {
        $value = $this->get($key);
        if ($value !== false) {
            return unserialize($value);
        }
        
        $value = $callback();
        $this->set($key, $value, $ttl);
        return $value;
    }
}
```

#### 9.1.3 缓存更新策略

| 策略 | 说明 | 适用场景 |
|-----|------|---------|
| Cache Aside | 先读缓存，未命中读数据库再写缓存 | 读多写少 |
| Write Through | 写数据库同时写缓存 | 强一致性要求 |
| Write Behind | 先写缓存，异步写数据库 | 写密集型 |
