
# CAPP系统安全设计文档

## 1. 安全概述

### 1.1 安全目标
确保CAPP系统的数据安全、应用安全和基础设施安全，保护企业核心工艺数据。

### 1.2 安全原则
- **最小权限原则**：用户只拥有完成工作所需的最小权限
- **纵深防御原则**：多层安全防护机制
- **审计追踪原则**：完整的操作日志记录

### 1.3 安全威胁矩阵

| 威胁类型 | 风险等级 | 描述 | 防护措施 |
| :--- | :--- | :--- | :--- |
| SQL注入 | 高 | 恶意SQL语句注入 | 参数化查询、输入过滤 |
| XSS攻击 | 高 | 跨站脚本攻击 | 输入转义、CSP策略 |
| 未授权访问 | 高 | 未授权用户访问系统 | 认证授权、权限控制 |
| 数据泄露 | 高 | 敏感数据泄露 | 数据加密、访问审计 |
| CSRF攻击 | 中 | 跨站请求伪造 | Token验证、Referer校验 |
| 会话劫持 | 中 | 会话凭证被盗取 | HTTPS、会话超时 |
| 暴力破解 | 中 | 密码暴力破解 | 登录限制、验证码 |
| 中间人攻击 | 中 | 数据传输被篡改 | HTTPS、证书验证 |

## 2. 认证与授权

### 2.1 认证机制

#### 2.1.1 JWT认证
- **Token类型**：JWT（JSON Web Token）
- **Token结构**：Header.Payload.Signature
- **加密算法**：HS256
- **有效期**：2小时
- **刷新Token**：有效期7天，存储于Redis

#### 2.1.2 企业微信认证
- **OAuth2.0协议**：扫码登录
- **授权流程**：获取code → 获取access_token → 获取用户信息
- **状态验证**：state参数防止CSRF攻击

#### 2.1.3 认证流程

```mermaid
sequenceDiagram
    participant User as 用户
    participant CAPP as CAPP系统
    participant Redis as Redis缓存

    User->>CAPP: 发起请求(携带Token)
    CAPP->>CAPP: 验证Token格式
    alt Token有效
        CAPP->>Redis: 检查Token是否在黑名单
        Redis-->>CAPP: 返回结果
        alt Token未被拉黑
            CAPP->>CAPP: 解析Token获取用户信息
            CAPP->>User: 处理请求
        else Token已拉黑
            CAPP->>User: 返回未授权
        end
    else Token无效/过期
        CAPP->>User: 返回未授权
    end
```

### 2.2 授权机制

#### 2.2.1 RBAC模型
- **角色定义**：管理员、工艺工程师、质量工程师、生产主管等
- **权限定义**：模块级、功能级、按钮级权限
- **权限继承**：角色继承上级角色权限

#### 2.2.2 权限数据结构

```json
{
  "role_id": 1,
  "role_name": "工艺工程师",
  "permissions": [
    {"module": "process", "action": "create"},
    {"module": "process", "action": "edit"},
    {"module": "process", "action": "view"},
    {"module": "bom", "action": "view"}
  ]
}
```

#### 2.2.3 权限校验流程

```mermaid
flowchart TD
    A[用户发起请求] --> B[获取当前用户角色]
    B --> C[查询角色权限]
    C --> D{校验权限}
    D -->|有权限| E[继续处理请求]
    D -->|无权限| F[返回403错误]
```

## 3. 数据安全

### 3.1 数据加密

#### 3.1.1 传输加密
- **协议**：HTTPS/TLS 1.2+
- **证书**：SSL证书（Let's Encrypt或商业证书）
- **强制HTTPS**：HTTP请求自动重定向到HTTPS

#### 3.1.2 存储加密
- **敏感字段加密**：密码、手机号、邮箱等使用AES-256加密
- **加密密钥管理**：密钥存储在环境变量中，不写入代码

#### 3.1.3 加密算法
| 用途 | 算法 | 密钥长度 |
| :--- | :--- | :--- |
| 密码哈希 | bcrypt | 10轮 |
| 数据加密 | AES-256 | 256位 |
| Token签名 | HS256 | 256位 |

### 3.2 数据脱敏
- **显示脱敏**：手机号显示为138****8000
- **日志脱敏**：敏感信息不在日志中打印
- **导出脱敏**：导出数据时自动脱敏

### 3.3 数据备份
- **每日备份**：凌晨2:00执行全量备份
- **增量备份**：每小时执行增量备份
- **备份保留**：保留最近30天备份
- **异地备份**：备份文件存储到异地服务器

## 4. 应用安全

### 4.1 输入验证

#### 4.1.1 参数校验
- **类型校验**：验证参数类型（int/string等）
- **长度校验**：限制参数最大长度
- **格式校验**：验证邮箱、手机号等格式
- **范围校验**：验证数值范围

#### 4.1.2 防SQL注入
- **参数化查询**：使用PDO参数化查询
- **输入过滤**：过滤特殊字符
- **ORM框架**：使用ORM防止SQL注入

#### 4.1.3 防XSS攻击
- **输入转义**：对用户输入进行HTML转义
- **输出编码**：输出时进行HTML编码
- **CSP策略**：配置内容安全策略

### 4.2 会话管理

#### 4.2.1 会话安全
- **会话ID**：随机生成，长度≥32位
- **会话超时**：30分钟无操作自动过期
- **并发控制**：同一账号最多同时登录3个设备

#### 4.2.2 Token管理
- **Token刷新**：Access Token过期后使用Refresh Token刷新
- **Token黑名单**：退出登录时将Token加入黑名单
- **Redis存储**：Token信息存储于Redis，便于快速查询

### 4.3 安全日志

#### 4.3.1 日志记录
- **登录日志**：记录登录时间、IP、设备信息
- **操作日志**：记录所有业务操作
- **异常日志**：记录系统异常和错误

#### 4.3.2 日志格式
```json
{
  "timestamp": "2024-01-15 10:30:00",
  "level": "INFO",
  "user_id": 1,
  "username": "zhangsan",
  "action": "create_process_route",
  "module": "process",
  "target": "PR-2024-001",
  "ip": "203.0.113.10",
  "user_agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64) Chrome/120.0.0.0"
}
```

## 5. 基础设施安全

### 5.1 服务器安全

#### 5.1.1 操作系统安全
- **系统更新**：定期更新操作系统补丁
- **防火墙配置**：只开放必要端口
- **用户管理**：禁用root远程登录，使用普通用户

#### 5.1.2 数据库安全
- **访问控制**：限制数据库访问IP
- **账号管理**：最小权限原则，定期轮换密码
- **审计日志**：开启数据库审计功能

### 5.2 网络安全

#### 5.2.1 网络隔离
- **DMZ区**：Web服务器放置在DMZ区
- **内网隔离**：数据库服务器在内网，不对外暴露
- **VPN访问**：远程访问需通过VPN

#### 5.2.2 DDoS防护
- **流量监控**：实时监控网络流量
- **流量清洗**：配置DDoS防护设备
- **CDN加速**：使用CDN分散流量

### 5.3 容器安全
- **镜像安全**：使用官方镜像，定期更新
- **容器隔离**：限制容器资源使用
- **安全扫描**：定期扫描容器漏洞

## 6. 安全审计

### 6.1 审计范围
- **用户行为**：登录、操作、数据访问
- **系统行为**：配置变更、权限变更
- **异常行为**：多次登录失败、异常访问模式

### 6.2 审计流程

```mermaid
flowchart TD
    A[日志收集] --> B[日志分析]
    B --> C{发现异常}
    C -->|是| D[触发告警]
    C -->|否| E[继续监控]
    D --> F[通知管理员]
    F --> G[安全响应]
    G --> H[事件记录]
    H --> E
```

### 6.3 告警机制
- **实时告警**：关键安全事件实时通知
- **告警渠道**：企业微信、邮件、短信
- **告警级别**：紧急、严重、警告、提示

## 7. 安全运维

### 7.1 安全巡检
- **每日巡检**：检查系统日志、异常登录
- **每周巡检**：检查安全配置、权限变更
- **每月巡检**：全面安全评估、漏洞扫描

### 7.2 漏洞管理
- **漏洞扫描**：定期进行漏洞扫描
- **漏洞修复**：及时修复发现的漏洞
- **漏洞跟踪**：记录漏洞处理进度

### 7.3 应急响应
- **应急预案**：制定安全事件应急预案
- **应急演练**：定期进行应急演练
- **事件复盘**：安全事件后进行复盘分析

## 8. 代码安全

### 8.1 安全编码规范
- **避免硬编码**：敏感信息不硬编码到代码中
- **使用安全函数**：使用安全的字符串处理函数
- **错误处理**：正确处理异常，不暴露敏感信息

### 8.2 代码审查
- **安全审查**：代码提交前进行安全审查
- **静态分析**：使用静态分析工具扫描代码
- **安全测试**：进行渗透测试和安全测试

### 8.3 依赖管理
- **依赖更新**：定期更新第三方依赖
- **漏洞监控**：监控依赖包安全漏洞
- **依赖审计**：定期审计依赖包安全性
