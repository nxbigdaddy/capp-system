# DEMO-CAPP P0-P2 开发计划

## 总体策略

采用“生产化重构”：保留原生 PHP、原生 HTML/JS/CSS 技术约束，但先建立可测试、可迁移的工程基础。现有 `sql/*.sql` 和数据作为迁移来源；历史 `CAPP/`、`capp2/`～`capp5/` 仅作需求参考。

严格按 `P0 → P1 → P2` 推进。每个里程碑先写失败测试，再实现，再跑全量回归；门禁未通过不进入下一阶段。第一轮从工程基线和 P0 认证权限开始，而不是直接开发 AI。

## 阶段 0：工程和运行基线

1. 建立 PHP 8.3/MySQL 8.0 基线，新增 Composer 清单、锁文件、PSR-4 自动加载、`.env.example`、统一 bootstrap 和环境校验。
2. 仅引入明确依赖：Dotenv、稳定路由、二维码、PDF、PHPUnit、PHPStan；不采用 Laravel/ThinkPHP。
3. 重构 `public/index.php`：统一请求、路由、异常、404/405、JSON 响应、会话、CORS 白名单和移动端入口。
4. 建立向前数据库迁移；现有含 `DROP TABLE` 的 SQL 只作为历史初始化材料。
5. 建立 `tests/Unit`、`tests/Integration`、`tests/Api`、`tests/E2E`，配置 PHPUnit、PHPStan 和 Playwright。
6. 门禁：空环境可安装，空库可迁移，PHP lint、静态分析、HTTP smoke 和数据库 smoke 全通过。

## P0：可生产试用的核心 CAPP

### P0.1 认证、权限和安全

1. 实现本地登录、登出、会话续期、密码重置基础能力；管理员由环境变量初始化，不写固定密码。
2. 完成用户、部门、角色、权限、数据范围模型；权限使用 `resource:action`，对象状态权限由 Domain Policy 判断。
3. 增加认证、权限、CSRF/同源保护、请求校验、分页限制、异常脱敏和审计上下文。
4. 预留企业微信身份映射和 OAuth Adapter；无真实凭据时使用契约 mock。
5. 测试登录正反例、禁用用户、CSRF、未登录 401、越权 403、数据范围和审计。

### P0.2 基础数据和工艺编制

1. 实现产品、物料、工作中心、标准工序、设备、工装、刀具、量具的 Service、Repository、API 和 PC 页面。
2. 建立稳定工艺路线根与不可变 revision；发布版本不可原地修改。
3. 增加工序、工步、工艺参数、资源关联和工序依赖；停止删除全部工序再重建。
4. 建设 PC 编制工作台：产品选择、工序/工步增删改排、标准工序引用、资源选择、参数编辑、自动保存、乐观锁和完整性校验。
5. 增加典型工艺、标准工序和卡片模板的复制/引用。
6. 测试 CRUD、排序、复制、并发冲突、草稿恢复和关联数据稳定性。

### P0.3 版本、审批和受控发布

1. 实现草稿、已提交、审批中、已批准、已发布、已作废状态机。
2. 重建审批为流程版本、节点、转换、实例、审批任务和审批动作；实例绑定具体 revision，审批人进入节点时冻结。
3. 正确实现单签、会签、或签、驳回、撤回、转审、加签、幂等和并发锁。
4. 最后节点完成后才批准；提交快照 hash 不一致时禁止发布。
5. 发布后旧版本失效；二维码和文件生成放在事务提交后执行，失败可重试且不产生半发布状态。
6. 测试创建→提交→多节点审批→发布，以及失败回滚、越权、重复和并发审批。

### P0.4 结构化卡片、变更和行业专项

1. 建立模板 revision、卡片实例 revision 和结构化字段校验，完成工序卡、检验卡与 KCP。
2. 实现 ECR/ECN：申请、影响对象、revision 差异、审批、发布、执行确认和通知。
3. 实现 WPS、PQR、WPQ/焊工资格、母材组别、厚度范围、焊接方法、焊材和适用性校验。
4. 实现受控附件、文件版本、ACL、访问和发放记录。
5. 测试模板升级隔离、变更新版本、WPS 适用边界、资格有效期及文件权限。

### P0.5 输出、移动端和发布门禁

1. 完成 PDF、工艺卡打印、标签、路线/工序二维码和打印记录；二维码仅允许站内受控目标。
2. 修复移动首页、路线/工序详情、扫码、待办和个人中心；匿名用户仅可按策略查看已发布内容。
3. 企业微信 JS-SDK 由后端按当前 URL 动态签名；无凭据环境使用 mock。
4. 实现审计查询、健康检查、日志、备份/恢复脚本和 Apache/Nginx 部署配置。
5. P0 门禁：核心生命周期 E2E 全通过；草稿不可越权访问；修改代码覆盖率 ≥80%，核心状态机/审批 ≥90%，无高危安全缺陷。

## P1：行业完整性和系统协同

### P1.1 EBOM/PBOM/MBOM

1. 建立 BOM 根、revision、item 和派生关系，支持 EBOM→PBOM/MBOM 转换、重组与差异。
2. 实现制造/采购/虚拟件、工序投料、损耗、替代料、供料方式和装配顺序。
3. 测试多层 BOM、循环、汇总、变更影响和投料完整性。

### P1.2 特殊过程和定额

1. 完成装配卡、热处理卡、无损检测卡、压力/气密试验规程、炉批和质量证明追溯。
2. 完成准备、加工、辅助、宽放、人工和设备工时定额。
3. 完成毛坯、下料、毛重、净重、余量、废料和材料利用率；数据库统一基准单位。
4. 测试规则边界、单位换算、定额 revision、审批和标准/实际偏差。

### P1.3 外部集成

1. 建立 Adapter、字段映射、外部对象映射、Inbox/Outbox、游标、批次、重试、补偿和对账。
2. CAXA PLM：产品、图纸、EBOM、变更与工艺摘要/MBOM。
3. U8：物料、订单、材料/工时定额和路线。
4. MES/QMS：路线、SOP、变更下发及报工、工时、检验结果回传。
5. 企业微信：OAuth、通讯录、通知、催办和移动审批。
6. 默认使用 mock server 做契约和故障注入；真实联调需用户提供授权端点和凭据。

### P1.4 规则、搜索和追溯

1. 使用受限 JSON DSL 建立规则版本、规则集、绑定和执行记录，禁止数据库直接执行 PHP。
2. 发布前校验工序、资源、卡片、WPS、BOM 投料、标准有效期和受控附件。
3. 先用 MySQL FULLTEXT 建统一搜索和 ACL 投影。
4. 完成版本差异与产品→BOM→路线→卡片→审批→发放→执行全链追溯及报表。
5. P1 门禁：BOM/定额/特殊过程/规则 E2E 全通过；集成幂等、重试和对账通过；总体覆盖率 ≥85%，核心规则/状态机 ≥95%。

## P2：受控智能化

### P2.1 知识和相似工艺

1. 仅已发布 revision 可进入知识库，记录 hash、来源、ACL、同步和失效状态。
2. 实现结构化特征加全文的相似零件、路线和参数检索；先建立可解释基线，再决定是否引入向量搜索。
3. 测试权限隔离、版本失效、引用追溯、召回评估和去重。

### P2.2 AI 助手和推荐

1. 对接 MaxKB/可替换知识服务，实现带来源引用的问答。
2. 实现工序、资源、工时和参数候选推荐；AI 只能生成候选草稿。
3. 推荐必须经过 schema、规则、人工确认和正常审批，不能直接发布。
4. 保存模型、提示词、输入 revision、引用、规则结果、采纳和人工修改记录。

### P2.3 AI 评估门禁

1. 建立固定评估集，测检索召回率、引用准确性、无依据回答率、违规率和采纳率。
2. 测试提示注入、越权检索、敏感信息泄漏、错误引用和降级。
3. P2 门禁：AI 不可绕过权限/规则/审批；建议全可追溯；AI 不可用不影响核心 CAPP；指标达到阈值后才开放生产开关。

## 执行规范

- 每个需求遵循测试先行；每个里程碑运行单元、集成、API、相关 E2E 和全量回归。
- 数据迁移采用加表/列→回填校验→切读→冻结旧写入口，不覆盖未知现有数据。
- 外部调用、真实消息发送和生产数据迁移在执行前单独确认；本地默认 mock。
- 每个里程碑报告修改文件、迁移、测试结果、覆盖率、遗留风险和下一阶段入口。
- 获批后先执行“阶段 0 + P0.1”，通过门禁后继续 P0.2；不会在测试失败时跳到 P1/P2。
