## 一、设计规范

### 1.1 命名规范

| 对象 | 规范 | 示例 |
|------|------|------|
| 数据库名 | `capp_db` | capp_db |
| 表名 | 小写+下划线，前缀 `capp_` | capp_process_route |
| 主键 | `id` (INT AUTO_INCREMENT) | id |
| 外键 | `{关联表名}_id` | route_id, product_id |
| 索引 | `idx_{字段名}` / `uk_{字段名}` | idx_status, uk_code |
| 创建时间 | `created_at` (DATETIME) | created_at |
| 更新时间 | `updated_at` (DATETIME) | updated_at |
| 删除标记 | `is_deleted` (TINYINT, 0/1) | is_deleted |
| 创建人 | `created_by` (INT) | created_by |
| 更新人 | `updated_by` (INT) | updated_by |

### 1.2 通用规则

- 所有表使用 **InnoDB** 引擎，**UTF8MB4** 字符集
- 所有表包含 `created_at`, `updated_at` 字段
- 采用**软删除**策略，关键业务表保留 `is_deleted` 字段
- 外键在**应用层维护**，数据库层仅建索引（提高性能，便于数据同步）
- 适当冗余以提高查询性能（如工艺路线中冗余产品编码）

## 四、索引策略

### 4.1 索引设计原则

1. **主键**：所有表使用自增 INT 主键
2. **唯一索引**：业务唯一字段（编码、编号等）
3. **外键索引**：所有外键字段建立索引
4. **查询索引**：高频查询条件字段（status、type、created_at）
5. **复合索引**：多条件查询场景
6. **每表索引数**：不超过 6 个

### 4.2 高频查询索引示例

```sql
-- 工艺路线列表查询（按产品+状态）
CREATE INDEX idx_product_status ON capp_process_route(product_id, status);

-- 待办审批查询
CREATE INDEX idx_pending_approval ON capp_approval_instance(status, current_node_id);

-- 操作日志查询（按用户+时间）
CREATE INDEX idx_user_time ON capp_audit_log(user_id, created_at);

-- 变更通知查询
CREATE INDEX idx_ecr_status ON capp_change_request(business_type, status);
```
