# CAPP 系统 - 项目概述与需求规格说明书

> 版本：V1.0 | 日期：2026-06-07 | 状态：初稿

---

## 一、项目背景

### 1.1 企业现状

本公司为工业压缩机、压力容器等特种设备制造企业，工艺数据管理长期依赖 Excel 和纸质文档，存在以下痛点：

- **工艺数据分散**：工艺路线、工序卡片、定额数据分散在不同人员电脑中，版本混乱
- **审批效率低**：工艺审批依赖纸质签字，周期长，异地审批困难
- **数据孤岛**：与 CAXA PLM（设计）、用友 U8（ERP）、MES（车间执行）系统无数据互通
- **知识流失**：老工艺师经验无法沉淀，新人培养周期长
- **现场执行难**：车间现场无法便捷查看最新工艺文件，变更通知滞后

### 1.2 项目目标

构建一套面向中小规模制造企业的 **计算机辅助工艺规划（CAPP）系统**，实现：

1. **工艺数据集中管理**：工艺路线、工序卡片、定额、变更全生命周期管理
2. **高效审批流转**：线上审批，支持会签、转审、催办，与企业微信深度集成
3. **系统互联互通**：与 PLM、U8、MES 实现数据双向流转
4. **知识沉淀复用**：历史工艺数据可检索、可推荐
5. **移动化支持**：车间现场通过移动端查看工艺、扫码追溯

### 1.3 使用规模

| 指标 | 数值 | 说明 |
|------|------|------|
| 总用户数 | ≤ 100 人 | 工艺员、审核人、车间工人、管理人员 |
| 并发用户数 | ≤ 10 人 | 同时在线编制/审批 |
| 工艺路线数量 | 约 5000 条 | 含历史数据 |
| 日活跃操作 | 约 200 次 | 查询、编制、审批 |

## 二、需求范围

### 2.1 功能需求

#### P0 - 核心功能（必须实现）

| 模块 | 功能点 | 说明 |
|------|--------|------|
| 系统管理 | 用户/角色/权限管理 | 基于企业微信同步，本地角色权限配置 |
| 系统管理 | 操作日志 | 记录所有数据变更，支持追溯 |
| 基础数据 | 物料管理 | 从 PLM/U8 同步，本地维护 |
| 基础数据 | 工作中心/设备/工装/刀具 | 工艺资源基础档案 |
| 基础数据 | 标准工序库 | 常用工序模板，快速引用 |
| 工艺路线 | 工艺路线编制 | 可视化添加工序、调整顺序、引用标准工序 |
| 工艺路线 | 版本管理 | V{major}.{minor} 版本号，发布后旧版作废 |
| 工艺路线 | 审批流程 | 提交→审核→批准→发布，支持驳回/转审 |
| 工艺规程 | 工序卡片 | 每道工序的操作步骤、参数、图纸引用 |
| 工艺规程 | 检验卡片 | 检验项目、标准、方法、工具 |
| 工艺规程 | 焊接工艺规程(WPS) | 焊接专用参数规程 |
| 定额管理 | 工时定额 | 准备/加工/辅助/宽放时间 |
| 定额管理 | 材料定额 | 毛重/净重/废料/利用率 |
| 文件输出 | 单据打印/PDF导出 | 工艺卡片、标签等支持二维码 |
| 变更管理 | ECR/ECN | 变更申请、变更通知、影响分析 |
| 移动端 | H5 页面 | 扫码查看工艺、接收通知、简单审批 |

#### P1 - 扩展功能（后续迭代）

| 模块 | 功能点 | 说明 |
|------|--------|------|
| AI 助手 | 工艺推荐 | 基于历史数据推荐相似工艺 |
| AI 助手 | 智能问答 | 工艺知识问答 |
| 报表分析 | 工时统计对比 | 标准工时 vs 实际工时 |
| 报表分析 | 材料利用率分析 | 按产品/车间/时间维度 |

### 2.2 非功能需求

| 类别 | 要求 |
|------|------|
| 性能 | 页面加载 < 2s，报表查询 < 5s |
| 可用性 | 系统可用性 ≥ 99%（单服务器部署，夜间维护窗口） |
| 安全 | JWT 认证，密码加密，操作审计，HTTPS 传输 |
| 兼容性 | Chrome/Edge/Firefox 最新两版，移动端 H5 适配 |
| 数据安全 | 每日自动备份，保留 30 天 |
| 扩展性 | 预留外部系统对接接口，模块可独立升级 |

## 四、业务流程

### 4.1 工艺路线生命周期

```
[编制] → [保存草稿] → [提交审核] → [工艺组长审核] → [工艺总师批准] → [发布]
   ↑        ↓              ↓              ↓ (驳回)          ↓ (驳回)
   └────────┴──────────────┴──────────────┘
```

### 4.2 变更管理流程

```
[发起ECR] → [影响分析] → [提交审批] → [批准] → [生成ECN] → [通知相关人员]
                                              ↓
                                       [执行变更/更新工艺版本]
```

### 4.3 移动端使用场景

1. **扫码查看工艺**：扫描工件上的二维码 → 显示当前工序卡片
2. **接收通知**：企业微信推送 → 点击查看审批待办/变更通知
3. **简单审批**：移动端查看工艺概要 → 点击通过/驳回
4. **报工录入**：扫描工位二维码 → 录入实际工时和完成数量

## 五、集成需求

### 5.1 企业微信

- 扫码登录（免密）
- 通讯录同步（部门/人员）
- 消息推送（审批待办、变更通知、催办）

### 5.2 CAXA PLM

- 读取：产品结构、EBOM、物料主数据、图纸信息
- 回写：工艺路线摘要、MBOM

### 5.3 用友 U8

- 读取：物料档案、库存、生产订单
- 回写：材料定额、工时定额、工艺路线

### 5.4 MES

- 下发：工艺路线、SOP、变更通知
- 接收：报工数据、质量检验数据

## 六、约束条件

### 6.1 技术约束

- **后端**：原生 PHP（不引入 Laravel/ThinkPHP 等框架），PHP 7.4+
- **数据库**：MySQL 8.0（主库），SQL Server（只读，连接 PLM/U8）
- **前端**：原生 HTML + JavaScript + CSS，不引入 Vue/React 等框架
- **缓存**：Redis（会话、缓存、锁）
- **其他组件**：非必要不增加，保持轻量

### 6.2 部署约束

- 单服务器部署即可满足性能需求
- 支持 CentOS/Ubuntu/Windows Server
- 支持 Apache/Nginx

### 6.3 二维码约束

- 所有必须输出的单据（工艺卡片、标签、检验卡）必须包含二维码
- 二维码内容：单据唯一标识 URL，扫码可直接查看对应内容
- 支持打印和 PDF 导出时嵌入二维码
